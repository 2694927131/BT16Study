## 一、总体架构（P0）

### 1.1 蓝牙协议栈六层架构

```
┌──────────────────────────────────────────────────────────────────┐
│  Layer 1: App / 车机系统应用层                                     │
│  蓝牙设置、音乐App、电话App、HiCar/CarPlay App                     │
├──────────────────────────────────────────────────────────────────┤
│  Layer 2: Framework API 层 (Java)                                │
│  BluetoothAdapter, BluetoothA2dp, BluetoothHeadset,              │
│  BluetoothProfile, BluetoothDevice, BluetoothGatt,               │
│  BluetoothAvrcpController, BluetoothHidHost...                   │
├──────────────────────────────────────────────────────────────────┤
│  Layer 3: Bluetooth Service 层 (Kotlin/Java)                     │
│  BluetoothService.kt → AdapterBinder.kt → IAdapter.aidl          │
│  AdapterService.java (AIDL 服务端实现)                             │
├──────────────────────────────────────────────────────────────────┤
│  Layer 4: JNI 层                                                 │
│  com_android_bluetooth_btservice_AdapterService.cpp              │
│  com_android_bluetooth_a2dp.cpp                                  │
│  com_android_bluetooth_headset.cpp                               │
│  等 JNI 桥接文件                                                  │
├──────────────────────────────────────────────────────────────────┤
│  Layer 5: BTIF 层 (C++) — Bluetooth Interface                   │
│  bluetooth.cc (HAL总入口)                                        │
│  btif_dm.cc (设备管理) / btif_av.cc (A2DP) / btif_hf.cc (HFP)   │
│  btif_gatt.cc (GATT) / btif_rc.cc (AVRCP) / btif_hh.cc (HID)   │
│  btif_sock.cc / btif_pan.cc / btif_hd.cc / btif_sdp.cc         │
├──────────────────────────────────────────────────────────────────┤
│  Layer 6: BTA 层 (C++) — Bluetooth Application                  │
│  bta/dm/ (设备管理) / bta/av/ (A2DP/AV) / bta/ag/ (HFP AG)     │
│  bta/gatt/ (GATT) / bta/hh/ (HID) / bta/sdp/ / bta/pan/       │
│  bta/jv/ (Java Vendor) / bta/le_audio/ / bta/vc/ / bta/has/    │
├──────────────────────────────────────────────────────────────────┤
│  Layer 7: Stack 层 (C++) — 核心协议栈                             │
│  stack/l2cap/ (L2CAP) / stack/rfcomm/ (RFCOMM)                  │
│  stack/sdp/ (SDP) / stack/avdt/ (AVDT) / stack/avct/ (AVCT)    │
│  stack/btm/ (BTM) / stack/bne/ (BNEP) / stack/hcic/ (HCI Cmd)  │
│  stack/acl/ (ACL) / stack/gatt/ (GATT) / stack/hid/ (HID)      │
├──────────────────────────────────────────────────────────────────┤
│  Layer 8: GD 层 (C++) — 新架构 (Gable Dodge)                    │
│  gd/hci/ (新HCI实现) / gd/hal/ (HAL抽象) / gd/os/ (OS抽象)      │
│  gd/packet/ (数据包框架) / gd/storage/ / gd/crypto_toolbox/     │
│  gd/common/ (通用工具) / gd/metrics/                             │
├──────────────────────────────────────────────────────────────────┤
│  Layer 9: HCI → HAL → 蓝牙芯片                                   │
│  gd/hal/hci_hal_impl.h → hci_backend_aidl.cc (AIDL HAL)        │
│  hci_backend_hidl.cc (HIDL HAL, 旧)                             │
└──────────────────────────────────────────────────────────────────┘
```

### 1.2 层间通信机制（P0）

| 通信方向        | 机制                       | 示例                                     |
| ----------- | ------------------------ | -------------------------------------- |
| 上层→下层       | API 函数调用                 | `BTA_AvOpen()` → BTA层                  |
| 下层→上层       | Callback 回调              | `btav_callbacks_t` → BTIF → JNI → Java |
| BTA内部       | 事件驱动                     | `bta_sys_sendmsg()` 投递事件到 BTA 事件循环     |
| BTIF→JNI    | JNI 回调                   | `callback_env→CallVoidMethod()`        |
| GD→旧栈       | Shim 适配层                 | `main/shim/` 目录下的适配代码                  |
| Service→App | BroadcastReceiver / AIDL | `IBluetoothCallback.aidl`              |

### 1.3 线程模型（P0）

| 线程                 | 作用                 | 关键文件                  |
| ------------------ | ------------------ | --------------------- |
| Main Thread (btif) | BTIF 主线程，处理 JNI 调用 | `btif_jni_task.cc`    |
| BTA Thread         | BTA 事件循环           | `bta_sys_main.cc`     |
| GD Stack Thread    | GD 新架构线程           | `gd/os/thread.h`      |
| JNI Thread         | JNI 环境管理           | `btif_jni_task.cc`    |
| Alarm Thread       | 定时器处理              | `osi/include/alarm.h` |

## 二、蓝牙开关/配对/连接（P0）

### 2.1 蓝牙开启流程

```
App: BluetoothAdapter.enable()
  → BluetoothManagerService.enable()
    → AdapterService.enable()
      → JNI: adapterServiceEnable()
        → BTIF: btif_dm.cc → BTA_DM_ENABLE_EVT
          → BTA: bta_dm_act.cc → bta_dm_enable()
            → GD/HCI: 发送 HCI_Reset → HCI_Read_BD_ADDR 等
              → 芯片初始化完成 → 上报回调
```

### 2.2 蓝牙关闭流程

```
App: BluetoothAdapter.disable()
  → BluetoothManagerService.disable()
    → AdapterService.disable()
      → JNI: adapterServiceDisable()
        → BTIF: btif_dm.cc → cleanup all profiles
          → BTA: bta_dm_disable() → 逐个关闭 Profile
            → HCI: HCI_Reset → 关闭芯片
```

### 2.3 设备扫描流程

```
App: BluetoothAdapter.startDiscovery()
  → AdapterService.startDiscovery()
    → JNI: startDiscovery()
      → BTIF: btif_dm.cc → BTA_DmSearch()
        → BTA: bta_dm_act.cc → bta_dm_search_start()
          → HCI: HCI_Inquiry (BR/EDR扫描)
          → HCI: LE_Set_Scan_Enable (BLE扫描)
            → 扫描结果回调: bta_dm_search_cb()
              → BTIF: btif_dm_search_devices_evt()
                → JNI → Java: onDeviceFound()
```

### 2.4 配对流程（SSP）

```
App: BluetoothDevice.createBond()
  → AdapterService.createBond()
    → JNI: createBond()
      → BTIF: btif_dm.cc → btif_dm_create_bond()
        → BTA: bta_dm_sec.cc → bta_dm_sec_create_bond()
          → HCI: HCI_Create_Connection / ACL建立
            → SSP配对请求: IO Capability Exchange
              → 用户确认/Numeric Comparison/Passkey
                → Bond完成: BTA_DM_AUTH_CMPL_EVT
                  → BTIF: btif_dm_auth_cmpl_evt()
                    → JNI → Java: onBondStateChanged()
```

### 2.5 配对流程（LE）

```
App: BluetoothDevice.createBond()
  → 同上到 BTIF
    → btif_dm.cc → btif_dm_create_bond()
      → BTA: bta_dm_sec.cc
        → HCI: LE_Create_Connection
          → LE SMP 配对 (Pairing Request/Response)
            → Encryption Change Event
              → Bond完成回调
```

### 2.6 Profile 连接流程

```
App: BluetoothA2dp.connect(device)
  → A2dpService.connect()
    → JNI: connectA2dpNative()
      → BTIF: btif_av.cc → connect()
        → BTA: bta_av_act.cc → BTA_AV_CONNECT_REQ
          → Stack: AVDT 信令连接 → SDP 查询 → L2CAP 通道
            → 连接成功: btav_connection_state_t.CONNECTED
              → BTIF回调 → JNI → Java: onConnectionStateChanged()
```

### 2.7 关键概念

| 概念           | 说明                           | 优先级 |
| ------------ | ---------------------------- | --- |
| ACL 链路       | 基础异步连接，所有数据传输的基础             | P0  |
| SCO/eSCO 链路  | 同步连接，语音通话专用                  | P0  |
| L2CAP 通道     | 逻辑链路控制和适配协议，ACL上的多路复用        | P0  |
| RFCOMM       | 串口仿真协议，基于L2CAP               | P0  |
| SDP          | 服务发现协议，查询远端设备支持的服务           | P0  |
| Bond/Pairing | 配对过程，建立加密链路                  | P0  |
| SSP          | Secure Simple Pairing，安全简单配对 | P0  |
| UUID         | 服务唯一标识，SDP和GATT中广泛使用         | P0  |
| Transport    | BR/EDR vs LE，两种蓝牙传输方式        | P0  |
| GATT         | 通用属性协议，BLE数据传输核心             | P1  |

## 三、A2DP 蓝牙音乐（P0）

### 3.1 A2DP 架构

```
┌──────────────────────────────────────────────────────────────┐
│  App: 音乐播放器                                              │
├──────────────────────────────────────────────────────────────┤
│  Framework: BluetoothA2dp (Java API)                         │
│  connect/disconnect/getConnectedDevices/isA2dpPlaying        │
│  setCodecConfigPreference/getCodecStatus                     │
├──────────────────────────────────────────────────────────────┤
│  JNI: com_android_bluetooth_a2dp.cpp                         │
├──────────────────────────────────────────────────────────────┤
│  BTIF: btif_av.cc — A2DP 状态机核心                          │
│  状态: Idle → Opening → Opened → Started → Closing          │
│  编解码器协商: SBC/AAC/aptX/aptX-HD/LDAC/LC3/Opus            │
├──────────────────────────────────────────────────────────────┤
│  BTIF: btif_a2dp_source.cc (Source端编码发送)                 │
│  BTIF: btif_a2dp_sink.cc (Sink端解码接收) ← 车机常用         │
├──────────────────────────────────────────────────────────────┤
│  BTA: bta_av_act.cc + bta_av_ssm.cc                         │
│  AV Stream 状态机                                            │
├──────────────────────────────────────────────────────────────┤
│  Stack: AVDT (音视频分发传输协议)                              │
│  信令通道: Discover → GetCap → SetConfig → Open → Start      │
│  媒体通道: 传输编码后的音频数据                                │
├──────────────────────────────────────────────────────────────┤
│  Audio HAL: 编码/解码实现                                     │
│  Software模式: CPU编解码                                      │
│  Offload模式: DSP编解码 ← 车载常用                            │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 A2DP 连接详细流程

```
1. App调用 BluetoothA2dp.connect(device)
2. → A2dpService.connect() → JNI
3. → btif_av.cc: btif_av_source_connect()
4.   → 检查当前状态机状态(必须在Idle)
5.   → BTA_AvOpen() → bta_av_act.cc
6.     → AVDT 连接请求
7.       → L2CAP 通道建立
8.         → SDP 查询远端A2DP Sink服务
9.           → AVDT Discover (发现SEP)
10.            → AVDT GetCap (获取编解码能力)
11.              → AVDT SetConfig (配置编解码器)
12.                → AVDT Open (打开媒体通道)
13.                  → 连接完成回调
14.                    → btif_av.cc 状态: Idle → Opened
15.                      → JNI → Java: CONNECTION_STATE_CONNECTED
```

### 3.3 A2DP 音频播放流程

```
1. 手机端开始播放音乐
2. → AVDT_Start → 媒体通道开始传输
3. → btif_av.cc 状态: Opened → Started
4. → btif_a2dp_sink.cc: 接收音频数据
5.   → Software模式: 解码 → AudioTrack播放
6.   → Offload模式: 数据直接送DSP解码播放
7. → JNI → Java: AUDIO_STATE_STARTED
```

### 3.4 编解码器协商（P0）

```
协商流程:
1. 本地支持的编解码器列表(按优先级排列):
   SBC(必选) → AAC → aptX → aptX-HD → LDAC → LC3 → Opus
2. 远端设备支持的编解码器列表
3. 取两者交集，选择优先级最高的
4. 配置编解码器参数(采样率、声道模式、比特率等)

关键代码:
- btif_av.cc: codec_config_preference
- btif_av_co.cc: 编解码器选择逻辑
- stack/a2dp/ : 各编解码器的具体实现

车载特殊:
- 通常使用 Offload 模式，编解码在 DSP 完成
- Offload 编解码器通过 A2DP Offload HAL 注册
- 需要关注 ro.bluetooth.a2dp_offload.supported 属性
```

### 3.5 A2DP Offload vs Software（P0）

| 对比项   | Software 模式                       | Offload 模式                                        |
| ----- | --------------------------------- | ------------------------------------------------- |
| 编解码位置 | CPU (软件)                          | DSP (硬件)                                          |
| 音频路径  | BT → CPU解码 → AudioFlinger → DSP播放 | BT → DSP解码+播放                                     |
| CPU占用 | 高                                 | 低                                                 |
| 延迟    | 较高                                | 较低                                                |
| 车载使用  | 少                                 | 几乎都用                                              |
| 关键属性  | -                                 | `ro.bluetooth.a2dp_offload.supported=true`        |
| 代码差异  | btif\_a2dp\_sink.cc (解码)          | audio\_hal\_interface/a2dp\_encoding.cc (Offload) |

### 5.1 HFP 架构

```
┌──────────────────────────────────────────────────────────────┐

├──────────────────────────────────────────────────────────────┤

│  connect/disconnect/startVoiceRecognition                      │
│  phoneStateChanged/dialMemory/answerCall/hangupCall           │
├──────────────────────────────────────────────────────────────┤
│  JNI → BTIF: btif_hf.cc                                      │
│  AT 命令处理 / SCO音频链路管理 / 编解码协商                     │
├──────────────────────────────────────────────────────────────┤
│  BTA: bta/ag/ (Audio Gateway)                                 │
│  bta_ag_act.cc — HFP AG 状态机                                │
│  bta_ag_at.cc — AT 命令解析器                                  │
│  bta_ag_rfc.cc — RFCOMM 连接管理                               │

│  bta_ag_sdp.cc — SDP 服务注册                                  │

├──────────────────────────────────────────────────────────────┤
│  Stack: RFCOMM (AT命令通道) + SCO/eSCO (语音通道)              │
└──────────────────────────────────────────────────────────────┘
```

### 5.2 HFP 连接流程

```
1. App调用 BluetoothHeadset.connect(device)
2. → HeadsetService.connect() → JNI
3. → btif_hf.cc: connect()
4.   → BTA_AgOpen() → bta_ag_act.cc
5.     → SDP 查询远端HFP服务
6.       → RFCOMM 连接建立
7.         → SLC (Service Level Connection) 建立
8.           → AT命令能力协商:
9.             - 支持的HFP特性(BRSF)
10.            - 编解码器协商(CVSD/mSBC/LC3)
11.            - 呼叫等待/来电显示等
12.          → SLC完成: BTHF_CONNECTION_STATE_SLC_CONNECTED
13.            → JNI → Java: onConnectionStateChanged()
```

### 5.3 HFP 通话流程

```
来电流程:
1. 手机收到来电 → 发送 AT+RING / +CLIP
2. → bta_ag_at.cc 解析AT命令
3.   → btif_hf.cc 回调
4.     → JNI → Java: phoneStateChanged(RINGING)
5.       → 车机界面显示来电
6.
7. 用户点击接听 → App调用 answerCall()
8. → btif_hf.cc → 发送 ATA (Answer)
9.   → 手机端接听
10.    → 建立 SCO/eSCO 音频链路
11.      → bta_ag_sco.cc: bta_ag_sco_open()
12.        → 音频通路建立
13.          → JNI → Java: onAudioStateChanged(CONNECTED)

拨号流程:
1. App调用 dialMemory() / dial()
2. → btif_hf.cc → 发送 ATD<number>;
3.   → 手机端拨号
4.     → SCO/eSCO 建链
5.       → 通话建立

挂断流程:
1. App调用 hangupCall()
2. → btif_hf.cc → 发送 AT+CHUP
3.   → 手机端挂断
4.     → SCO/eSCO 断开
5.       → 音频通路关闭
```

### 5.4 SCO/eSCO 音频链路（P0）

```
SCO (Synchronous Connection-Oriented):
- 固定速率 64kbps
- CVSD 编解码 (窄带语音)
- 用于 HFP 1.5 基本通话

eSCO (Enhanced SCO):
- 可变速率
- mSBC 编解码 (宽带语音, WBS)
- LC3 编解码 (超宽带语音, SWB)
- 用于 HFP 1.7+ 高清通话

SCO 建链流程:
1. bta_ag_sco.cc: bta_ag_create_sco()
2. → BTM_CreateSco() → HCI: Setup_Synchronous_Connection
3.   → 芯片建立SCO/eSCO链路
4.     → 连接完成回调
5.       → 音频数据通过 I2S/HCI 传输

SCO 路由 (车载关键):
- HCI 路由: 音频数据通过HCI传到CPU → 送给Audio HAL
- I2S 路由: 音频数据直接走数字音频总线 → DSP
- 车载通常使用 I2S 路由，延迟更低
```

### 5.5 HFP 编解码（P0）

| 编解码        | 带宽         | 音质 | HFP版本          | 车载使用 |
| ---------- | ---------- | -- | -------------- | ---- |
| CVSD       | 窄带(8kHz)   | 基础 | HFP 1.5        | 兼容模式 |
| mSBC       | 宽带(16kHz)  | 较好 | HFP 1.6+ (WBS) | 主流   |
| LC3        | 超宽带(32kHz) | 优秀 | HFP 1.9+ (SWB) | 新车型  |
| aptX Voice | 超宽带(32kHz) | 优秀 | HFP 1.9+ (SWB) | 高端车型 |

### 5.6 关键 AT 命令（P0）

| AT 命令                 | 方向    | 功能            |
| --------------------- | ----- | ------------- |
| ATA                   | HF→AG | 接听来电          |
| AT+CHUP               | HF→AG | 拒接/挂断         |
| ATD<number>;          | HF→AG | 拨号            |
| AT+VTS=<dtmf>         | HF→AG | 发送DTMF        |
| AT+CLCC               | HF→AG | 查询当前通话列表      |
| +RING                 | AG→HF | 来电振铃          |
| +CLIP:<number>        | AG→HF | 来电号码          |
| +CIEV:<index>,<value> | AG→HF | 指示器更新(信号/电量等) |
| AT+BVRA=<state>       | HF→AG | 语音识别开关        |
| AT+VGM=<gain>         | HF→AG | 麦克风音量         |
| AT+VGS=<gain>         | HF→AG | 扬声器音量         |
| +BSIR:<state>         | AG→HF | 车内铃声开关        |
| AT+BCC                | HF→AG | 编解码协商         |
| AT+BAC=<codecs>       | HF→AG | 编解码能力上报       |

## 六、手机互联蓝牙部分（P1）

### 6.1 HiCar 蓝牙流程

```
1. BLE 扫描阶段:
   - 车机扫描特定 Service UUID 的 BLE 广播
   - 发现 HiCar 设备 → 建立BLE连接
   - 通过 GATT 读写 Characteristic 交换设备信息

2. 握手认证阶段:
   - BLE通道传输认证数据
   - 交换WiFi连接参数(SSID/密码/频段)
   - 确认连接模式

3. WiFi 切换阶段:
   - 断开或保持BLE连接
   - 建立WiFi Direct或STA连接
   - 数据通道切换到WiFi

4. 数据传输阶段:
   - 视频/音频/控制数据走WiFi
   - 蓝牙仅保持心跳或辅助通道
```

### 6.2 CarPlay 蓝牙流程

```
1. BLE 发现阶段:
   - 车机扫描 CarPlay 特定 UUID
   - 建立BLE连接
   - 交换设备证书和配对信息

2. 认证阶段:
   - 通过BLE传输认证数据
   - Apple 认证协议

3. WiFi 建立阶段:
   - BLE通道传输WiFi参数
   - 建立WiFi连接(AWDL)
   - 数据通道切换到WiFi

4. 数据传输:
   - 视频流: H.264 over WiFi
   - 音频流: WiFi
   - 触控输入: WiFi
```

### 6.3 CarLink/其他互联

```
通用模式:
1. BLE扫描 → 发现 → 连接
2. GATT读写 → 交换WiFi参数
3. WiFi建立 → 数据传输
4. 蓝牙保持 → 心跳/辅助

关键代码:
- btif_gatt.cc: BLE扫描和GATT操作
- bta_gattc_act.cc: GATT Client操作
- btif_sock_rfc.cc: RFCOMM数据通道(部分互联方案)
- bta_jv_act.cc: Java Vendor接口
```

### 6.4 BLE GATT 完整流程（P1）

```
1. 扫描:
   BluetoothLeScanner.startScan()
   → BTIF: btif_gatt.cc → BTA: bta_gattc_act.cc
   → GD: Le Scanning Manager
   → HCI: LE_Set_Scan_Enable

2. 连接:
   BluetoothGatt.connect()
   → BTIF: btif_gatt.cc → BTA_GATTC_Open()
   → HCI: LE_Create_Connection

3. 服务发现:
   BluetoothGatt.discoverServices()
   → BTA_GATTC_Discover() → ATT: Read By Type / Find Information
   → 获取所有Service/Characteristic/Descriptor

4. 读写:
   BluetoothGatt.writeCharacteristic()
   → BTA_GATTC_Write() → ATT: Write Request/Command
   BluetoothGatt.readCharacteristic()
   → BTA_GATTC_Read() → ATT: Read Request

5. 通知:
   BluetoothGatt.setCharacteristicNotification()
   → BTA_GATTC_Write() (写CCC Descriptor使能通知)
   → ATT: Notification 从远端发来
   → 回调: onCharacteristicChanged()
```

### 6.5 RFCOMM/SPP 通道（P1）

```
1. SDP 查询:
   - 查找远端设备的 SPP Service Record
   - 获取 RFCOMM Channel Number 和 UUID

2. 建立连接:
   BluetoothSocket.connect()
   → BTIF: btif_sock_rfc.cc
   → BTA_JvRfcommStart()
   → RFCOMM: SABM/DISC/PN/Negotiation
   → L2CAP 通道建立

3. 数据传输:
   InputStream/OutputStream
   → RFCOMM 数据帧
   → L2CAP

4. 关闭:
   BluetoothSocket.close()
   → RFCOMM: DISC
   → L2CAP 通道关闭
```

## 七、IoT 外部设备（P2）

### 7.1 HID 设备（键盘/鼠标/遥控器）

```
HID (Human Interface Device):
- BR/EDR HID: 通过 L2CAP + HID Control/Interrupt 通道
- HOGP (HID over GATT Profile): 通过 BLE GATT

连接流程 (HOGP):
1. BLE扫描 → 发现HID Service UUID
2. GATT连接 → 发现HID Service
3. 注册Notification → 获取输入报告
4. 数据传输: 按键/鼠标移动/触控

关键代码:
- btif_hh.cc: HID Host BTIF层
- bta_hh_act.cc: HID Host BTA层
- bta_hh_le.cc: HOGP (BLE HID) 实现
```

### 7.2 SPP/RFCOMM 设备（OBD/诊断仪）

```
SPP (Serial Port Profile):
- 基于 RFCOMM 的串口通信
- 车载OBD诊断仪常用

连接流程:
1. SDP查询 → 获取SPP Channel
2. RFCOMM连接 → 建立数据通道
3. 串口数据收发

关键代码:
- btif_sock_rfc.cc
- bta_jv_act.cc
```

### 7.3 BLE GATT 设备（传感器/胎压/钥匙）

```
BLE GATT 通用设备:
- 胎压监测: 通过GATT读取胎压数据
- 蓝牙数字钥匙: BLE + UWB
- 座椅/空调控制: GATT读写控制指令

关键代码:
- btif_gatt.cc
- bta_gattc_act.cc
- bta_gatts_act.cc (GATT Server)
```

### 7.4 PAN（网络共享）

```
PAN (Personal Area Networking):
- 蓝牙网络共享
- 车载可通过手机蓝牙上网

关键代码:
- btif_pan.cc
- bta_pan_act.cc
```

## 九、车载蓝牙特殊知识（P1）

### 9.1 多连接（P0）

```
车机同时连接多部手机:
- 同时连接2部手机的A2DP + HFP
- 主设备/副设备切换
- 音频焦点管理

关键代码:
- btif_av.cc: 多设备A2DP状态机(每个设备独立状态)
- btif_hf.cc: 多设备HFP管理
- bta_dm_act.cc: 多设备ACL管理
```

### 9.2 A2DP Offload（P0）

```
车载几乎都使用A2DP Offload模式:
- 音频编解码在DSP完成
- CPU不参与编解码
- 降低延迟和功耗

关键属性:
- ro.bluetooth.a2dp_offload.supported=true
- persist.bluetooth.a2dp_offload.disabled=false

关键代码:
- bluetooth.cc: isA2DPOffloadEnabled()
- audio_hal_interface/a2dp_encoding.cc: Offload编码接口
- btif_a2dp_sink.cc: Offload接收路径
```

### 9.3 SCO 路由（P0）

```
车载SCO音频路由选择:
1. HCI路由: 音频数据通过HCI到CPU → Audio HAL → 扬声器
2. I2S路由: 音频数据直接走数字音频总线 → DSP → 扬声器

车载通常使用I2S路由:
- 延迟更低
- 音质更好
- CPU不参与

配置:
- vendor.sco.route.i2s (厂商自定义属性)
```

### 9.4 蓝牙唤醒（P1）

```
车机休眠后蓝牙唤醒:
- 蓝牙芯片保持低功耗运行
- 收到远端连接请求时唤醒车机
- 通过GPIO中断唤醒AP

关键代码:
- gd/os/wakelock_manager.h: WakeLock管理
- AutoOn.kt: 蓝牙自动开启
```

### 9.5 电源管理（P1）

```
蓝牙与车机电源状态联动:
- 车机休眠 → 蓝牙进入低功耗模式
- 车机唤醒 → 蓝牙恢复
- 保持BLE连接以支持唤醒

关键代码:
- system/doc/power_management.md
- bta_dm_pm.cc: 电源管理
- bta_dm_pm_offload.cc: 电源管理Offload
```

### 9.6 Interop 兼容性修复（P1）

```
设备兼容性问题修复:
- interop_database.conf: 已知设备兼容性修复列表
- interop.cc: 兼容性修复实现
- device_iot_config.cc: IoT设备配置

常见修复类型:
```

## 十、GD 新架构与 HCI（P2）

### 10.1 GD 架构概述

```
GD (Gable Dodge) 是蓝牙协议栈的新架构:
- 逐步替代旧的BTA/Stack层
- 更模块化、更可测试
- 使用现代C++特性

GD模块:
- gd/hci/: 新HCI层实现
- gd/hal/: HAL抽象层
- gd/os/: 操作系统抽象(线程/定时器/队列)
- gd/packet/: 数据包构建/解析框架
- gd/storage/: 设备存储
- gd/crypto_toolbox/: 加密工具
- gd/common/: 通用工具
- gd/metrics/: 度量统计
```

### 10.2 GD HCI 层

```
gd/hci/ 核心模块:
- hci_layer.cc: HCI层核心实现
- controller.cc: 控制器接口(读取芯片能力)
- le_address_manager.cc: LE地址管理(隐私)
- acl_manager/: ACL连接管理
- le_scanning_manager/: LE扫描管理
- le_advertising_manager/: LE广播管理
- security_module/: 安全模块
- neighbor/: 设备发现
```

### 10.3 GD HAL 层

```
gd/hal/ 核心模块:
- hci_hal.h: HAL抽象接口
- hci_backend_aidl.cc: AIDL HAL后端(新)
- hci_backend_hidl.cc: HIDL HAL后端(旧)
- snoop_logger.cc: Snoop日志
- link_clocker.cc: 链路时钟
```

### 10.4 Shim 适配层

```
新旧架构共存:
- main/shim/ 目录下的适配代码
- 将旧API调用转换到GD层
- 逐步迁移，最终完全替换旧架构

关键文件:
- main/shim/entry.h: Shim入口
- main/shim/acl_api.cc: ACL API适配
- main/shim/btm_api.cc: BTM API适配
```

### 10.5 GD Packet 框架

```
gd/packet/ 数据包框架:
- packet_builder.h: 数据包构建器
- packet_view.h: 数据包视图
- base_struct.h: 基础结构定义
- bit_inserter.h: 位插入器
- iterator.h: 迭代器

特点:
- 类型安全的数据包构建和解析
- 自动生成代码(packet/parser/)
- 运行时零拷贝
```
