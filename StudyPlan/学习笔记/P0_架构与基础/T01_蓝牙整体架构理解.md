# T01_蓝牙整体架构理解

> 学习日期：2026-05-16
> 使用工具：Trae + Deepseek-v4-pro
> 状态：已完成

## 关键收获
1. Android 蓝牙协议栈共 9 层：App → Framework API → Service → JNI → BTIF → BTA → Stack → GD → HCI/HAL → 芯片
2. 上层调下层用函数调用+IPC，下层通知上层用Callback+事件，典型路径是 btif_common.h 的 HAL_CBACK 宏
3. BTIF 层的 btif_transfer_context() 是核心线程同步机制，所有 BTA 操作必须在 BTIF 线程上执行
4. GD 新架构通过 main/shim/ 适配层与旧架构共存，最终目标是完全替代 BTA/Stack
5. 车载开发最常修改 BTIF + BTA 层（约占 60%），最常遇到的问题也在这两层

## 详细笔记

### 一、完整分层架构

```
┌──────────────────────────────────────────────────────────────┐
│  层 1: App 应用层 (Java/Kotlin)                               │

├──────────────────────────────────────────────────────────────┤

│  BluetoothAdapter, BluetoothA2dp, BluetoothHeadset,           │

├──────────────────────────────────────────────────────────────┤
│  层 3: Bluetooth Service 层 (Kotlin/Java)                     │
│  BluetoothService.kt → BluetoothSupervisor.kt                │
│  → BluetoothManagerService (AIDL 服务端)                       │
│  com.android.bluetooth 进程                                   │
├──────────────────────────────────────────────────────────────┤
│  层 4: JNI 层 (C++)                                          │
│  com_android_bluetooth_*.cpp — Java→C++ 桥接                  │
├──────────────────────────────────────────────────────────────┤
│  层 5: BTIF 层 (C++) — Bluetooth Interface                   │
```

### 二、层间通信机制

**下行 (App→HCI)**:
- App→Framework: 直接 API 调用
- Framework→Service: AIDL/Binder IPC
- Service→JNI: JNI native 方法
- JNI→BTIF→BTA→Stack→HCI: 直接函数调用

**上行 (HCI→App)**:
- HCI→GD→BTA: Event + Callback
- BTA→BTIF: btav_callbacks_t 回调表
- BTIF→JNI→Java: btif_common.h 的 HAL_CBACK 宏
- Java→App: BroadcastReceiver + AIDL Callback

**A2DP connect 完整调用链**:
```
下行: BluetoothA2dp.connect() → A2dpService.connect() → JNI
  → btif_av.cc: btif_av_source_connect() (检查状态机)
  → bta_av_act.cc: bta_av_api_open() (投递事件)
  → bta_av_ssm.cc: 状态机处理 → SDP查询 → AVDT Connect
  → Stack: AVDT Discover/GetCap/SetConfig/Open
  → HCI: L2CAP通道建立

上行: HCI Connection Complete → GD分发 → AVDT回调
  → BTA: bta_av_open_ok() → btav_callbacks_t.connection_state_cb
  → BTIF: HAL_CBACK → JNI → Java → onConnectionStateChanged(CONNECTED)
  → Broadcast: ACTION_CONNECTION_STATE_CHANGED
```

### 三、线程模型

**关键线程**:
- JNI Thread: 处理 Java→C++ 调用和回调到 Java
- BTIF Main Thread: BTIF 核心业务逻辑 + 消息队列
- BTA Thread (BTU): BTA 事件循环 (bta_sys_main.cc)
- GD Stack Thread: GD 新架构线程
- Alarm Thread: 定时器回调
- Audio Thread: A2DP 音频处理

**核心同步机制**:
- `btif_transfer_context()`: BTA→BTIF 跨线程消息传递
- `do_in_jni_thread()` / `jni_thread_wrapper()`: BTIF→JNI 线程切换
- `std::mutex`: 状态机状态保护
- `base::WeakPtr`: 防止回调时对象已销毁

**线程切换必要性**: 状态机非线程安全，多线程同时操作会崩溃，必须保证所有操作在同一线程

### 四、GD 新架构

**引入原因**: 可测试性差、代码耦合、内存安全、跨平台、协议解析易错

**共存方式**: main/shim/ 适配层将旧 BTA API 桥接到 GD 实现

**最终目标**: 所有协议逻辑迁移到 GD，BTIF 保留作为 JNI 桥梁，实现跨平台

### 五、车载开发

**最常修改**: Service 层 (API定制) > BTIF 层 (行为定制) > BTA 层 (协议调整)

**最常出问题**: BTIF+BTA 层 (60%) > Service 层 (20%) > HCI/HAL (10%) > 兼容性 (5%)
