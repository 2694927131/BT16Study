# T06_回调机制详解

> 学习日期：2026-05-16 | 工具：Trae+DS-v4-pro | 状态：已完成

## 关键收获
1. HAL 回调用函数指针表(bt_callbacks_t)注册，各Profile有独立回调结构体
2. BTIF→Java 回调经 HAL_CBACK(CB, FUNC, ...) → JNI callback_env→CallVoidMethod 完成线程切换
3. BTA 事件循环用 bta_sys_sendmsg() 投递事件，BTA 线程从队列取出后按事件ID分发到对应 handler
4. GD 层用 base::Callback / base::Bind 替代函数指针，通过 Shim 适配层与旧栈桥接
5. 三条典型回调路径：A2DP连接回调/BTA事件→BTIF→JNI、HFP来电/AT解析→回调→JNI、配对/SMP→BTA→BTIF→JNI

## 详细笔记

### 一、HAL 回调机制

**bt_callbacks_t 结构体** (include/hardware/bluetooth.h L200+):
```cpp
typedef struct {
    size_t size;
    bt_status_t (*init)(bt_callbacks_t* callbacks, ...);
    bt_status_t (*enable)();
    bt_status_t (*disable)();
    bt_status_t (*start_discovery)();
    bt_status_t (*cancel_discovery)();
    void (*get_device_is_connected)(const RawAddress& bd_addr);
    // ... 更多函数指针
} bt_interface_t;
```

回调通过 `bt_hal_cbacks` 全局变量在 bluetooth.cc 的 init() 中注册。

**各Profile回调表**:
- `btav_sink_callbacks_t` / `btav_source_callbacks_t` — A2DP: connection_state_cb / audio_state_cb / audio_config_cb
- `bthf_callbacks_t` — HFP: connection_state_cb / audio_state_cb / vr_state_cb / phone_state_change / callstate_change
- `btgatt_callbacks_t` — GATT: client_register / scan_result / connect / service_discovery / read/write/notify 回调
- `bthh_callbacks_t` — HID: connection_state / protocol_mode / get_report / set_report 回调

**C++ → Java 传递路径**:
```
BTIF: HAL_CBACK(bt_av_sink_callbacks, connection_state_cb, bd_addr, state)
→ btif_common.h: HAL_CBACK 宏展开 → callback wrapper
→ JNI: callback_env->CallVoidMethod(jCallbackObj, jMethodID, ...)
→ Java: callback 方法执行 → Broadcast/Listener 通知 App
```

### 二、JNI 回调实现

**callback_env 获取和管理** (btif_common.h L137):
```cpp
// HAL_CBACK 宏先做线程切换保证安全
#define HAL_CBACK(P_CB, P_CBACK, ...) \
  do { \
    if ((P_CB) && (P_CB)->P_CBACK) { \
      (P_CB)->P_CBACK(__VA_ARGS__); \
    } \
  } while (false)
```

**线程安全保证**:
- `do_in_jni_thread(task)` / `jni_thread_wrapper(cb)` — 将回调投递到 JNI 线程
- `is_on_jni_thread()` — 检查是否在 JNI 线程
- JNI 线程的 callback_env 已 attach，安全可用

### 三、BTA 事件机制

**bta_sys_sendmsg()** (bta_sys_main.cc):
```
1. 调用 bta_sys_sendmsg(p_msg)
2. → 将 BTA 事件消息放入 BTA 线程的消息队列
3. BTA 事件循环: while(true) { msg = dequeue(); dispatcher(event_id, msg); }
4. dispatcher 根据 event_id → 查表找到 handler → 调用 handler(msg)
5. handler 函数在每个 Profile 的 ACT 文件中定义 (bta_av_act.cc 等)
```

**典型事件ID**:
- `BTA_DM_API_SEARCH_EVT` → bta_dm_search_start()
- `BTA_AV_CONNECT_REQ` → bta_av_state_opening_handler()
- `BTA_AG_API_OPEN` → bta_ag_sm_execute()
- `BTA_DM_AUTH_CMPL_EVT` → btif_dm_auth_cmpl_evt()

### 四、GD 层回调 (base::Callback/base::Bind)

```cpp
// GD 层使用模式 (替代函数指针):
base::Callback<void(RawAddress, btav_connection_state_t)> on_state_change;
// 注册回调:
on_state_change = base::Bind(&BtifAv::OnConnectionState, base::Unretained(this));
// 调用:
on_state_change.Run(bd_addr, state);

// base::Bind 自动绑定参数:
base::Bind(&func, arg1, arg2) — 绑定静态参数
base::Unretained(ptr) — 不增加引用计数的裸指针
base::Owned(ptr) — 转移所有权
```

**GD→旧栈桥接 (Shim)**:
```
GD 层事件 → main/shim/ 适配函数 → 旧 BTA API 调用 → BTA 事件循环
例如: GD ACL Manager 断连 → shim::acl_disconnect_callback → BTA_DmACLClose() → BTA 事件
```

### 五、三条典型回调路径

**A2DP 连接状态变化**:
```
BTA_AV_OPEN_EVT → bta_av_state_opened_handler()
→ p_stream_cb->p_cback(BTAV_OPEN_EVT) ← btav_sink_callbacks 回调表
→ btif_report_connection_state(bd_addr, BTAV_CONNECTION_STATE_CONNECTED)
→ do_in_jni_thread(bond_state_changed_callback)
→ invoke_connection_state_changed_cb(state)
→ HAL_CBACK(bt_av_sink_callbacks, connection_state_cb, bd_addr, CONNECTED)
→ JNI: CallVoidMethod → Java: onConnectionStateChanged()
```

**HFP 来电通知**:
```
AT: +RING / +CLIP: 来电号码
→ bta_ag_at.cc AT 解析器识别 +RING/+CLIP
→ bta_ag_act.cc: bta_ag_at_cind_result() / bta_ag_call_state_change()
→ btif_hf.cc: bthf_callbacks_t.phone_state_change_cb(RINGING)
→ do_in_jni_thread → JNI → Java: onPhoneStateChanged()
```

**配对状态变化**:
```
SMP Auth Complete → bta_dm_ble_smp_cback(BTM_LE_AUTH_CMPL_EVT)
→ bta_dm_auth_cmpl() → 投递 BTA_DM_AUTH_CMPL_EVT 到 BTIF
→ btif_dm.cc: btif_dm_auth_cmpl_evt [L1130]
→ btif_storage_add_bonded_device() 存储配对信息
→ bond_state_changed(status, bd_addr, BT_BOND_STATE_BONDED)
→ GetInterfaceToProfiles()->events->invoke_bond_state_changed_cb(...)
→ JNI → Java: ACTION_BOND_STATE_CHANGED
```
