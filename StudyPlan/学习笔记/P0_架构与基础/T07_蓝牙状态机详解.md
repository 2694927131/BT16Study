# T07_蓝牙状态机详解

> 学习日期：2026-05-16 | 工具：Trae+DS-v4-pro | 状态：已完成

## 关键收获
1. StateMachine 框架：AddState→SetInitialState→Start→ProcessEvent→TransitionTo，核心是状态对象的 ProcessEvent+OnEnter+OnExit
2. A2DP btif_av 状态机：Idle→Opening→Opened→Started→Closing，Source/Sink 独立实例
3. HFP AG 状态机 (bta_ag): 多个子状态覆盖 INIT→OPENING→OPEN→CLOSING→SCO，AT命令触发转换
4. BTA DM 状态机 (bta_dm): 设备管理级状态 (ENABLE/DISABLE) + 扫描子状态 (IDLE/INQUIRY/DISCOVER)
5. AV Stream 状态机 (bta_av_ssm): Idle→Open→Started→Suspend，与 A2DP Profile 状态机协作

## 详细笔记

### 一、通用状态机框架 (common/state_machine.h)

```cpp
namespace bluetooth::common {
class StateMachine {
    class State {
        virtual bool ProcessEvent(uint32_t event, void* p_data) = 0;
    protected:
        virtual void OnEnter();  // 进入状态时的初始化
        virtual void OnExit();   // 离开状态前的清理
        void TransitionTo(int dest_state_id);
    };
    void AddState(State* state);
    void SetInitialState(State* state);
    void Start();       // → TransitionTo(initial_state_)
    void Quit();
    bool ProcessEvent(uint32_t event, void* p_data); // 代理到 current_state_
    void TransitionTo(int dest_state_id); // current_->OnExit → 切换 → new->OnEnter
};
}
```

**TransitionTo 核心流程 [L177-184]**:
```cpp
void TransitionTo(State* dest_state) {
    if (current_state_ != nullptr) current_state_->OnExit();
    previous_state_ = current_state_;
    current_state_ = dest_state;
    current_state_->OnEnter();  // ← 关键: 新状态的初始化逻辑
}
```

### 二、A2DP 状态机 (btif_av.cc)

**状态定义** (btif_av.h):
```
BTIF_AV_STATE_IDLE(0) — 空闲，可接收连接或发起连接
BTIF_AV_STATE_OPENING(1) — AVDT OPEN 进行中
BTIF_AV_STATE_OPENED(2) — AVDT 通道已建立，等待 START
BTIF_AV_STATE_STARTED(3) — 音频数据正在传输
BTIF_AV_STATE_CLOSING(4) — AVDT CLOSE 进行中
```

**状态转换图**:
```
    ┌──────────────┐     connect()     ┌──────────────┐
    │              │ ─────────────────→│              │
    │     Idle     │                  │   Opening    │
    │              │←─────────────────│              │
    └──────┬───────┘   Open Failed    └──────┬───────┘
           │                                 │ AVDT OPEN OK
           │                                 ▼
    ┌──────┴───────┐                  ┌──────────────┐
    │   Closing    │                  │    Opened    │
    │              │←─────────────────│              │
    └──────┬───────┘  disconnect()    └──────┬───────┘
           │                                 │ AVDT START
           │                                 ▼
    ┌──────┴───────┐                  ┌──────────────┐
    │     Idle     │←─────────────────│   Started    │
    └──────────────┘  disconnect/stop └──────────────┘
                                           ↑
                                     AVDT SUSPEND
                                     ↓
                                  ┌──────────────┐
                                  │   Suspended  │ (中间状态，可恢复)
                                  └──────────────┘
```

**每个状态处理的事件**:
| 状态 | 处理的事件 |
|------|-----------|
| Idle | BTIF_AV_SRC_CONNECT_EVT (开始连接), BTIF_AV_SINK_CONNECT_EVT (接收连接) |
| Opening | BTA_AV_OPEN_EVT (成功→Opened), BTA_AV_CLOSE_EVT (失败→Idle) |
| Opened | BTA_AV_START_EVT (→Started), BTIF_AV_DISCONNECT_EVT (→Closing) |
| Started | BTA_AV_SUSPEND_EVT (→Suspended), BTA_AV_STOP_EVT (→Opened) |
| Closing | BTA_AV_CLOSE_EVT (→Idle) |

**Source vs Sink**:
- Source(发送音频): btif_av_source_connect() → AVDT Source 角色
- Sink(接收音频): btif_av_sink_connect() → AVDT Sink 角色
- 车机主要是 Sink (接收手机音频)

### 三、HFP AG 状态机 (bta_ag_act.cc)

**BTA AG 状态** (不是单一状态机，而是多个子状态):
```
主状态: BTA_AG_INIT_ST → BTA_AG_OPENING_ST → BTA_AG_OPEN_ST → BTA_AG_CLOSING_ST
服务状态: BTA_AG_SDP_ST (SDP查询中)
SCO 状态: BTA_AG_SCO_OPENING_ST → BTA_AG_SCO_OPEN_ST → BTA_AG_SCO_CLOSING_ST → BTA_AG_SCO_SHUTTING_ST
```

**AT 命令驱动的状态转换**:
```
RFCOMM 连接成功 → BTA_AG_AT_CIND_RESULT → SLC 协商开始
ATA (接听) → BTA_AG_SCO_OPENING_ST → SCO 建链
AT+CHUP (挂断) → BTA_AG_SCO_CLOSING_ST → SCO 断开
```

**SCO 与 HFP 关系**: SCO 状态是 HFP 主状态下的子状态，HFP 连接(SLC建立)是前置条件

### 四、BTA DM 状态机 (bta_dm_act.cc)

**设备管理层状态**:
```
BTA_DM_ENABLE_ST: 蓝牙开启 → enable 完成 → BTA_DM_IDLE_ST
BTA_DM_DISABLE_ST: 蓝牙关闭

扫描子状态 (bta_dm_device_search.cc):
BTA_DM_SEARCH_IDLE → BTA_DM_SEARCH_ACTIVE → BTA_DM_SEARCH_CANCELLING
配对子状态 (bta_dm_sec.cc):
BTA_DM_BOND_STATE_NONE → BTA_DM_BOND_STATE_BONDING → BTA_DM_BOND_STATE_BONDED
```

### 五、AV Stream 状态机 (bta_av_ssm.cc)

**状态**: IDLE→OPENING→OPEN→STARTING→STARTED→SUSPENDING→CLOSING

**与 A2DP btif_av 的协作**:
- btif_av 的状态表示 Profile 层面的连接状态
- bta_av_ssm 的状态表示 AVDT 流传输层面的状态
- 两者通过事件桥接: btif_av 发送事件→bta_av_ssm 处理→AVDT 命令→结果回调→btif_av

### 六、状态机调试技巧

**日志追踪状态转换**:
```bash
# A2DP 状态转换日志
adb logcat -s bluetooth-a2dp | grep -E "Idle|Opening|Opened|Started|Closing"

# HFP AG 状态日志
adb logcat -s bt_bta_ag | grep -E "state|transition|event"

# BTA DM 状态
adb logcat -s bt_bta_dm | grep -E "search_state|bond_state"
```

**状态机卡死常见原因**:
1. 期望的事件一直没收到 (HCI 命令未响应/芯片卡死)
2. 状态机内部死循环/阻塞等待 future
3. 回调未注册导致事件丢失
4. 线程死锁导致 ProcessEvent 无法被调用

**添加自定义状态机日志**:
- 在状态的 OnEnter/OnExit 中添加 LOG_INFO
- 在 ProcessEvent 入口添加 event 日志
- 使用 `GetInterfaceToProfiles()->events->invoke_metrics` 上报自定义 metrics
