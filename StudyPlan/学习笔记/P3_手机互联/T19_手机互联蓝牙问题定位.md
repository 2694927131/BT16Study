1. 互联通用模式: BLE发现(UUID广播)→GATT握手(认证+参数)→WiFi建立→蓝牙退为心跳，每一步有对应日志tag+snoop特征

## 详细笔记

### 一、互联蓝牙流程通用模式

```
阶段1: BLE 发现 (0.5-3s)
  车机主动扫描 → 手机广播带proprietary 128-bit UUID
  Tag: bt_btif_gatt | bt_btif_scan

阶段2: GATT 握手 (1-5s)
  connect → discoverServices → read Char(获取设备信息) → write Char(发送认证/WiFi参数)
  关键: Service UUID=compatible proprietary + Characteristic UUIDs=deviceInfo/wifi/network
  Tag: bt_btif_gatt | bt_bta_gattc

阶段3: WiFi 切换 (2-10s)
  GATT 获取WiFi SSID/密码/频段 → disconnect BLE channel
  → P2P connect / STA connect / NAN Networking
  Tag: wifi | p2p | wifidirect
```

### 二、各阶段定位

**BLE 发现阶段问题**:
```
扫描不到设备:
  → adb shell dumpsys bluetooth_manager | grep -A 10 "scanManager"
  → adb logcat bt_btif_scan → "onScanResult" 是否出现
  → Snoop btle → ADV_IND 或 SCAN_RSP 广告包
  → 验证 ScanFilter UUID → 128-bit 全匹配? → adb logcat bt_btif_gatt "findAllUuids"

方案:
  → 检查 ScanSettings: ScanMode=SCAN_MODE_LOW_LATENCY、matchMode=STICKY
  → getScanFilters → addServiceUUID (使用ParcelUuid比较)
```

**GATT 握手阶段问题**:
```
步骤:
1. 检查 GATT 连接: adb logcat bt_btif_gatt "open" → bt_gatt_callbacks.client.open_cb
2. 检查 discoverServices: snoop btle → ATT Read By Group Type Request / Response
3. 检查 Characteristic 读写:
   - readChar: BTA_GATTC_Read → ATT Read Request → Response → 回调
   - writeChar: → char UUID/properties/mtu → ATT Write Request/Command
4. 超时: BTA_GATT_CONN_IDLE_TIMEOUT 典型30s

认证失败 (CarPlay):
  → Snoop btle ATT → 查看 write char value → Apple MFI cert step
  → sw_nonce/rx_auth_tag/tx_auth_tag 交换序列
  → Apple Wireless Accessory Configuration → BLE 2-phase auth
```

**WiFi 切换阶段问题**:
```
WiFi 参数获取:
  → GATT read char <wifiSsid/wifiPwd/frequency>
  → 如果值为空 → 检查 GATT Service UUID 是否正确
  → 如果为某种格式 → 需要应用层解析 (JSON<binary)

WiFi 建立:
  → adb logcat wifi | p2p | wifidirect
  → connect_to_peer → group_formation → provision_discovery
  → WPA2 key exchange (GATT提供的credential)

蓝牙+WiFi 协作:
  → RFCOMM 共存: BT SCO + WiFi 2.4GHz → 干扰 → 延迟增加
  → 方案: 车载 → WiFi 5GHz => 避免与BT竞争 2.4GHz
```

### 三、三案例

**案例1: HiCar 连接失败**
```
排查步骤:
1. adb logcat | grep -E "hci_scan|btif_gatt.*open|bta_gattc"
2. Snoop btle → 先验证 ADV→CONNECT→ATT 序列完整
3. 是否进入 HiCar Service (UUID=0xFEE0?) → discoverServices 返回值
4. 检查 pi(设备信息) characteristic read → response 非空
5. 检查 wf(WiFi) characteristic write → 值到达手机

关键日志:
btif_gatt: "open" = GATT连接请求
bta_gattc: "connected" = ATT连接成功
bta_gattc: "read_cmpl" = characteristic读完成
→ wf char写入 → wifi connect → HiCar Service通知
```

**案例2: CarPlay 认证失败**
```
排查:
1. Verify: Apple iAP2 BLE Service UUID = D0611E78-BBB9-4D54-9CAC-8FE6B9352ED6
2. Snoop btle → ATT 认证交换:
   ↔ Exchange MFi Certificate
   ↔ Exchange sw_nonce / auth_method
   ↔ Get Result: res/auth_status
3. 验证: auth_status = 0x00(success)?
   → 如果不等于 0x00 → check Apple MFI chip
4. 时间: CarPlay BLE 握手在 30s 内完成
```

**案例3: 互联频繁断连**
```
蓝牙层排查:
  → BT BQR: adb dumpsys bluetooth_manager | grep quality
  → RSSI ≤ -85 dBm → 蓝牙本身不稳定
  → eSCO→ 有retransmission count高

WiFi层排查:
  → adb logcat wifi | grep "disconnect_reason"
  → P2P group_removed → reason代码 (0=normal, 4=timeout, 2=rejected)
  → WiFi RSSI → 2.4GHz 干扰检查

心跳机制:
  → BT层: Advertising timeout? → idle_disconnect 触发
  → WiFi层: ARP ping 超时 → 重连间隔
  → 车机端: 设置 policy.xml 调整 timeout
```

### 四、互联兼容性

| 平台 | 蓝牙握手 | WiFi | 特点 |
|------|----------|------|------|
| HiCar (Android) | BLE → Service 0xFEE? | P2P/Direct | 需要特定HiCar App |
| CarPlay (iOS) | BLE iAP2 UUID | AWDL/WiFi | Apple MFI 芯片 |
| CarLink | BLE | STA/P2P | 厂商定制 |

**差异化处理**:
- 扫描过滤: 不同平台使用不同 UUID filter
- 连接超时: iOS 较严格 (≤15s), Android 较宽松 (≤30s)
- 编解码: CarPlay 视频 H.264 over WiFi

**兼容性定位方法**:
```bash
# 抓全部蓝牙+WiFi日志
adb logcat -s bt_btif_gatt bt_bta_gattc bt_btif_scan wifi | grep -E "connect|disconnect|service|char|auth"
# Snoop 分析
filter: btle && bt.addr == XX:XX:XX:XX:XX:XX
# 看ATT层+WiFi层是否有超时
```
