## 1. 日志系统架构

### 1.1 日志API统一规范

整个蓝牙协议栈采用 **统一日志库** `<bluetooth/log.h>`，所有C++代码使用：

```cpp
#include <bluetooth/log.h>

// 5级日志，参数支持fmt格式化
log::verbose("detailed trace: codec={} handle={}", codec, handle);
log::debug("connection state change: old={} new={}", old_state, new_state);
log::info("A2DP stream started for peer={}", peer_addr);
log::warn("SCO fallback from LC3 T2 to mSBC T1, device={}", addr);
log::error("encryption failed for peer={}, reason={}", peer, reason);
log::fatal("stack crash: {}", error_msg); // 致命错误
```

**级别对应关系**：

| 日志方法 | 级别 | 使用场景 | logcat可见性 |
|----------|------|----------|-------------|
| `log::verbose()` | V | 详细追踪、数据包dump | 默认不显示 |
| `log::debug()` | D | 调试状态变化 | 默认可见(userdebug/eng) |
| `log::info()` | I | 重要状态变化（连接/断开/开始/停止） | 始终可见 |
| `log::warn()` | W | 异常但可恢复（fallback/retry） | 始终可见 |
| `log::error()` | E | 错误但不致命（连接失败/超时） | 始终可见 |
| `log::fatal()` | F | 致命错误触发crash | 始终可见 |

### 1.2 LOG_TAG命名规范

每个源文件在顶部定义自己的LOG_TAG：

| 层级 | 命名规范 | 示例 |
|------|----------|------|
| BTIF层 | `bt_btif_<模块>` | `bt_btif_dm`, `bt_btif_hf`, `bt_btif_avrc` |
| BTA层 | `bt_bta_<模块>` | `bt_bta_dm`, `bt_bta_gattc` |
| Stack层 | `bt_<协议>` 或简短名 | `bt_l2cap`, `bt_rfcomm`, `bt_btu_hcif` |
| GD层 | 功能描述名 | `bluetooth`, `bt_main_thread` |
| AG特殊 | `bta_ag_<功能>` | `bta_ag_cmd`, `bta_ag_at` |
| AV特殊 | `bluetooth-a2dp` | 所有A2DP的BTIF+BTA文件共用 |

### 1.3 动态调整日志级别

**方法一：adb shell setprop（需重启蓝牙）**
```bash
# 查看当前蓝牙所有property
adb shell getprop | grep bluetooth

# 调整全局蓝牙日志级别（需要源码支持）
adb shell setprop log.tag.bluetooth-a2dp DEBUG
adb shell setprop log.tag.bt_btif_dm VERBOSE

# 重启蓝牙使生效
adb shell svc bluetooth disable
adb shell svc bluetooth enable
```

**方法二：使用开发者选项**
设置 → 开发者选项 → 启用蓝牙HCI信息收集日志 → 会开启完整Snoop Log

**方法三：aconfig flag（Android 14+）**
```bash
# 查看所有蓝牙flag状态
adb shell device_config get aconfig_flags com.android.bluetooth.flags

# 设置特定flag
adb shell device_config put aconfig_flags com.android.bluetooth.flags <flag_name> true
```

## 3. 关键日志行解读

### 3.1 A2DP连接状态变化

**状态机进入Idle（断开/初始状态）**
```
I bluetooth-a2dp: state=Idle peer=AA:BB:CC:DD:EE:FF
```
→ 蓝牙已断开或刚启动，A2DP处于空闲

**开始连接**
```
I bluetooth-a2dp: state=Opening peer=AA:BB:CC:DD:EE:FF event=BTIF_AV_CONNECT_REQ_EVT flags=0x00 active_peer=null
```
→ 收到连接请求，状态从Idle→Opening

**ACL断连导致A2DP回退Idle**
```
W bluetooth-a2dp: Peer AA:BB:CC:DD:EE:FF : event=BTIF_AV_ACL_DISCONNECTED: transitioning to Idle due to ACL Disconnect
```
→ **车载常见问题**：ACL链路断开，A2DP被迫回退。排查RF/干扰问题

**进入Opened（连接成功，未播放）**
```
I bluetooth-a2dp: state=Opened peer=AA:BB:CC:DD:EE:FF
```
→ AVDT连接建立，但还未START流

**进入Started（正在播放音频）**
```
I bluetooth-a2dp: state=Started peer=AA:BB:CC:DD:EE:FF
```
→ AVDT START命令成功，音频数据开始传输

**错误的操作**
```
E bluetooth-a2dp: Peer AA:BB:CC:DD:EE:FF : event=BTIF_AV_START_STREAM_REQ_EVT: stream is not Opened
```
→ 在非Opened状态下尝试开始播放，通常因时序问题

### 3.2 HFP通话状态变化

**SLC连接成功**
```
D bt_btif_hf: SLC connected event:XXX idx:0
```
→ Service Level Connection建立，AT命令通道就绪

**SLC建立失败**
```
E bt_btif_hf: failed to setup SLC for AA:BB:CC:DD:EE:FF
```
→ 可能原因：AT协商超时、BRSF不兼容、RFCOMM断开

**来电阻止发送RING**
```
W bta_ag_cmd: don't send RING, conn_service=0, callsetup_ind=1
```
→ conn_service(服务连接状态)=0意味着SLC未完全建立，此时来电不发送RING

**SCO建链成功**
```
I bta_ag_sco: Succeeded for index 0x0002, device AA:BB:CC:DD:EE:FF
```

**SCO建链失败（已穷尽所有fallback）**
```
E bta_ag_sco: eSCO/SCO failed to open, no more fall back
```
→ **关键错误**：CVSD/mSBC/LC3全部失败，检查射频环境和codec配置

**SCO codec降级链**
```
W bta_ag_sco: eSCO/SCO failed to open, falling back to LC3 T1 settings
W bta_ag_sco: eSCO/SCO failed to open, falling back to mSBC T1 settings
```
→ 自动降级：LC3 T2→T1→mSBC T2→T1→CVSD

### 3.3 配对过程日志

**IO能力和认证方式确定**
```
I bt_bta_dm_sec: io mitm:1 oob_data:0
```
→ mitm=1表示需要MITM保护（Numeric Comparison/Passkey），oob_data=0表示无OOB

**认证失败**
```
W bt_bta_dm_sec: authentication failed entry:XXX, reason:YYY
```

**配对成功**
```
I bt_btif_dm: device=AA:BB:CC:DD:EE:FF, bond state=12, success=1, key_present=1
```
→ bond state=12即BOND_BONDED

**配对失败**
```
W bt_btif_dm: Bonding failed with failure reason:XXX
W bt_btif_dm: Pairing timeout; retrying (1) ...
```

**加密进行中冲突**
```
E bt_bta_dm_sec: Unable to start encryption as already in progress peer:AA:BB:CC:DD:EE:FF transport:2
```

### 3.4 编解码器协商

**编解码器选择结果**
```
V bluetooth-a2dp: codec: SBC
V bluetooth-a2dp: avdt_handle: 0 codec: AAC
```

**选中的编解码器**
```

```

## 4. 调试命令大全

### 4.1 adb dumpsys bluetooth_manager

这是**车载蓝牙调试最重要的命令**，一个命令输出蓝牙全状态。

```bash
adb shell dumpsys bluetooth_manager
```

**输出结构**（三层dump架构）：

```
Bluetooth Status                          ← BluetoothManagerService.dump()
├── enabled: true
├── state: ON (15)
├── address: XX:XX:XX:XX:XX:XX
├── name: "MyCar"
├── time since enabled: 2h 15m 30s
├── Crash Stats: ...
├── Flags:                                ← dumpBluetoothFlags()
│   ├── [■] fix_started_module_race
│   ├── [■] set_component_available_fix
│   ├── [ ] add_bond_loss_reason
│   └── ... (全部aconfig flag状态)
│
└── AdapterService.dump()                 ← 委托到AdapterService
    ├── Properties: name/address/state/scan mode
    ├── Remote Devices: 已配对设备列表
    ├── Active Device Manager
    ├── Scan Mode: CONNECTABLE_DISCOVERABLE
    ├── Snoop Log Settings
    ├── Enabled Profiles: A2DP, HFP, AVRCP, GATT, HID, PAN...
    ├── State Machine: AdapterState
    ├── Profile Services: (各Profile dump)
    └── Native Stack Dump: (HAL层dump)
```

**常用dumpsys过滤**：
```bash
# 只看蓝牙是否开启
adb shell dumpsys bluetooth_manager | head -5

# 查看flag状态
adb shell dumpsys bluetooth_manager | grep -E "\[■\]|\[ \]"

# 查看已配对设备
adb shell dumpsys bluetooth_manager | grep -A 20 "Remote Devices"
```

### 4.3 HCI Snoop Log

**启用方式**：

方法一：开发者选项（推荐）
```
设置 → 开发者选项 → 启用蓝牙HCI信息收集日志 → 开启
```

方法二：adb命令
```bash
# 设置为full模式
adb shell setprop persist.bluetooth.btsnooplogmode full

# 设置为filtered模式（推荐：省空间，够用）
adb shell setprop persist.bluetooth.btsnooplogmode filtered

# 设置为disabled关闭
adb shell setprop persist.bluetooth.btsnooplogmode disabled

# 禁用过滤header（full模式显示完整ACL数据）
adb shell setprop persist.bluetooth.snooplogfilter.headers.enabled false

# 重启蓝牙
adb shell svc bluetooth disable && adb shell svc bluetooth enable
```

**文件位置**：
```bash
# 主Snoop文件
/data/misc/bluetooth/logs/btsnoop_hci.log

# Snooz日志（压缩格式）
/data/misc/bluetooth/logs/btsnooz_hci.log

# 拉取到电脑
adb pull /data/misc/bluetooth/logs/btsnoop_hci.log ./
```

**Snoop模式对比**：

| 模式 | 内容 | 文件大小 | 适用场景 |
|------|------|----------|----------|
| `full` | 全部HCI包(含ACL数据payload) | 很大(GB级) | 音频数据分析 |
| `filtered` | HCI包+选择性ACL数据 | 中等 | **日常调试推荐** |
| `disabled` | 不记录 | 0 | 生产环境 |
| `kernel` | 由Kernel记录 | 取决于内核 | 内核级调试 |

**Filtered模式详情**：
- 默认在userdebug/eng构建上启用
- 可过滤A2DP媒体数据（保留headers）
- 可过滤RFCOMM UIH payload
- 可按profile类型过滤（PBAP/HFP/MAP）

### 4.4 BQR (Bluetooth Quality Report)

BQR通过Vendor Specific Event获取控制器端的链路质量数据。

**BQR监控的9种质量事件**：

| 事件 | 掩码 | 说明 | 车载使用 |
|------|------|------|----------|
| Monitor Mode | 0x01 | RSSI实时监控 | ⭐⭐⭐ |
| Approaching LSTO | 0x02 | 接近链路超时 | ⭐⭐⭐⭐ |
| **A2dp Audio Choppy** | 0x04 | A2DP音频卡顿检测 | ⭐⭐⭐⭐⭐ |
| **Sco Voice Choppy** | 0x08 | 通话音频卡顿 | ⭐⭐⭐⭐⭐ |
| Root Inflammation | 0x10 | 异常根因分析 | ⭐⭐⭐ |
| Energy Monitoring | 0x20 | 功耗监控 | ⭐⭐ |
| LE Audio Choppy | 0x40 | LE Audio卡顿 | ⭐⭐ |
| **Connect Fail** | 0x80 | 连接失败原因 | ⭐⭐⭐⭐⭐ |
| Vendor Specific Trace | 0x80000000 | 厂商自定义trace | ⭐⭐⭐ |

**BQR配置命令**：
```bash
# 设置事件掩码（监控A2DP卡顿 + SCO卡顿 + 连接失败）
adb shell setprop persist.bluetooth.bqr.event_mask 0x8C

# 设置最小报告间隔(ms)
adb shell setprop persist.bluetooth.bqr.min_interval_ms 1000

# 设置卡顿阈值
adb shell setprop persist.bluetooth.bqr.choppy_threshold 3

# BQR质量报告文件
/data/misc/bluetooth/logs/lmp_ll_message_trace.log
/data/misc/bluetooth/logs/bt_scheduling_trace.log
```

**BQR数据结构**（[btif_bqr.h](file:///d:/AndroidWorkspace/claudeProject/BT16Study/Bluetooth/system/btif/include/btif_bqr.h)）：
```
BqrLinkQualityEvent {
    rssi, snr, retransmission_count, no_rx_count,
    nak_count, flow_off_count, ...
}
BqrEnergyMonitorEvent {
    avg_current_consume,
    idle/active/BREDR/LE TX/RX times
}
BqrRFStatsEvent {
    RSSI distribution across chains
    TX power counters
}
```

### 5.1 过滤特定设备的日志

```bash
# 实时过滤特定设备的所有蓝牙日志
adb logcat | grep -i "AA:BB:CC:DD:EE:FF"

adb logcat bluetooth-a2dp:D bt_btif_hf:D bt_btif_dm:D *:S | grep "AA:BB:CC:DD:EE:FF"

# 保存到文件
adb logcat -v threadtime > bt_log.txt &

kill %1
grep "AA:BB:CC:DD:EE:FF" bt_log.txt > target_device_log.txt
```

```bash
# A2DP调试专用
```

### 5.2 Wireshark实时分析HCI日志

**方法一：Android Snoop直接分析**
