## 1. 车载多连接架构

### 1.1 典型多设备场景

```
车机蓝牙同时最多连接:
  ┌─────────────────────────────────────┐
  │  主手机 (Drive Phone)              │
  │  ├── A2DP (音乐) + AVRCP (控制)    │  ← active_peer
  │  └── HFP (电话)                     │  ← active_bda
  ├─────────────────────────────────────┤
  │  副手机 (Passenger Phone)           │
  │  ├── A2DP (仅连接, 不播放)         │  ← suspended
  │  └── HFP (待机, 接听来电时切换)    │
  └─────────────────────────────────────┘
```

**A2DP和HFP的active设备可以不同**：
- A2DP active_peer = 主手机（播放音乐）
- HFP active_bda = 主手机（通话）
- 但副手机来电时，HFP可临时切换到副手机

## 2. A2DP多设备管理

### 2.1 BtifAvPeer 核心结构

源码：[btif_av.cc](file:///d:/AndroidWorkspace/claudeProject/BT16Study/Bluetooth/system/btif/src/btif_av.cc)

```cpp
// 每个已配对设备维护独立的状态机
struct BtifAvPeer {
    RawAddress peer_address;        // 设备地址
    BtifAvStateMachine state_machine; // 独立状态机(Idle/Opening/Opened/Started/Closing)
    uint8_t flags;                  // kFlagLocalSuspendPending | kFlagRemoteSuspend
    std::set<btif_av_sm_event_t> pending_events; // 待处理事件队列
};
```

每个Peer都有自己的A2DP状态机，**互不干扰**：
- 主手机: state=Started（播放中）
- 副手机: state=Opened（连接但不播放）

### 2.2 SetActivePeer 核心切换流程

源码：[btif_av.cc:L515-L567](file:///d:/AndroidWorkspace/claudeProject/BT16Study/Bluetooth/system/btif/src/btif_av.cc#L515-L567)

```cpp
void BtifAvSource::SetActivePeer(const RawAddress& peer_address) {
    // 1. 空地址 = 清除active_peer
    if (peer_address.IsEmpty()) {
        btif_a2dp_source_end_session(active_peer_);   // 结束当前音频会话
        btif_a2dp_source_shutdown();                   // 关闭A2DP source
        active_peer_ = RawAddress::kEmpty;
        return;
    }

    // 2. 相同设备 = 不操作
    if (active_peer_ == peer_address) return;

    // 3. 暂停当前active设备的音频
    btif_a2dp_source_end_session(active_peer_);
    
    // 4. 启动新active设备的音频
    active_peer_ = peer_address;
    btif_a2dp_source_restart_session(active_peer_);
    
    // 5. 暂停所有其他非active设备
    DispatchSuspendStreamEvent(BTIF_AV_SUSPEND_STREAM_REQ_EVT);
}
```

**Suspend分发**（[btif_av.cc:L596-L600](file:///d:/AndroidWorkspace/claudeProject/BT16Study/Bluetooth/system/btif/src/btif_av.cc#L596-L600)）：
```cpp
void DispatchSuspendStreamEvent(btif_av_sm_event_t event) {
    // 遍历所有Peer，非active的设备全部发送Suspend事件
    for (auto& peer : peers_) {
        if (peer.peer_address != active_peer_) {
            peer.state_machine.ProcessEvent(event);
        }
    }
}
```

**非Active设备自动防Start**（[btif_av.cc:L2290-L2325](file:///d:/AndroidWorkspace/claudeProject/BT16Study/Bluetooth/system/btif/src/btif_av.cc#L2290-L2325)）：
```
当非active设备尝试Start播放时:
  → 检查是否为active_peer
  → 如果不是 → 自动发送Suspend，阻止播放
```

### 2.3 主设备切换触发条件

```
触发切换的场景:
1. 用户手动切换 → UI点击"切换音频到设备B"
2. 新设备来电 → HFP自动切换到该设备，A2DP可选跟随
3. 当前设备断开 → 自动切换到下一个可用设备(如果有)
4. 音频焦点抢占 → 导航提示音插入时可能需要暂停A2DP
```

**切换过程中的关键操作**：
```
1. EndSession(旧设备) → AVDT SUSPEND/CLOSE
2. 等待音频通路完全释放
3. RestartSession(新设备) → Audio HAL重新配置
4. 若新设备在Opened状态 → 发送AVDT START
5. 若新设备在Idle状态 → 先连接再START
```

**切换失败处理**：
```
如果RestartSession失败:
  → active_peer_保持不变(旧设备)
  → 日志ERROR提示切换失败
  → App层收到回调 → 显示"切换失败"提示

如果被切换的设备正在通话:
  → 仅切换A2DP, HFP保持不变
  → 通话结束后再同步切换
```

## 3. HFP多设备管理

### 3.1 active_bda 全局单例

源码：[btif_hf.cc](file:///d:/AndroidWorkspace/claudeProject/BT16Study/Bluetooth/system/btif/src/btif_hf.cc)

```cpp
// btif_hf.cc
static RawAddress active_bda;  // 全局唯一的HFP活跃设备

// 检查是否为active设备
static bool is_active_device(const RawAddress bd_addr) {
    return !active_bda.IsEmpty() && active_bda == bd_addr;
}

// 设置active设备
bt_status_t HeadsetInterface::SetActiveDevice(const RawAddress active_device_addr) {
    active_bda = active_device_addr;
    BTA_AgSetActiveDevice(active_device_addr);  // 通知BTA层
    return BT_STATUS_SUCCESS;
}
```

**HFP与A2DP的active可以不同**：
```
场景: 主手机通话中 + 副手机播放音乐
  HFP active_bda  = 主手机 (SCO通路建立)
  A2DP active_peer = 副手机 (音乐暂停, 因为通话中)

通话结束后:
  A2DP自动恢复副手机的音乐播放
```

### 3.2 BTA_AgSetActiveDevice

源码：[bta_ag_api.h](file:///d:/AndroidWorkspace/claudeProject/BT16Study/Bluetooth/system/bta/include/bta_ag_api.h)

```cpp
void BTA_AgSetActiveDevice(const RawAddress& active_device_addr);
```

**BTA层active切换影响**：
- 新的SCO建链请求只对active设备处理
- 非active设备的来电仍可处理（Ring通知）
- 非active设备的通话可切换到active状态（需要用户确认）

### 3.3 两部手机同时来电

```
场景: 主手机和副手机同时来电

处理策略:
1. 两部手机都发送 +RING 到车机
2. 车机显示两个来电
3. 用户选择接听其中一部 → 该设备成为通话active
4. 另一部来电继续响铃 → 用户可挂断或接听
5. 当前通话挂断 → 如果还有未接来电, 自动切换

源码处理:
  bta_ag_cmd.cc → bta_ag_send_result(BTA_AG_LOCAL_RES_RING)
  → 每个已连接HFP设备独立发送RING
  → UI层根据来电列表让用户选择
```

## 4. 音频焦点管理

### 4.1 A2DP音乐 vs HFP通话优先级

```
优先级(从高到低):
1. HFP通话 (SCO音频)                   → 最高优先级, 独占
2. 导航提示音 (TTS/预录音频)           → 临时抢占, 结束后恢复
3. A2DP音乐                             → 正常播放
4. 系统提示音 (按键音/警告音)          → 与A2DP混音
```

### 4.2 来电时自动暂停音乐

```
流程:
1. HFP: +RING + +CLIP(来电号码) → UI显示
2. 车机自动: AudioManager.requestAudioFocus(GAIN_TRANSIENT)
   → Android AudioFlinger将A2DP音频通道DUCK(降低音量)或暂停
3. 用户接听(ATA) → AudioManager.requestAudioFocus(GAIN)
   → SCO音频通路建立, A2DP完全静音
4. 通话结束(AT+CHUP) → AudioManager.abandonAudioFocus()
   → 恢复A2DP播放
```

### 4.3 导航提示音与蓝牙音频混音

```
场景: A2DP音乐播放中, 导航播报"前方500米右转"

处理方式1: DUCK (降低音乐音量)
  AudioManager.requestAudioFocus(AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK)
  → A2DP音量降低到30%
  → 导航音在另一个AudioTrack播放
  → 导航结束 → abandonAudioFocus → A2DP恢复100%音量

处理方式2: PAUSE (暂停音乐)
  适用于长导航播报(>3秒)
  AVRCP PAUSE → 导航播报 → AVRCP PLAY

车载推荐: DUCK模式
  → 体验更好, 不频繁暂停/播放
  → 帧缓冲区不丢失
```

### 4.4 车载音频路由

```
A2DP音乐路径 (Offload模式):
  手机 → BT RF → 车机蓝牙芯片 → DSP解码(SBC/AAC/LDAC) 
    → I2S/TDM总线 → 车载DSP → 功放 → 扬声器

SCO通话路径:
  手机 → BT RF → 车机蓝牙芯片 → CVSD/mSBC解码
    → I2S总线 → 车载DSP → EC(回声消除) + NR(降噪)
    → 功放 → 扬声器 (对方声音)
    → MIC → ADC → DSP → I2S → 蓝牙芯片 → SCO上行 (我方声音)

导航音/TTS:
  车机AP侧生成 → AudioTrack → AudioFlinger混音
    → (如果A2DP Offload) 与A2DP在DSP端混音
    → (如果无Offload) 在AudioFlinger PCM层面混音
```

### 4.5 多音区 (Driver Zone / Passenger Zone)

```
车载多音区方案:
  
方案A: 双蓝牙芯片
  芯片1 → 主驾扬声器 (导航音+通话)
  芯片2 → 副驾/后排扬声器 (音乐+娱乐)

方案B: 单芯片 + DSP分区
  蓝牙芯片输出 → 车载DSP → 分4声道
    Ch1/2 → 主驾区域 (导航独立 + 音乐低音量)
    Ch3/4 → 副/后排 (音乐正常音量)
  导航提示仅在主驾区域播放

HAL层配置:
  audio_policy_configuration.xml
  → 定义多个Output Device (speaker_driver_zone, speaker_passenger_zone)
  → AudioFlinger根据UID/Usage路由到不同zone
```

## 5. 常见问题与对策

### 5.1 切换设备时音频中断过长

```
原因: EndSession→RestartSession之间的等待时间过长
诊断: 
  logcat -s bluetooth-a2dp | grep -E "end_session|restart_session|state="
  
优化:
  1. 缩短AVDT CLOSE等待时间
  2. 预连接目标设备(提前在Opened状态)
  3. DSP端快速切换(不重新加载codec)
```

### 5.2 通话结束后音乐不恢复

```
原因: AudioFocus未正确释放
诊断:
  adb shell dumpsys audio | grep -A 10 "AudioFocus"
  查看谁持有焦点

常见原因:
  1. 车载TTS未释放焦点(第三方导航App卡住)
  2. HFP电话状态未正确回调(AT+CIEV未通知call=0)
  3. AVRCP PLAY命令未发送到手机

修复:
  → 超时强制释放: Handler.postDelayed(abandonFocus, 3000)
  → 监听HFP call状态为0后触发恢复
```

### 5.3 两部手机同时来电处理

```
推荐策略(车载):
1. 显示两个来电 → 用户选择接听
2. 接听A → HFP active切换到A → SCO建立
3. B保持响铃 → 可SEND DTMF挂断或转语音信箱
4. A挂断 → 如果B仍在来电 → 自动切换active → SCO建立
5. 如果B已挂断 → 恢复A2DP播放

源码关键: bta_ag_cmd.cc 中每个HFP设备独立维护 call_state
```
