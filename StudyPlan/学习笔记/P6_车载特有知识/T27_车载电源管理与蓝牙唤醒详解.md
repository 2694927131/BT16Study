## 1. 车机电源状态

### 1.1 四种电源状态

```
┌─────────────────────────────────────────────────────────────┐
│ 状态         │ 描述                  │ 蓝牙行为              │
├──────────────┼───────────────────────┼───────────────────────┤
│ 完全开启     │ 正常行车/ACC ON       │ 全功能运行            │
│ (Full On)    │ CPU/DSP/Radio全开     │ 扫描/连接/A2DP/HFP    │
├──────────────┼───────────────────────┼───────────────────────┤
│ 浅度休眠     │ 熄火后短时间          │ BLE保持连接           │
│ (Shallow     │ CPU降频, 蓝牙保持     │ Sniff模式省电         │
│  Sleep)      │ 少量外设关闭          │ 可被远端唤醒          │
├──────────────┼───────────────────────┼───────────────────────┤
│ 深度休眠     │ 长时间停车            │ 蓝牙完全关闭          │
│ (Deep Sleep) │ RAM保持, 蓝牙断电     │ 需重新初始化          │
│              │ 仅RTC/GPIO唤醒        │ 配对信息保留在Flash   │
├──────────────┼───────────────────────┼───────────────────────┤
│ 定时唤醒     │ AutoOn机制            │ 自动开启蓝牙          │
│ (Scheduled   │ AlarmManager定时器    │ 扫描可用设备          │
│  Wake)       │ 如每天早上5点         │ 检查远程连接请求      │
└──────────────┴───────────────────────┴───────────────────────┘
```

### 1.2 各状态下蓝牙的生命周期

**Full On → Shallow Sleep 转换**：
```
1. 关闭主动扫描(停止Inquiry/LE Scan)
2. 所有连接进入Sniff Mode (节省功耗)
3. 保存BLE连接信息(CCCD/MTU/PHY)
4. 蓝牙芯片进入低功耗模式
   → HCI: Sniff Mode Request → max_sniff_period=500ms
5. 配置唤醒源: GPIO引脚 + BLE Connection Event
```

**Shallow Sleep → Full On 转换**（唤醒）：
```
1. 唤醒源触发(手机靠近/用户点火)
2. 蓝牙芯片退出Sniff Mode → Active Mode
3. 恢复扫描和连接状态
4. 重新注册GATT通知
5. 恢复音频通路
```

## 2. Sniff低功耗模式

### 2.1 模式定义

源码：[power_mode.h](file:///d:/AndroidWorkspace/claudeProject/BT16Study/Bluetooth/system/stack/btm/power_mode.h)

```cpp
enum : uint8_t {
    BTM_PM_MD_ACTIVE = 0x00,   // 活跃模式 (全功耗)
    BTM_PM_MD_HOLD   = 0x01,   // 保持模式 (>Sniff功耗)
    BTM_PM_MD_SNIFF  = 0x02,   // 嗅探模式 (低功耗, 定期唤醒) ← 车载推荐
    BTM_PM_MD_PARK   = 0x03,   // 停驻模式 (最低功耗, 延时最大)
    BTM_PM_MD_FORCE  = 0x10,   // 强制标志(OR组合)
};

enum : uint8_t {
    BTM_PM_STS_ACTIVE  = 0x00,
    BTM_PM_STS_SNIFF   = 0x02,
    BTM_PM_STS_SSR,             // Sniff Subrating (更省电)
    BTM_PM_STS_PENDING,
    BTM_PM_STS_ERROR
};
```

**车载推荐Sniff参数**：

| 场景 | max_sniff | min_sniff | attempt | timeout | 说明 |
|------|-----------|-----------|---------|---------|------|
| 音乐播放 | 不启用 | — | — | — | 音频需要低延迟 |
| 通话中 | 不启用 | — | — | — | SCO独占 |
| 空闲BLE | 500ms | 100ms | 4 | 2 | 省电且保持心跳 |
| 后排娱乐 | 200ms | 50ms | 4 | 1 | 遥控器响应及时 |
| 停车休眠 | 800ms | 400ms | 2 | 4 | 极度省电 |

## 3. 蓝牙唤醒机制

### 3.1 三种唤醒方式

```
唤醒方式         │ 机制                    │ 适用场景
─────────────────┼─────────────────────────┼──────────────────
远端设备连接      │ 手机发起ACL连接请求     │ 手机靠近车机
                  │ → HCI Connection Request│ → 蓝牙芯片产生中断
                  │ → GPIO唤醒SoC           │ → 车机唤醒

BLE Notification  │ 已配对的BLE设备发送     │ 数字钥匙靠近
                  │ 数据/连接请求           │ HID遥控器按键
                  │ → BLE Advertising包     │ TPMS传感器报警

GPIO中断          │ 蓝牙芯片通过GPIO引脚    │ 硬件唤醒
                  │ 直接唤醒SoC             │ 最低延迟
```

### 3.2 HID设备唤醒

源码：[btif_dm.cc](file:///d:/AndroidWorkspace/claudeProject/BT16Study/Bluetooth/system/btif/src/btif_dm.cc)

```cpp
void btif_dm_allow_wake_by_hid(

{

```

**唤醒逻辑**：
```
1. btif_storage_get_wake_capable_classic_hid_devices()
   → 从存储中读取允许唤醒的HID设备列表

2. 将这些设备的BD_ADDR配置到蓝牙芯片固件

3. 休眠时: 芯片检测到这些设备的连接请求 → 触发唤醒
   非白名单设备的请求 → 忽略(不唤醒车机)

4. 唤醒后: btif_hh.cc → hh_open_handler → 恢复HID连接
```

### 3.3 AutoOn 自动开启机制

源码：[AutoOn.kt](file:///d:/AndroidWorkspace/claudeProject/BT16Study/Bluetooth/service/src/AutoOn.kt)

```kotlin
// AutoOn核心逻辑
class AutoOn {
    // 设置键
    val KEY_AUTO_ON = "bluetooth_automatic_turn_on"
    val KEY_AUTO_ON_TIMER = "bluetooth_internal_automatic_turn_on_timer"
    
    // 默认唤醒时间: 每天早上5:00
    val DEFAULT_TIMEOUT = nextDayAt5AM()
    
    // 开启条件
    fun shouldAutoOn(): Boolean {
        if (isBluetoothAlreadyOn()) return false    // 已开启
        if (isSatelliteMode()) return false          // 卫星模式
        if (isAirplaneMode()) return false           // 飞行模式
        return true
    }
    
    // 定时任务: AlarmManager.setExactAndAllowWhileIdle()
    fun scheduleAutoOn(timeout: Long) {
        alarmManager.setExactAndAllowWhileIdle(
            RTC_WAKEUP, timeout, pendingIntent
        )
    }
}
```

**AutoOn触发后的流程**：
```
AlarmManager触发 → BroadcastReceiver
  ↓
BluetoothManagerService.enableFromAutoOn()
  ↓ 原因: ENABLE_DISABLE_REASON_AUTO_ON
发送广播: ACTION_AUTO_ON_STATE_CHANGED
  ↓
AdapterState: TURNING_ON → ON
  ↓
加载已配对设备 → 自动连接
  ↓
连接成功后 → 不需要用户操作
```

## 4. 休眠/唤醒流程

### 4.1 车机进入休眠时蓝牙的处理

```
步骤1: 准备休眠 (收到PowerManager休眠通知)
  ──────────────────────────────────────────
  1. 停止主动扫描 (停止Inquiry + LE Scan)
  2. 所有连接进入Sniff Mode
  3. BLE: 保留连接, 增大Connection Interval (如30ms→500ms)
  4. HID: 保留唤醒白名单
  5. 保存已连接设备状态到 Flash

步骤2: 蓝牙芯片进入低功耗
  ──────────────────────────────────────────
  1. HCI: Sniff Mode Request (所有ACL)
  2. HCI: Write Scan Enable (0x00, 关闭扫描)
  3. VSC: 配置GPIO唤醒引脚
  4. VSC: 设置BLE Advertising过滤(仅白名单设备)
  5. 芯片进入 Low Power Mode

步骤3: SoC进入休眠
  ──────────────────────────────────────────
  1. 蓝牙芯片通过UART告警(HCI_WAKE_IND) → SoC确认
  2. SoC保存CPU状态 → 进入Suspend-to-RAM
  3. 仅RTC + GPIO唤醒源保持供电
```

### 4.2 车机唤醒时蓝牙的恢复

```
触发唤醒:
  ──────────────────────────────────────────
  方式A: 用户点火/ACC ON → SoC全唤醒
  方式B: 手机靠近 → 蓝牙芯片→GPIO→SoC唤醒
  方式C: AutoOn定时器 → AlarmManager RTC唤醒

蓝牙恢复流程:
  ──────────────────────────────────────────
  1. SoC唤醒 → 蓝牙芯片恢复供电
  2. 蓝牙HCI初始化 (HCI_RESET + Read_Local_Features + ...)
     → 与首次启动相同, 但更快(省略部分步骤)
  3. 加载之前的配对和连接状态 (btif_config.cc)
     → 读取存储的 link_key, lt_key, irk
     → 读取设备优先级 (PRIORITY_AUTO_CONNECT)
  4. 自动连接已配对设备
     → btif_dm.cc: btif_dm_get_connection_state()
     → 按优先级依次尝试连接
  5. BLE恢复:
     → 重新建立GATT连接
     → 恢复CCCD (之前订阅的Notification)
     → 恢复MTU
```

### 4.3 连接恢复机制

```
Page Scan (BR/EDR恢复):
  休眠前: 设置Page Scan参数 + 开机后自动进入Page Scan
  唤醒后: 手机发起Page → 车机响应 → 快速重连 (不回连配对流程)

Whitelist (BLE恢复):
  休眠前: 将已绑定设备加入White List
  唤醒后: 车机发送Connect_Request (with White List)
          → 跳过Scanning阶段 → 直接连接
```

### 4.4 数据一致性保证

```
配对信息: 存储在 /data/misc/bluedroid/bt_config.conf
  → 跨休眠持久化
  → 启动时 btif_config.cc 读取恢复

GATT数据库: 缓存在 bta_gattc_cache.cc
  → 休眠后可能丢失(内存缓存)
  → 唤醒后需要重新做 Service Discovery

CCCD: 存储在蓝牙芯片Flash
  → 芯片重新配置时恢复
  → 如果丢失 → GATT Server重新注册后重写CCCD
```

## 5. 常见问题

### 5.1 休眠后蓝牙无法唤醒

```
症状: 熄火后再次点火, 蓝牙一直处于OFF状态

排查:
1. dumpsys bluetooth_manager → enabled: false
2. logcat -s bt_stack_manager | grep "enable"
3. 检查蓝牙芯片供电(GPIO/VREG)是否正常
4. 检查UART通信: /dev/ttyHS0 是否可用

常见原因:
  → 休眠时蓝牙芯片未正确断电(FW异常)
  → GPIO唤醒引脚配置错误
  → UART驱动未恢复 (需要重新open)
  
解决:
  → 休眠前强制发送 HCI_RESET
  → 唤醒后重新初始化整个HCI层(stack_manager.cc: start_up_stack_async)
  → 增加超时重试(如果首次enable失败)
```

### 5.2 唤醒后连接丢失

```
症状: 点火后蓝牙开启, 但之前连接的设备未自动重连

排查:
1. dumpsys → 检查已配对设备PRIORITY是否为AUTO_CONNECT(1000)
2. logcat -s bt_btif_dm | grep "connect_int"
3. 检查设备是否在扫描范围内

常见原因:
  → PRIORITY在休眠时未正确保存
  → 设备的Link Key过期
  → BLE White List未正确配置
  → 手机端蓝牙未开启/未在扫描

解决:
  → 休眠前保存PRIORITY到bt_config.conf
  → 唤醒后延迟5秒再开始自动连接(等待RF稳定)
  → BLE: 使用direct_connect(跳过扫描, 直接连接)
```

### 5.3 唤醒后音频异常

```
症状: 唤醒后A2DP连接成功但无声音

原因:
  → Audio HAL未正确恢复 (AudioPolicy未检测到蓝牙输出设备)
  → Offload DSP未重新加载codec (DSP还处于休眠状态)
  → A2DP会话状态不一致 (手机以为在播放, 车机以为已暂停)

解决:
  → 唤醒后先Disconnect再Reconnect (强制重新建立AVDT会话)
  → Audio HAL: 重新枚举输出设备
  → Offload: 发送vendor command重新加载DSP codec
```

### 5.4 功耗过高

```
症状: 熄火后电池消耗过快, 蓝牙是主要耗电来源

排查:
1. dumpsys batterystats → 查看蓝牙耗电占比
2. 检查是否有设备未进入Sniff模式

优化:
  → 熄火后立即停止所有扫描
  → 强制所有连接进入Sniff (max_sniff=800ms)
  → 断开非必要BLE连接(仅保留数字钥匙)
  → 蓝牙芯片进入Deep Sleep (HCI_VSC_SLEEP_MODE)
```
