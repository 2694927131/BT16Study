## 3. 工作边界（能做什么 / 不能做什么）

### 3.1 可以做

- 读取 `doc/` 下的所有文档；
- 读取 `framework/` `service/` `android/` `system/` `flags/` 等源码目录（**只读**，用来理解上下文）；
- 在 `doc/学习资料_v2/<章>/` 下**生成或编辑** Markdown 章节文件；
- 运行 `scripts/scaffold_section.py` 和 `scripts/verify_section.py`；
- 更新 `doc/开发跟踪记录.md` 反映你的进度；
- 按项目约定执行 `git add` + `git commit`。

### 3.2 禁止做

| 禁止行为 | 原因 |
|---------|------|
| 修改 `doc/` 之外的任何目录 | 那是被学习的源码，不可污染 |
| 修改 `doc/学习资料_v2/_物料包/` 下的 `.yaml` 文件 | 物料包是强模型/人工的产出，你只能读 |
| 修改 `doc/v2_编写规范.md` / `doc/术语表.md` / `doc/v2_Mermaid模板库.md` / `doc/v2_反例库.md` | 这些是规则文件，规则不能由你改 |
| 修改 `scripts/` 下的 Python 脚本 | 自检规则不能由你自己放宽 |
| 编造 `file:line` 引用 | 所有引用必须来自物料包 `allowed_refs`，未列入的禁止使用 |
| 改写函数名、变量名 | 必须从物料包 `code_snippets` 或 `allowed_refs.purpose` 字段中**逐字复制** |
| 用模板库之外的 Mermaid 图样式 | 见模板库 §I 禁用清单 |
| 自检 FAIL 时强行 commit（如 `--no-verify`） | 自检 FAIL 就是不允许 commit，必须修改后通过 |
| 用 "Master/Slave"、"主设备/从设备"、"长期密钥" 等被列入黑名单的术语 | 见术语表 |

### 3.3 必须做

- 每节生成的文件必须包含**完整十二段标题**，顺序与规范一致；
- 每节至少 6 条 `file:line` 引用，且每条都能 Grep 命中；
- 每节至少 2 张 Mermaid 图，全部使用模板库中的模板编号；
- 每节字数下限按物料包 `section_outline.<段>.min_words` 执行；
- 完成一章（不是一节）后执行一次 `git commit`，commit message 格式：`docs(v2): 完成 <章节编号> <章节名>`；
- 中文交付，所有对话与文档使用中文。

## 4. 单节工作循环（五步流程）

```
┌────────────────────────────────────────────────────────┐
│ Step 1: 读物料包                                        │
│   cat doc/学习资料_v2/_物料包/<章>/<节>.yaml            │
│   ↓ 确认你能看懂 allowed_refs / code_snippets /         │
│     mermaid_templates / section_outline 四个字段        │
└────────────────────────────────────────────────────────┘
                         ↓
┌────────────────────────────────────────────────────────┐
│ Step 2: 生成脚手架（若还没生成）                          │
│   python scripts/scaffold_section.py \                  │
│     doc/学习资料_v2/_物料包/<章>/<节>.yaml              │
│   ↓ 输出 doc/学习资料_v2/<章>/<节>.md（含 12 段空标题   │
│     + 每段约束注释 + 已插入的代码片段/Mermaid 占位）    │
└────────────────────────────────────────────────────────┘
                         ↓
┌────────────────────────────────────────────────────────┐
│ Step 3: 填空                                            │
│   - 在每段「<!-- ↑ 在此段下方填写中文内容 -->」位置上方填中文 │
│   - 不要删除任何 HTML 注释（约束/术语/陷阱提示）         │
│   - 不要修改一级标题文字与顺序                            │
│   - Mermaid 占位块按推荐模板从 doc/v2_Mermaid模板库.md   │
│     复制源码并填占位符                                    │
└────────────────────────────────────────────────────────┘
                         ↓
┌────────────────────────────────────────────────────────┐
│ Step 4: 自检                                            │
│   python scripts/verify_section.py \                    │
│     doc/学习资料_v2/<章>/<节>.md \                       │
│     --materials doc/学习资料_v2/_物料包/<章>/<节>.yaml  │
│   退出码: 0 PASS / 1 FAIL / 2 WARN                       │
└────────────────────────────────────────────────────────┘
                         ↓
              ┌──────────┴──────────┐
              │                     │
           PASS                   FAIL
              │                     │
              ↓                     ↓
       Step 5 commit         回 Step 3 修改
                              （≤ 3 轮，仍失败
                              → 停下来等人工）
```

### 4.1 Step 5：commit 时机与格式

**不是每节都 commit，而是每完成一整章再 commit。**

- 章节内的小节（如 13.1、13.2、13.3）边写边落盘，**暂不提交**；
- 写完该章的最后一节后，更新 `doc/开发跟踪记录.md` 把整章状态翻成 ✅；
- 然后一次性 `git add` 全章所有新增/修改的文件，统一 `git commit`：

```bash
git add doc/学习资料_v2/<章>/ doc/开发跟踪记录.md
git commit -m "docs(v2): 完成第 <章号> 章 <章名>"
```

**不要询问用户是否提交，自动执行**（项目硬性约定）。

## 5. 自检失败怎么办

`scripts/verify_section.py` 检查 14 项,FAIL 即阻断 commit。常见 FAIL 与对应修法:

| FAIL 项 | 原因 | 修法 |
|--------|------|------|
| 十二段标题缺失 | 删了某个 `## §N` 标题 | 从脚手架重新对照,把缺失段加回来 |
| 十二段顺序错 | 段间被调换 | 按规范顺序重排 |
| file:line 引用数 < 6 | 引用不足 | 从物料包 allowed_refs 选未用过的补充 |
| file:line Grep 失败 | 凭印象编了行号 | 删掉编造的引用,只用物料包列出的 |
| file:line 不在 allowed_refs | 用了物料包白名单外的引用 | 删掉,换成白名单内的 |
| Mermaid 块数 < 2 | 图太少 | 按物料包 mermaid_templates 推荐补图 |
| 各段字数下限 | 内容太薄 | 按 min_words 扩写,但不要灌水(灌水会被人工抽审驳回) |
| 调用链层数 < 4 | §6 写得太浅 | 补足 App → Framework → Service → JNI → BTIF → BTA → Stack 各层 |
| FAQ < 3 / 上路任务 < 2 | §12 不够 | 从物料包 suggested_faqs / suggested_homeworks 选用 |
| 术语黑名单命中 | 用了 Master/Slave 等 | 全文替换为 canonical 术语 |

### 5.1 三轮仍 FAIL 的处理

```
轮 1 FAIL → 看 verify_section.py 输出的 detail,精确修改
轮 2 FAIL → 重读物料包对应段的 outline + 反例库相关章节
轮 3 FAIL → 停下来,在控制台明确说出:
            "本节自检 3 轮仍 FAIL,请人工审查 <章节路径>"
            然后等待人工指示,不要继续硬填。
```

**禁止用 `git commit --no-verify` 等任何方式绕过自检**。
