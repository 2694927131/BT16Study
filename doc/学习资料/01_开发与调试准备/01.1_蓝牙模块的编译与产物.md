# 01.1 蓝牙模块的编译与产物

> 速通摘要：本仓库是 **Mainline 模块** `packages/modules/Bluetooth`，编译产物落在 APEX `com.android.btservices`。常用单点编译命令是 `m com.android.btservices`（在 AOSP 根）；车机本地若没有完整 AOSP 树，多数情况下你**不需要编译**——只是改代码读懂栈而已。理解产物名能让你定位 OTA 后哪个 so 被更新。

---

## 1. 学习目标

读完本节，你应该能：

1. 说清本仓库属于 AOSP 哪个模块、走 Mainline 升级。
2. 默写主要产物的名字（`libbluetooth.so`、`libbluetooth_jni.so`、`com.android.btservices.apex` 等）。
3. 知道如何只编蓝牙模块，跳过 Android 全量构建。
4. 在车机上找到当前运行的产物路径。

## 3. 场景故事：你改了 `BondStateMachine` 一个 bug，怎么部署？

```
本地修改：android/app/src/com/android/bluetooth/btservice/BondStateMachine.java
   │
   ▼  在 AOSP 根目录
m com.android.btservices       ← 仅编译蓝牙 APEX
   │
   ▼
out/target/product/<device>/obj/PACKAGING/apex/com.android.btservices.apex
   │
   ▼  推送到设备
adb root && adb remount  (或) adb install --apex com.android.btservices.apex
   │
   ▼  重启
adb reboot
```

车机现实：很多车厂构建系统不是标准 AOSP，而是基于 Yocto/自研。这种情况下你需要联系系统组拿到"仅编 BT 模块"的脚本——但**逻辑上仍是这套**。

## 4. 仓库结构对应到产物

| 仓库子目录 | 产物 | 安装路径 |
|----------|------|---------|
| `framework/java` | `framework-bluetooth.jar` | `/apex/com.android.btservices/javalib/` |
| `service/src` | `service-bluetooth.jar` | `/apex/com.android.btservices/javalib/` |
| `android/app/src` | `Bluetooth.apk`（蓝牙 App） | `/apex/com.android.btservices/app/Bluetooth/` |
| `android/app/jni` | `libbluetooth_jni.so` | `/apex/com.android.btservices/lib*/` |
| `system/` 全部 | `libbluetooth.so` | `/apex/com.android.btservices/lib*/` |
| `flags/*.aconfig` | 编译期 → Java `Flags`/C++ `bluetooth::flags::*` | 不单独安装 |
| `sysprop/*.sysprop` | 编译期 → `BluetoothProperties` API | 不单独安装 |

整体打包成 **`com.android.btservices.apex`** 一个 APEX 包。

## 5. 常用编译命令（AOSP 根目录）

```bash
# 准备
source build/envsetup.sh
lunch <product>-userdebug

# 仅编蓝牙 APEX
m com.android.btservices

# 编 framework 部分（Java API）
m framework-bluetooth

# 编蓝牙 App
m Bluetooth

# 编 native 协议栈
m libbluetooth

# 编 JNI
m libbluetooth_jni

# 跑单元测试（在 AOSP 中）
atest BluetoothInstrumentationTests
atest net_test_btif_dm    # 等 native 测试

# 看产物在哪
ls -la out/target/product/$TARGET_PRODUCT/system/apex/com.android.btservices/
```

## 6. 在车机上定位当前运行产物

```bash
# 1. 查 APEX 挂载
adb shell ls /apex/com.android.btservices/

# 2. 查蓝牙 App 进程加载的 SO
adb shell "cat /proc/$(pidof com.android.bluetooth)/maps | grep libbluetooth"

# 3. 查 framework jar
adb shell ls /apex/com.android.btservices/javalib/

# 4. 查 APEX 版本
adb shell dumpsys package com.android.btservices | grep versionName
```

## 7. 编译期 vs 运行期

| 维度 | 来源 | 影响 |
|------|------|------|
| **aconfig flag** | `flags/*.aconfig`，编译期生成 Java/C++ 头 | 重编 + OTA 才能改 |
| **sysprop** | `sysprop/*.sysprop`，运行时 `getprop`/`setprop` | 立即生效（重启蓝牙 App 后） |
| **`bt_stack.conf` / `bt_did.conf`** | `system/conf/`，启动时读取 | 改文件后重启蓝牙 App 生效 |
| **`device_config`（Phenotype）** | 远端配置 | 实时 push，可灰度（依赖 OEM 支持） |

例：要快速验证"关掉某 flag 行为"是否解决 bug，**先看 flag 是否能用 device_config 覆盖**——不能就只能重编。

## 8. 跨 Android 版本的差异

| 版本 | 蓝牙模块状态 |
|------|------------|
| Android 10 及以前 | 蓝牙在 `packages/apps/Bluetooth`，非 Mainline |
| Android 11 | 引入 GD，仍非 Mainline |
| Android 12+ | 成为 Mainline 模块（APEX），可独立升级 |
| Android 13+ | `BluetoothManagerService` 用 Kotlin 重写在 `service/src/` |
| Android 16（本仓） | 完整 Mainline + Kotlin + aconfig |

**车机注意**：很多车厂在 Android 12/13 没启用 Mainline 蓝牙（怕影响稳定性），把它编入 system.img。本仓代码两种方式都兼容。

## 9. 调试方法

| 想看 | 方法 |
|------|------|
| 当前 APEX 是否启用了 Mainline | `adb shell ls -l /apex/com.android.btservices/`；符号链接到 `/system/apex/...` = 静态，否则是动态加载 |
| 编译产物时间戳 | `adb shell stat /apex/com.android.btservices/lib*/libbluetooth.so` |
| 我推的版本是否生效 | `adb shell md5sum /apex/com.android.btservices/lib*/libbluetooth.so` + 本地 md5 对比 |
| 编译期 flag 默认值 | `grep -A 5 "<flag_name>" flags/*.aconfig` |

## 10. FAQ

**Q1：车机环境没法用 `m com.android.btservices`，怎么改代码？**
A：通常做法：
1. 用车厂的 yocto / 自研构建系统，找到 BT 子项目的 build target。
2. 或者用 AOSP 单独构建蓝牙 APEX，手动推到车机覆盖。
3. 或者只读源码不重编（多数学习者）。

**Q2：改了 Java 代码不重编蓝牙 App 能不能生效？**
A：不能。Java 代码是 dex 在 `Bluetooth.apk` 里。

**Q3：sysprop 改了立刻生效吗？**
A：通常需要"重启蓝牙开关"或"重启蓝牙 App 进程"。本仓里有些 sysprop 是 `ro.*`（只读、开机读），改后必须重启。

**Q4：能不能边测试边改 `bt_stack.conf`？**
A：可以。改后 `adb shell svc bluetooth disable && enable` 重启蓝牙 App 进程即可。

**Q5：把蓝牙 APEX 替换后系统起不来？**
A：常见原因：① APEX 签名不匹配（要禁 verity 或用 testkey 重签）；② 版本号回退被拒；③ 依赖的 framework 改动未同步。建议先用 testkey + `adb install --apex` + `adb reboot`。

## 12. 本节小结（速记卡）

```
本仓 = AOSP packages/modules/Bluetooth Mainline 模块
APEX：com.android.btservices.apex
产物：
  libbluetooth.so      ← system/ 全部 C++
```
