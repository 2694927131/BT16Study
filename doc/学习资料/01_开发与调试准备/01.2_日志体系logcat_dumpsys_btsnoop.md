# 01.2 日志体系：`logcat` / `dumpsys` / `btsnoop` / HCI log

> 速通摘要：蓝牙调试的"四件套"——`logcat` 看 Java/Native log、`dumpsys bluetooth_manager` 看进程状态快照、`btsnoop_hci.log` 看 HCI 二进制流（Wireshark 打开）、栈 internal log 看 BTA/BTM 内部状态。**90% 的车机蓝牙 bug 用这四样工具就能定位**。

---

## 1. 学习目标

读完本节，你应该能：

1. 默写四种日志工具的用途、命令、解析方式。
2. 看 `dumpsys bluetooth_manager` 输出的常见段落，每段定位到源码类。
3. 抓出 BTSnoop 文件并用 Wireshark 看 HCI 流。
4. 知道日志 tag 与 sysprop 之间的关系（动态调日志级别）。

## 3. 工具一：`logcat`（Java/Native 双源）

### 3.1 Java 端常用 tag

| Tag | 来源 |
|-----|------|
| `BluetoothAdapter` | `framework/java/.../BluetoothAdapter.java` |
| `BluetoothManagerService` / `BluetoothService` | `service/src/` |
| `BluetoothAdapterService` | `android/app/.../btservice/AdapterService.java` |
| `BluetoothAdapterServiceBinder` | `AdapterServiceBinder.java` |
| `BluetoothAdapterState` | `AdapterState.java` |
| `BluetoothBondStateMachine` | `BondStateMachine.java` |
| `BluetoothRemoteDevices` | `RemoteDevices.java` |
| `BluetoothJniCallbacks` | `JniCallbacks.java` |
| `BluetoothPhonePolicy` | `PhonePolicy.java` |
| `BluetoothActiveDeviceManager` | `ActiveDeviceManager.java` |
| `BluetoothA2dpService` / `BluetoothHeadsetClientService` / `BluetoothGattService` / 等 | 各 Profile Service |

> 仓库里所有 Java 日志 tag 命名规律：`Utils.BT_PREFIX + class.getSimpleName()`，`BT_PREFIX = "Bluetooth"`。

### 3.2 Native 端常用 tag

Native 端用 `log::verbose/info/warn/error`（来自 `system/log/`），底层走 `__android_log_*`，tag 在 SO 里集中设置。

| Tag | 来源 |
|-----|------|
| `bluetooth` | 全栈默认 tag（`com_android_bluetooth_btservice_AdapterService.cpp:2330` 起设置） |
| `bt_btif` / `bt_btif_dm` / `bt_btif_av` / `bt_btif_hf` | BTIF 各模块 |
| `bt_bta_dm` / `bt_bta_av` / `bt_bta_ag` / `bt_bta_hf_client` | BTA |
| `bt_btm` / `bt_btm_sec` / `bt_btm_inq` / `bt_btm_sco` | BTM |
| `bt_l2cap` / `bt_smp` / `bt_gatt` / `bt_avdt` / `bt_avrc` | Stack 协议层 |
| `bt_hci` | HCI |
| `bt_osi_alarm` | OSI |

### 3.3 动态调日志级别

```bash
# 一次性提级（重启进程后失效）
adb shell setprop log.tag.BluetoothAdapter VERBOSE
adb shell setprop log.tag.bluetooth VERBOSE

# 持久化（重启系统也保留）
adb shell setprop persist.log.tag.bluetooth VERBOSE

# 看当前 minimum priority（Native）
adb logcat -d | head -5     # 找 "Set stack default log level to ..."
```

`JNI_OnLoad` 启动时根据 `log.tag.bluetooth` 决定 native 最低日志级别（详 `com_android_bluetooth_btservice_AdapterService.cpp:2332-:2347`）。

### 3.4 常用过滤组合

```bash
# 看一切蓝牙
adb logcat | grep -i "blueto\|bt_"

# 只看错误
adb logcat *:S BluetoothAdapter:E BluetoothAdapterService:E bt_btm:E

# 关注配对
adb logcat | grep -E "Bond|SSP|PIN_|Pairing|smp"

# 关注 A2DP
adb logcat -s BluetoothA2dpService bt_btif_av bt_bta_av bt_avdt bt_a2dp
```

## 4. 工具二：`dumpsys bluetooth_manager`

```bash
adb shell dumpsys bluetooth_manager > /tmp/bm.txt
```

输出（量很大，按段）大致包含：

| 段名 | 含义 | 对应类 |
|------|------|--------|
| `Bluetooth Status` | 顶层开关状态、Hearing Aid 支持 | `BluetoothManagerService` |
| `AdapterState` | 子态机当前态 | `AdapterState` |
| `AdapterProperties` | 名称、地址、scan_mode、UUID 列表 | `AdapterProperties` |
| `BondStateMachine` | 当前配对中设备、最近事件 | `BondStateMachine` |
| `Bonded devices` | 已绑定设备完整列表 | `RemoteDevices` |
| `Profile Services` | 各 Profile 是否启用、当前连接 | 各 Service |
| `A2DP State` / `HFP State` / `GATT State` / `LE Audio` | 每 Profile 详细 | 各 Service dumpsys |
| `ACL stats` | ACL 连接计数 | BTM acl |
| `Btif Counters` | 各 Profile 调用计数 | BTIF |
| `Bond Events` / `Discovery Events` | 历史事件流 | `BTM_LogHistory` |
| `HCI counters` | HCI 命令/事件计数 | hci |
| `Flags` | aconfig 当前值 | aconfig |

**实战技巧**：每次出问题就 `dumpsys` 一份留底，再做"复现 → 再 dump → diff"。三段一对比，99% 的状态问题能定位。

`dumpsys` 还能传参数：
```bash
adb shell dumpsys bluetooth_manager -h     # 帮助
adb shell dumpsys bluetooth_manager --proto   # protobuf 格式（脚本解析）
```

## 5. 工具三：BTSnoop（HCI 二进制日志）

### 5.1 开关

```bash
# 设置模式（FULL / FILTERED / DISABLED）
adb shell setprop persist.bluetooth.btsnooplogmode full

# 重启蓝牙生效
adb shell svc bluetooth disable && sleep 2 && adb shell svc bluetooth enable

# 抓完拉回
adb pull /data/misc/bluetooth/logs/btsnoop_hci.log
```

> 路径在不同车机可能不同。一些厂商用 `/data/vendor/bluetooth/logs/`。

### 5.2 用 Wireshark 打开

`btsnoop_hci.log` 是 BTSnoop V1 格式，Wireshark 直接打开。常见过滤：

| 过滤式 | 含义 |
|--------|------|
| `hci_h4.type == 0x01` | HCI Command |
| `hci_h4.type == 0x04` | HCI Event |
| `hci_evt.code == 0x0e` | Command Complete |
| `hci_evt.code == 0x05` | Disconnect Complete |
| `bthci_acl` | ACL 数据 |
| `btl2cap` | L2CAP |
| `btrfcomm` | RFCOMM |
| `btsdp` | SDP |
| `btavdtp` / `btavrcp` | A2DP / AVRCP |
| `btatt` / `btgatt` | ATT / GATT |
| `btsmp` | SMP |

### 5.3 模式说明

- `full` — 所有 HCI 包含 payload（**调试用**）。
- `filtered` — 媒体 payload 去掉，仅保留控制字段（**生产/隐私要求**）。
- `disabled` — 不抓。

aconfig flag 也能控制：`flags/snoop_logger_*.aconfig` 系列。

## 6. 工具四：栈 internal log

栈侧有专门的"事件历史" `BTM_LogHistory`（`system/stack/btm/`），落到 dumpsys 的 `History` 段。每条记录：
```
<timestamp> <tag> <addr> <activity> <detail>
```

例子（来自 `btif_dm.cc:2729`）：
```cpp
BTM_LogHistory(
    kBtmLogTag, RawAddress::kEmpty, "Device discovery",
    std::format("is_request_queued:{:c}", bta_dm_is_search_request_queued() ? 'T' : 'F'));
```

通过这一行就能在 `dumpsys` 看到一条"Device discovery [is_request_queued:F]"。

```mermaid
    GD -.btsnoop.-> S[btsnoop_hci.log → Wireshark]
```

## 8. 调试方法（综合）

### 8.1 配对失败排查流程

1. `logcat -s BluetoothBondStateMachine bt_btif_dm bt_btm_sec` — 看状态机消息与栈侧 SSP 流程。
2. `dumpsys bluetooth_manager` — 看 `Bond Events` 段、`BondStateMachine` 当前态。
3. BTSnoop — 看 `Authentication_Requested` 是否下发、`Read_Local_OOB_Data` 是否成功。
4. `bt_config.conf` — 看是否有半成品条目。

### 8.2 A2DP 卡顿排查流程

1. `logcat -s BluetoothA2dpService bt_btif_av bt_a2dp bt_avdt` — 看丢包警告。
2. `dumpsys bluetooth_manager` 找 `A2DP State` 段，看缓冲水位、codec、bitrate。
3. BTSnoop — 看 ACL 重传、L2CAP 流控；看 `HCI_Number_of_Completed_Packets` 时序。
4. `audio_hal_interface` log — Audio HAL 端是否丢数据。

### 8.3 BLE 连不上排查流程

1. `logcat -s BluetoothGattService bt_gatt bt_btm bt_smp` — 看连接、SMP 时序。
2. nrf Connect 等工具确认对方广告周期。
3. BTSnoop — 看 `LE_Create_Connection` 是否下发、`LE_Connection_Complete` 状态码。

## 9. FAQ

**Q1：`logcat` 看不到 native log 怎么办？**
A：检查 `setprop log.tag.bluetooth` 级别；蓝牙 App 进程是否在跑（`pidof com.android.bluetooth`）。

**Q2：BTSnoop 取不出来？**
A：① selinux 拦截 → `adb root`；② 路径不同 → 找 `system/conf/bt_stack.conf` 里 `BtSnoopFileName`；③ 模式没开 → 检查 sysprop。

**Q3：dumpsys 输出太长不易看？**
A：用 `sed -n '/^Bonded devices/,/^$/p' bm.txt` 截段；或 `--proto` 出二进制再用脚本解。

**Q4：Wireshark 不识别新版 HCI?**
A：升级 Wireshark 到 ≥ 4.0；旧版可能不支持 LE Extended Advertising / EATT。

**Q5：能否在生产机长开 full BTSnoop？**
A：通常**不可以**——含明文 PIN / 密钥 / 通话音频片段，隐私+性能双坑。
