## 3. 速查卡：日常 15 条

```bash
# === 设备连接 ===
adb devices                          # 列出设备
adb root && adb remount              # 拿到 root + 系统分区可写（仅 userdebug）
adb shell                            # 进 shell

# === 蓝牙开关 ===
adb shell svc bluetooth enable       # 开蓝牙
adb shell svc bluetooth disable      # 关蓝牙
adb shell cmd bluetooth_manager enable
adb shell cmd bluetooth_manager disable
adb shell setprop persist.bluetooth.enable true   # 持久开（重启保留）

# === 状态查看 ===
adb shell dumpsys bluetooth_manager  # 全状态快照（最重要）
adb shell dumpsys bluetooth_manager | grep -A 3 "AdapterState"
adb shell pidof com.android.bluetooth   # 蓝牙 App 进程 PID
adb shell ps -A | grep -iE "blue|bt"    # 蓝牙相关进程

# === 日志 ===
adb logcat -c                        # 清空缓冲
adb logcat -d > /tmp/log.txt         # 一次性导出当前
adb logcat | grep -iE "blueto|bt_"   # 实时
adb shell setprop log.tag.bluetooth VERBOSE   # 调高 native 日志

# === BTSnoop ===
adb shell setprop persist.bluetooth.btsnooplogmode full
adb pull /data/misc/bluetooth/logs/btsnoop_hci.log

# === 强制清理 ===
adb shell pm clear com.android.bluetooth        # 清蓝牙 App 数据 + 状态
adb shell stop && adb shell start               # 重启 system_server（重试整套）

# === 配置文件 ===
adb pull /data/misc/bluedroid/bt_config.conf    # 已配对设备 + 链路密钥
adb shell ls -la /apex/com.android.btservices/  # 当前 APEX 内容

# === 重启 ===
adb reboot                           # 重启系统
adb shell svc bluetooth disable && sleep 2 && adb shell svc bluetooth enable
```

## 4. 分类详解

### 4.1 蓝牙开关组

| 命令 | 等价 | 何时用 |
|------|------|-------|
| `svc bluetooth enable/disable` | 模拟系统级开关 | 日常 |
| `cmd bluetooth_manager enable/disable` | 走 `BluetoothManagerService` Shell 命令 | 自动化测试 |
| `service call bluetooth_manager <code>` | 直接打 Binder | 高级（要查 AIDL code） |

### 4.2 状态查看组

```bash
# 关键段速选
adb shell dumpsys bluetooth_manager | sed -n '/Bluetooth Status/,/^$/p'
adb shell dumpsys bluetooth_manager | sed -n '/Bonded devices/,/^$/p'
adb shell dumpsys bluetooth_manager | sed -n '/A2DP State/,/^$/p'

# Profile 单独
adb shell dumpsys media.audio_flinger | grep -i blueto
adb shell dumpsys audio | grep -i blueto

# Flag 看运行时值（如果走 device_config）
adb shell device_config list bluetooth
adb shell device_config get bluetooth <flag_name>
```

### 4.3 日志组

```bash
# 单 tag 实时
adb logcat -s BluetoothAdapter:V

# 多 tag 实时
adb logcat -s BluetoothAdapter:V BluetoothAdapterService:V BluetoothBondStateMachine:V

# Profile 关注
adb logcat -s BluetoothA2dpService bt_btif_av bt_bta_av bt_a2dp bt_avdt

# 永久提级（要 root）
adb shell setprop persist.log.tag.bluetooth VERBOSE
```

### 4.4 强制清理组

`pm clear com.android.bluetooth` 几乎是"出大事时的核选项"——清掉蓝牙 App 进程的所有持久数据（包括 `bt_config.conf`、Profile 偏好设置）。**慎用**：会丢配对！

替代：
```bash
# 重启蓝牙 App 进程而不清数据
adb shell am force-stop com.android.bluetooth     # 通常被守护进程立即重拉
adb shell svc bluetooth disable && adb shell svc bluetooth enable   # 标准方法
```

### 4.5 sysprop 组

```bash
# 看全部
adb shell getprop | grep -iE "blueto|bt\."

# 重要的几个
adb shell getprop persist.bluetooth.btsnooplogmode
adb shell getprop persist.bluetooth.bluetooth_audio_hal.disabled
adb shell getprop persist.bluetooth.a2dp_offload.disabled
adb shell getprop persist.bluetooth.leaudio_offload.disabled

# 设置（多数 sysprop 改后要重启蓝牙生效）
adb shell setprop persist.bluetooth.btsnooplogmode full
adb shell svc bluetooth disable && adb shell svc bluetooth enable
```

### 4.6 配置文件组

```bash
# 已配对设备 + 密钥（敏感！）
adb shell cat /data/misc/bluedroid/bt_config.conf      # 需 root
adb pull /data/misc/bluedroid/bt_config.conf

# 蓝牙栈启动配置
adb shell cat /apex/com.android.btservices/etc/bluetooth/bt_stack.conf
adb shell cat /apex/com.android.btservices/etc/bluetooth/bt_did.conf

# 互操作数据库
adb shell cat /apex/com.android.btservices/etc/bluetooth/interop_database.conf
```

### 4.7 进程与权限组

```bash
# 蓝牙 App 进程信息
adb shell ps -p $(adb shell pidof com.android.bluetooth) -o uid,gid,cmd
adb shell cat /proc/$(adb shell pidof com.android.bluetooth)/maps | grep libblueto

# 当前 App 的蓝牙权限
adb shell dumpsys package <app_pkg> | grep -A 1 BLUETOOTH

# Hands-free 音频（车机调试常用）
adb shell dumpsys media.audio_policy | grep -iE "blueto|sco"
```

### 4.8 触发命令组

`cmd bluetooth_manager` 子命令（车机测试自动化常用）：
```bash
adb shell cmd bluetooth_manager help            # 看支持哪些子命令
adb shell cmd bluetooth_manager enable
adb shell cmd bluetooth_manager wait-for-state on
adb shell cmd bluetooth_manager set-bt-hci-snoop-log-mode full
```

## 5. 标准工作流：复现 + 取证

```bash
#!/bin/bash
# bt_capture.sh — 复现蓝牙问题前用
set -e
DEV=$1
OUT=/tmp/bt_$(date +%s)
mkdir -p $OUT

# 调高日志
adb -s $DEV shell setprop log.tag.bluetooth VERBOSE
adb -s $DEV shell setprop log.tag.BluetoothAdapter VERBOSE
adb -s $DEV shell setprop log.tag.BluetoothAdapterService VERBOSE

# 开 BTSnoop full
adb -s $DEV shell setprop persist.bluetooth.btsnooplogmode full

# 清空 logcat
adb -s $DEV logcat -c

# 重启蓝牙让设置生效
adb -s $DEV shell svc bluetooth disable
sleep 3
adb -s $DEV shell svc bluetooth enable
sleep 5

echo "==> 现在复现问题，完成后按回车"
read

# 取证
adb -s $DEV logcat -d > $OUT/logcat.txt
adb -s $DEV shell dumpsys bluetooth_manager > $OUT/dumpsys.txt
adb -s $DEV pull /data/misc/bluetooth/logs/btsnoop_hci.log $OUT/ 2>/dev/null || true
adb -s $DEV shell cat /data/misc/bluedroid/bt_config.conf > $OUT/bt_config.conf 2>/dev/null || true

echo "Saved to $OUT"
```

## 6. 权限速查

| 需要 root | 不需要 |
|----------|-------|
| `setprop persist.*`（持久 sysprop） | `setprop log.tag.*`（非持久） |
| 读 `/data/misc/bluedroid/bt_config.conf` | `dumpsys bluetooth_manager` |
| 读 BTSnoop 文件 | `logcat` |
| 写 `/apex/...`（rebind） | `svc bluetooth ...` |
| `pm clear com.android.bluetooth` | `cmd bluetooth_manager ...` |

> 车机量产机通常**没法 root**。所以核心调试要在 userdebug / 工程模式机上做。

---

## 7. 常见陷阱

**陷阱 1：用 `am force-stop com.android.bluetooth` 杀蓝牙 App**
后果：`BluetoothManagerService` 会立刻拉起，状态可能丢失。**推荐**用 `svc bluetooth disable && enable`。

**陷阱 2：以为 `pm clear` 等价于"重启蓝牙 App"**
后果：所有配对设备和首选项被清。

**陷阱 3：BTSnoop full 模式长期开**
后果：日志文件涨快，可能压满 `/data`；含敏感信息。

**陷阱 4：调试时忘记 `logcat -c` 清缓冲**
后果：dump 出来的 log 混入历史问题。

**陷阱 5：`adb pull` 失败但不报错**
后果：取的是空文件。每次 pull 后 `ls -l` 验证。

## 8. 调试方法

| 想验证 | 命令 |
|--------|------|
| adb 是否能用 | `adb devices` |
| 蓝牙 App 是否在跑 | `adb shell pidof com.android.bluetooth` |
| 蓝牙是否真的开 | `adb shell dumpsys bluetooth_manager | grep -E 'enabled|STATE_'` |
| 日志级别现在多少 | `adb shell getprop log.tag.bluetooth` |
| BTSnoop 模式 | `adb shell getprop persist.bluetooth.btsnooplogmode` |
| 当前哪台设备连着 | `adb shell dumpsys bluetooth_manager | grep -E 'Bonded|Connected'` |

## 9. FAQ

**Q1：车机没装 adb 怎么办？**
A：车厂工程模式通常会暴露 adb（USB / 网口 / 蓝牙）。需要联系 OEM 拿调试方法。学习阶段建议用手机或模拟器跑。

**Q2：`adb shell cmd bluetooth_manager` 报 "command not found"？**
A：可能蓝牙 App 未启动，或本机 `service-bluetooth.jar` 没注册 ShellCommand。看 `service/src/ShellCommand.kt`。

**Q3：`logcat` 看不到任何蓝牙输出？**
A：检查日志级别（`log.tag.bluetooth`）、`adb logcat -b all` 是否开启 main+system 缓冲。

**Q4：`dumpsys bluetooth_manager` 输出空？**
A：蓝牙 App 进程未跑或 Binder 死亡。先 `pidof com.android.bluetooth`，再看 logcat 报错。

**Q5：能不能远程通过 Wi-Fi adb 调？**
A：可以，`adb tcpip 5555` + `adb connect <ip>:5555`。车机有时只开 USB 调试，看 OEM 配置。
