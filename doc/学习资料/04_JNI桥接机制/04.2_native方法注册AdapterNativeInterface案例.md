# 04.2 native 方法注册：`AdapterNativeInterface` 案例

> 速通摘要：JNI 注册的本质是"把 Java 方法名映射到 C 函数指针"。Android 蓝牙全部用**动态注册**——`JNI_OnLoad` 调用 `RegisterNatives(env, jclass, methods[], n)`，其中 `methods[]` 数组每一项形如 `{"enableNative", "()Z", &enableNative_C}`。本节用 `AdapterNativeInterface` 这一对 Java/C 类做完整拆解。

---

## 1. 学习目标

读完本节，你应该能：

1. 默写 `JNINativeMethod` 结构体的三个字段。
2. 看懂 JNI 类型签名（如 `(I[B)Z`、`([B)V`、`(Ljava/lang/String;)I`）。
3. 把 `AdapterNativeInterface.java` 的 native 方法清单与 C 端 `methods[]` 数组对应起来。
4. 知道 `REGISTER_NATIVE_METHODS` 与 `GET_JAVA_METHODS` 两个宏在哪、做什么。

## 3. 场景故事：你在 Java 端加了个新 native 方法，怎么让它跑起来？

```text
1. 在 AdapterNativeInterface.java 里加：
     private native boolean myNewNative(byte[] addr);
2. 在 com_android_bluetooth_btservice_AdapterService.cpp 里加 C 函数：
     static jboolean myNewNative(JNIEnv* env, jobject obj, jbyteArray addr) { ... }
3. 在同文件 register_com_android_bluetooth_btservice_AdapterService 的
   JNINativeMethod methods[] 数组追加一项：
     {"myNewNative", "([B)Z", reinterpret_cast<void*>(myNewNative)},
4. 重编 libbluetooth_jni.so 并刷机。
```

漏 1 步 = `UnsatisfiedLinkError`。这就是为什么本节要把"注册三件套"讲透。

---

## 4. `JNINativeMethod` 的三个字段

```cpp
typedef struct {
    const char* name;       // ① Java 方法名（不要前缀，不要 Java_xxx_yyy_）
    const char* signature;  // ② JNI 签名（参数 + 返回值类型）
    void*       fnPtr;      // ③ 指向 C 函数的指针
} JNINativeMethod;
```

例（来自本仓 `com_android_bluetooth_btservice_AdapterService.cpp:2199-:2202`）：

```cpp
{"initNative",    "(ZZIZLjava/lang/String;)Z", reinterpret_cast<void*>(initNative)},
{"cleanupNative", "()V",                       reinterpret_cast<void*>(cleanupNative)},
{"enableNative",  "()Z",                       reinterpret_cast<void*>(enableNative)},
{"disableNative", "()Z",                       reinterpret_cast<void*>(disableNative)},
```

**签名怎么读**：
- `(ZZIZLjava/lang/String;)Z` = 参数列表 `(boolean, boolean, int, boolean, String)`，返回 `boolean`。
- `()V` = 无参，返回 `void`。
- `([B)Z` = `(byte[])boolean`。
- `([BII)Z` = `(byte[], int, int)boolean`。

## 5. JNI 类型描述符速查

| Java 类型 | 描述符 |
|----------|--------|
| `boolean` | `Z` |
| `byte` | `B` |
| `char` | `C` |
| `short` | `S` |
| `int` | `I` |
| `long` | `J` |
| `float` | `F` |
| `double` | `D` |
| `void`（返回值） | `V` |
| `String` | `Ljava/lang/String;` |
| `byte[]` | `[B` |
| `String[]` | `[Ljava/lang/String;` |
| `java.io.FileDescriptor` | `Ljava/io/FileDescriptor;` |
| `android.bluetooth.OobData` | `Landroid/bluetooth/OobData;` |
| 任意类 `X.Y.Z` | `LX/Y/Z;`（点变斜杠，加 `L...;`） |

> 加 `[` 表示数组。要更长的描述符，可用 `javap -s YourClass.class` 反编译验证。

## 7. 注册宏：`REGISTER_NATIVE_METHODS`

这是仓库自定义的便捷宏（封装了 ART 的 `RegisterNatives`，并加错误日志）。其使用如下（`:2267`）：

```cpp
const int result = REGISTER_NATIVE_METHODS(
        env,
        "com/android/bluetooth/btservice/AdapterNativeInterface",  // ① 目标 Java 类的全限定名
        methods);                                                    // ② JNINativeMethod 数组
if (result != 0) return result;
```

**展开后大致等价于**：

```cpp
jclass clazz = env->FindClass("com/android/bluetooth/btservice/AdapterNativeInterface");
if (clazz == nullptr) { /* log error */ return -1; }
int rc = env->RegisterNatives(clazz, methods, sizeof(methods)/sizeof(methods[0]));
env->DeleteLocalRef(clazz);
return rc;
```

注册成功后，Java 端 `private native boolean enableNative()` 调用就会直接跳到 C 端 `enableNative` 函数。

## 8. 取 Java 端回调方法 ID：`GET_JAVA_METHODS`

C 端要回调 Java，必须先拿到 Java 方法的 `jmethodID`。这是另一个仓库便捷宏（`:2302`）：

```cpp
const JNIJavaMethod javaMethods[] = {
    {"stateChangeCallback",          "(I)V",          &method_stateChangeCallback},
    {"adapterPropertyChangedCallback", "([I[[B)V",    &method_adapterPropertyChangedCallback},
    {"discoveryStateChangeCallback", "(I)V",          &method_discoveryStateChangeCallback},
    {"deviceFoundCallback",          "([B)V",         &method_deviceFoundCallback},
    {"pinRequestCallback",           "([B[BIZ)V",     &method_pinRequestCallback},
    {"sspRequestCallback",           "([BII)V",       &method_sspRequestCallback},
    {"bondStateChangeCallback",      "(I[BII)V",      &method_bondStateChangeCallback},
    {"aclStateChangeCallback",       "(I[BIIIII)V",   &method_aclStateChangeCallback},
    // ……更多
};
GET_JAVA_METHODS(env, "com/android/bluetooth/btservice/JniCallbacks", javaMethods);
```

**展开后大致等价于**：

```cpp
jclass cb = env->FindClass("com/android/bluetooth/btservice/JniCallbacks");
for (auto& m : javaMethods) {
    *m.idVar = env->GetMethodID(cb, m.name, m.signature);
}
env->DeleteLocalRef(cb);
```

之后异步事件回来时，C 端就能：

```cpp
env->CallVoidMethod(sJniCallbacksObj, method_deviceFoundCallback, jByteAddr);
```

## 9. Java 端的"接住面"：`JniCallbacks.java`

Java 端有一个专门的类 `android/app/src/com/android/bluetooth/btservice/JniCallbacks.java`，里面**全是被 C 端调的方法**：

```java
// 节选示意
package com.android.bluetooth.btservice;

public class JniCallbacks {
    void stateChangeCallback(int newState) { ... }
    void adapterPropertyChangedCallback(int[] types, byte[][] values) { ... }
    void discoveryStateChangeCallback(int state) { ... }
    void deviceFoundCallback(byte[] address) { ... }
    void pinRequestCallback(byte[] address, byte[] name, int cod, boolean min16Digit) { ... }
    void sspRequestCallback(byte[] address, int pairingVariant, int passkey) { ... }
    void bondStateChangeCallback(int status, byte[] address, int newState, int hciReason) { ... }
    void aclStateChangeCallback(int status, byte[] address, int newState, int transport,
                                int hciReason, int connectionHandle, int aclQueueDepth) { ... }
    // ……
}
```

`AdapterService` 会创建一个 `JniCallbacks` 实例并交给 `AdapterNativeInterface`，C 端的 `sJniCallbacksField` 持有它的引用，回调时通过该实例派发。

## 11. C++ 与 Java 概念对照

| C++（JNI） | Java 类比 |
|-----------|---------|
| `JNINativeMethod` | 函数指针表项 ≈ Java `Map<String, Method>` 一项 |
| `RegisterNatives` | `class.getMethod(name, paramTypes)` 的反向操作 |
| `jmethodID` | `java.lang.reflect.Method` 的轻量句柄 |
| `JNIEnv->CallVoidMethod(obj, id, args...)` | `method.invoke(obj, args)` |
| `NewGlobalRef` | "把局部引用 promote 成进程级全局引用"（避免被 GC） |
| `DeleteLocalRef` | 让 ART 提前回收局部引用，避免引用表满 |

## 12. 调试方法

| 想看 | 方法 |
|------|------|
| 注册是否成功 | `JNI_OnLoad` 之后没有抛 `UnsatisfiedLinkError` 就成功 |
| 方法名拼错 | logcat 报 `No implementation found for ...` |
| 签名拼错 | logcat 报 `JNI ERROR: incompatible JNI signature` 或调用直接 SIGSEGV |
| 找出 Java/C 端不匹配 | `javap -s -p AdapterNativeInterface.class` 看 Java 端签名，与 C 数组对照 |
| 注册到的是哪个 ClassLoader 的 class | `env->FindClass` 会用蓝牙 App 的 ClassLoader，所以不会拿错 |

## 13. FAQ

**Q1：为什么不用 C 命名法（`Java_com_android_bluetooth_btservice_AdapterNativeInterface_enableNative`）自动绑定？**
A：动态注册更可控，无需暴露符号，避免 `extern "C"` 强约束，便于"按需注册"和切换实现。

**Q2：注册顺序重要吗？**
A：注册顺序不重要，但**类型签名必须精确匹配**。多一个少一个参数都会失败。

**Q3：`jbyteArray` 怎么转 `std::vector<uint8_t>`？**
A：典型写法：
```cpp
jbyte* buf = env->GetByteArrayElements(addr, nullptr);
jsize len = env->GetArrayLength(addr);
std::vector<uint8_t> v(buf, buf + len);
env->ReleaseByteArrayElements(addr, buf, JNI_ABORT);  // JNI_ABORT 表示不写回
```

**Q4：注册时 `methods[]` 用 `static const` 还是局部数组？**
A：本仓多用局部 `const JNINativeMethod methods[]` —— RegisterNatives 只在调用时读取，调用完即不需要保留，所以局部数组也安全。

**Q5：能不能在运行时再次 `RegisterNatives` 覆盖已注册的？**
A：理论可以，蓝牙模块没必要这么做。Profile 启用/停用走 Java 层 Config，不动 JNI 映射。

## 15. 本节小结（速记卡）

```
JNI 注册三件套：
  ① Java 端  private native xxxNative(...)
  ② C 端    static jXxx xxxNative(JNIEnv*, jobject, ...)
  ③ 数组    {"xxxNative", "签名", &xxxNative}
注册宏：REGISTER_NATIVE_METHODS(env, "com/android/.../XxxNativeInterface", methods)
反向回拨：GET_JAVA_METHODS(env, "com/android/.../JniCallbacks", javaMethods)
签名速记：(参数...)返回   Z=bool I=int J=long [B=byte[] Ljava/lang/String;=String
错漏后果：UnsatisfiedLinkError / SIGSEGV
```
