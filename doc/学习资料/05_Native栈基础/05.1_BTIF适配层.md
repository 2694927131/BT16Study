# 05.1 BTIF 适配层

> 速通摘要：BTIF（Bluetooth Interface）= **JNI ↔ BTA/Stack 之间的"路由器"**。它对上提供 C 函数表 `bt_interface_t`（被 JNI 调）；对下编排各 Profile + 调 BTA + Callout（线程/Audio HAL）。每个 Profile 在 `system/btif/src/btif_<profile>.cc` 各有一个文件，全部都按"Java 调 BTIF → BTIF 调 BTA → BTA 调 Stack"的固定路径流转。

源码总入口：`system/btif/src/bluetooth.cc`（`bt_interface_t` 实现）+ `system/btif/src/stack_manager.cc`（栈启动）。

## 4. `bt_interface_t` 全局函数表

`system/btif/src/bluetooth.cc` 定义一个全局变量：

```cpp
EXPORT_SYMBOL bt_interface_t bluetoothInterface = {
    sizeof(bluetoothInterface),
    .init = init,
    .enable = enable,
    .disable = disable,
    .cleanup = cleanup,
    .start_discovery = btif_dm_start_discovery,
    .cancel_discovery = btif_dm_cancel_discovery,
    .create_bond = createBond,
    .create_bond_le = createBondLe,
    .remove_bond = removeBond,
    .cancel_bond = cancelBond,
    .pin_reply = pinReply,
    .ssp_reply = sspReply,
    .get_profile_interface = getProfileInterface,    // ★ 取各 Profile 函数表
    .dump = dump,
    .set_os_callouts = set_os_callouts,
    .set_dynamic_audio_buffer_size = ...,
    // ……更多函数
};
```

JNI `JNI_OnLoad` 时调 `hal_util_load_bt_library` 拿到这个表的指针，赋值给 `sBluetoothInterface`（参考 04.1 §8）。

## 5. `get_profile_interface` 是关键

要做 A2DP 操作，不直接调 `bluetoothInterface`，而是：

```cpp
const bt_av_interface_t* avi =
    (const bt_av_interface_t*)bluetoothInterface.get_profile_interface(BT_PROFILE_ADVANCED_AUDIO_ID);
avi->init(callbacks, max_connected_audio_devices, ...);
avi->connect_src(bd_addr);
```

Profile ID 常量：
- `BT_PROFILE_ADVANCED_AUDIO_ID` = "a2dp"
- `BT_PROFILE_ADVANCED_AUDIO_SINK_ID` = "a2dp_sink"
- `BT_PROFILE_HANDSFREE_ID` = "handsfree"
- `BT_PROFILE_HANDSFREE_CLIENT_ID` = "handsfree_client"
- `BT_PROFILE_GATT_ID` = "gatt"
- `BT_PROFILE_HIDHOST_ID` = "hidhost"
- ……

每个 Profile 都有自己的 `bt_xxx_interface_t` 函数表。

## 7. 简化代码片段：`btif_dm_create_bond`

```cpp
// system/btif/src/btif_dm.cc:2774
void btif_dm_create_bond(const RawAddress bd_addr, tBT_TRANSPORT transport) {
  log::verbose("bd_addr={}, transport={}", bd_addr, transport);
  BTM_LogHistory(kBtmLogTag, bd_addr, "Create bond",
                 std::format("transport:{}", bt_transport_text(transport)));
  btif_stats_add_bond_event(bd_addr, BTIF_DM_FUNC_CREATE_BOND, pairing_cb.state);
  pairing_cb.timeout_retries = NUM_TIMEOUT_RETRIES;
  btif_dm_cb_create_bond(bd_addr, transport);
}
```

注意 BTIF 的两个典型动作：
1. `log::verbose / BTM_LogHistory` 记日志。
2. 调内部 `btif_dm_cb_create_bond` 通过 `do_in_main_thread` 投递到 main_thread 再调 BTA。

## 8. BTIF 线程模型

```mermaid
flowchart TD
    JNI[JNI 调用线程<br/>(Binder 线程)]
    Main[btif main_thread]
    Hci[HCI/GD 线程]
    AudioSrc[A2DP Source 线程<br/>(btif_a2dp_source)]
    AudioSnk[A2DP Sink 线程]

    JNI -->|do_in_main_thread / async post| Main
    Main -->|BTA API| Bta[BTA 状态机]
    Bta -->|Stack API| Stack
    Stack -->|HCI 写| Hci
    Hci -.事件.-> Stack -.-> Bta -.-> Main
    Main -.回调.-> JNI

    Main --> AudioSrc
    AudioSrc -.编码送数据.-> Hci
```

- **main_thread**：BTA/BTIF/Stack 共享的事件循环。绝大多数 BTIF 函数会"立即 post 到 main_thread"再处理。
- **profile 线程**：A2DP 编解码线程、SCO 线程等独立运转。
- **Binder/JNI 线程**：从 Java 进来——通常调用 `do_in_main_thread` 后立即返回。

## 11. FAQ

**Q1：为什么 BTIF 不是 OOP 而是 C-style 函数表？**
A：历史原因 + 跨语言 ABI 稳定（JNI 端调用方便）。新代码（如 GD）转 C++ 类。

**Q2：BTIF 与 BTA 边界在哪？**
A：BTIF 偏"业务编排 + Java/Native 对接"；BTA 偏"业务状态机 + 与 Stack 协议交互"。简单一句：**BTIF 翻译 + 编排，BTA 做生意**。

**Q3：`do_in_main_thread` 是什么？**
A：把 `std::function` 投递到 main_thread 执行。所有 BTIF/BTA 业务必须在 main_thread 跑（避免多线程数据竞争）。

**Q4：BTIF 同步还是异步？**
A：上层 API 多数立即返回（同步），内部异步执行业务。错误大多以 callback 形式回。

**Q5：能否绕过 BTIF 直接调 BTA？**
A：技术可以（同 SO），但**强烈不建议**——BTIF 维护一致性约束、log history、metrics、线程纪律。

```
BTIF = JNI↔BTA 适配层
位置：system/btif/
入口：bluetoothInterface (bt_interface_t)
关键文件：
  bluetooth.cc        总接口
```
