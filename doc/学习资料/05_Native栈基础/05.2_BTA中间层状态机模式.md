# 05.2 BTA 中间层：状态机模式与目录组织

> 速通摘要：BTA（Bluetooth Application）= **业务状态机层**。每个 Profile 在 `system/bta/<profile>/` 一个子目录，主体由 `<profile>_main.cc`（状态机调度）+ `<profile>_act.cc`（状态动作）+ `<profile>_api.cc`（对外 API）+ `<profile>_int.h`（内部类型）+ 若干辅助文件组成。**记住"main 调度，act 干活，api 接外"，所有 Profile BTA 都是这套**。

源码：`system/bta/`

## 5. BTA 文件命名 5 件套

以 `system/bta/dm/` 为例：

| 文件 | 角色 |
|------|------|
| `bta_dm_main.cc` | 主状态机调度（事件 → 动作分发） |
| `bta_dm_act.cc` | 状态动作（"当事件 X 在状态 Y 发生，做……"） |
| `bta_dm_api.cc` | 对外 API（被 BTIF 调） |
| `bta_dm_int.h` | 内部类型与函数声明 |
| `bta_dm_cfg.cc` | 默认配置（连接参数、扫描参数） |
| `bta_dm_device_search.cc` | 子模块（设备搜索） |
| `bta_dm_disc.cc` | 子模块（disc） |
| `bta_dm_gatt_client.cc` | 子模块（DM 内的 GATT 用法） |
| ……更多 | 拆分以保持单文件 < 2000 行 |

类似的，`system/bta/av/`、`system/bta/ag/`、`system/bta/gatt/` 都是这套命名。

## 6. BTA 状态机模式（以 BTA AV 为例）

```cpp
// 思路图：BTA AV 状态机
typedef enum {
    BTA_AV_INIT_ST,          // 初始
    BTA_AV_OPENING_ST,       // 连接中
    BTA_AV_OPEN_ST,          // 已连接
    BTA_AV_RCFG_ST,          // 重新配置
    BTA_AV_CLOSING_ST,       // 关闭中
} tBTA_AV_STATE;

typedef enum {
    BTA_AV_API_OPEN_EVT,
    BTA_AV_API_CLOSE_EVT,
    BTA_AV_API_START_EVT,
    BTA_AV_API_STOP_EVT,
    BTA_AV_AVDT_CONNECT_EVT,
    // ……
} tBTA_AV_EVT;

// 状态机查表
static const tBTA_AV_SACT bta_av_st_init[][BTA_AV_NUM_ACTIONS] = {
    /* INIT state */
    /* API_OPEN_EVT      */ { BTA_AV_DO_OPEN, ... },
    /* AVDT_CONNECT_EVT  */ { BTA_AV_INCOMING_OPEN, ... },
};

// 调度：在 main 函数里查表 + 执行动作
void bta_av_sm_execute(tBTA_AV_SCB* p_scb, tBTA_AV_EVT event, tBTA_AV_DATA* p_data) {
    uint8_t* p_action = bta_av_st_<current_state>[event];
    while (*p_action != BTA_AV_IGNORE) {
        (*bta_av_action[*p_action])(p_scb, p_data);
        p_action++;
    }
    p_scb->state = next_state[current_state][event];
}
```

实现细节：见 `system/bta/av/bta_av_main.cc`、`bta_av_act.cc`、`bta_av_aact.cc`、`bta_av_ssm.cc`（state-stream machine）。

**关键设计**：BTA 状态机 = "查表式 SM"，事件 + 状态查出动作序列依次执行。优点是简单可控，缺点是新加事件要改表。

## 7. BTA 公共调度 `bta_sys`

`system/bta/sys/bta_sys_main.cc` 维护一个全局事件循环 / 模块表：

- 各 Profile 在初始化时注册一个 `tBTA_SYS_REG`：包含 `evt_hdlr`（事件处理器）+ `disable`。
- 来自外界（BTIF）的事件投递到 `bta_sys_sendmsg`，由它找到对应模块的 `evt_hdlr` 派发。
- 在 main_thread 上运行（避免多线程竞争）。

## 8. 简化代码片段：BTA DM 状态机入口

```cpp
// system/bta/dm/bta_dm_api.cc:81
void BTA_DmSearch(tBTA_DM_SEARCH_CBACK* p_cback) {
    bta_dm_disc_start_device_discovery(p_cback);
}

// system/bta/dm/bta_dm_device_search.cc
void bta_dm_disc_start_device_discovery(tBTA_DM_SEARCH_CBACK* cback) {
    bta_dm_search_cb.p_search_cback = cback;
    // 投递事件到状态机
    if (do_in_main_thread(base::BindOnce(&bta_dm_search_sm_execute,
                                         BTA_DM_API_SEARCH_EVT,
                                         /*data*/)) != BT_STATUS_SUCCESS) {
        // 错误处理
    }
}

// 状态机分发
static void bta_dm_search_sm_execute(tBTA_DM_DEV_SEARCH_EVT event,
                                     std::unique_ptr<tBTA_DM_MSG> msg) {
    auto current = bta_dm_search_get_state();
    auto action = state_table[current][event];
    action(std::move(msg));
    bta_dm_search_set_state(next_state_table[current][event]);
}
```

## 11. FAQ

**Q1：BTA 为什么不直接合并到 Stack？**
A：分层好处：Stack 仅做协议，BTA 做"业务状态机 + 状态间约束"。两者解耦让 Stack 可独立升级。

**Q2：BTA 与 BTIF 业务上有重叠？**
A：少量重叠（如 BTIF 也做一些状态管理），但层次清晰：BTIF 偏 "JNI 与栈之间的接口适配"，BTA 偏 "业务逻辑与状态机"。

**Q3：BTA 是否线程安全？**
A：BTA 假设在 main_thread 跑——非 main_thread 调 BTA API 会有竞争。所以 BTIF 用 `do_in_main_thread` post 事件。

**Q4：能不能写一个新 BTA 子模块？**
A：可以。参考 `bta_<profile>_*.cc` 五件套写。注意要在 `bta_sys_main.cc` 注册 / 在 build system 加进来。

**Q5：BTA 命名 `b_t_a_<...>` 这个前缀有规律吗？**
A：基本是 `BTA_<Profile>_<Action>`（公共 API） + `bta_<profile>_<helper>`（内部）。配套常量 `tBTA_<PROFILE>_<...>`。


```
位置：system/bta/<profile>/
文件五件套（如 dm/）：
  bta_<x>_main.cc   状态机调度
  bta_<x>_act.cc    状态动作
```
