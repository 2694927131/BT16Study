# 05.5 HCI 层：命令 / 事件 / ACL / SCO 通道

> 速通摘要：HCI（Host Controller Interface）= **Host 与蓝牙芯片之间的协议**。4 种 packet 类型：**Command**（Host→Controller）、**Event**（Controller→Host）、**ACL**（双向数据）、**SCO**（双向语音）。Host 端逻辑分两套：传统 `system/hci/` + 新 GD `system/gd/hci/`。HAL 进程负责把 packet 通过物理通道（UART/USB/SDIO）送到芯片。

## 3. HCI 四种 packet

| 类型 | 方向 | 头部首字节（H4） | 内容 |
|------|------|---------------|------|
| **Command** | Host→Controller | `0x01` | OpCode(2B) + ParamLength(1B) + Params |
| **Event** | Controller→Host | `0x04` | EventCode(1B) + ParamLength(1B) + Params |
| **ACL Data** | 双向 | `0x02` | HciHandle(12bit) + Flags(4bit) + Length(2B) + Data |
| **SCO Data** | 双向 | `0x03` | HciHandle(12bit) + Flags(2bit) + Length(1B) + Audio |
| **ISO Data** | 双向（BLE 5.2+） | `0x05` | 用于 LE Audio CIS/BIS |

H4 是常用的 HCI Transport，首字节标示类型。其他 transport（H5、SDIO 等）有不同前缀。

---

## 4. 常用 HCI Command（OpCode 速查）

OpCode = OGF(6bit) + OCF(10bit)。

| OpCode | 名称 | 用途 |
|--------|------|------|
| `0x0c03` | HCI_Reset | 控制器复位 |
| `0x0c01` | HCI_Set_Event_Mask | 设置事件掩码 |
| `0x1003` | HCI_Read_Local_Supported_Features | 查特性 |
| `0x1009` | HCI_Read_BD_ADDR | 读本机蓝牙地址 |
| `0x0401` | HCI_Inquiry | Classic 扫描 |
| `0x0405` | HCI_Create_Connection | Classic ACL |
| `0x0406` | HCI_Disconnect | 断开 |
| `0x0428` | HCI_Setup_Synchronous_Connection | SCO |
| `0x200b` | HCI_LE_Set_Scan_Parameters | BLE 扫描参数 |
| `0x200c` | HCI_LE_Set_Scan_Enable | 启/停 BLE 扫描 |
| `0x200d` | HCI_LE_Create_Connection | BLE 连接 |
| `0x2042` | HCI_LE_Set_Extended_Scan_Parameters | BLE 5+ |
| `0x2043` | HCI_LE_Set_Extended_Scan_Enable | BLE 5+ |
| `0x2031` | HCI_LE_Set_Default_PHY | 默认 PHY |
| `0x2014` | HCI_LE_Read_Local_Supported_Features | LE 特性 |

完整表见 Bluetooth Core Spec [Vol 4]。本仓 `system/stack/hcic/hcicmds.cc` / `hciblecmds.cc` 是构造端。

## 5. 常用 HCI Event

| Code | 名称 |
|------|------|
| `0x05` | Disconnection_Complete |
| `0x0e` | Command_Complete |
| `0x0f` | Command_Status |
| `0x13` | Number_Of_Completed_Packets |
| `0x3e` | LE Meta Event（容器，子事件如下） |

LE Meta Event 子事件（`Sub_Event_Code`）：
| Sub | 名称 |
|-----|------|
| `0x01` | LE_Connection_Complete |
| `0x02` | LE_Advertising_Report |
| `0x03` | LE_Connection_Update_Complete |
| `0x0a` | LE_Enhanced_Connection_Complete |
| `0x0d` | LE_Extended_Advertising_Report |

## 6. HCI 处理流程（GD HciLayer）

```mermaid
flowchart LR
    subgraph BTA["BTA / 旧 Stack"]
        Cmd[发命令请求]
    end
    subgraph GD["GD HciLayer"]
        Q[Command Queue<br/>(per-OpCode 限流)]
        Send[Send to HAL]
        Recv[Receive from HAL]
        Disp[Event Dispatcher]
    end
    subgraph HAL["HAL 进程"]
        H[HCI Hal Service]
    end
    subgraph Chip["蓝牙芯片"]
        C[Controller]
    end

    Cmd --> Q --> Send --> H
    H <--> C
    H --> Recv --> Disp
    Disp -->|Command_Complete| BTA
    Disp -->|Event| BTA
```

**Command Queue 关键作用**：
- 限制"未完成"的 HCI Command 数量（HCI 流控）。
- 收到 `Command_Complete` / `Command_Status` 才发下一个。
- 防止主机连发命令把控制器队列冲爆。

## 7. ACL / SCO 流控

### 7.1 ACL
- 控制器在启动时 `HCI_Read_Buffer_Size` 报告 ACL buffer 数。
- Host 维护 "未确认 ACL packet 计数"，不能超过 buffer 数。
- 控制器发 `Number_Of_Completed_Packets` 告诉 Host 已发出 N 个 → Host 减计数。

### 7.2 SCO
- 类似但 buffer 通常小（如 8 个）。
- mSBC over SCO 需要严格时序：每 7.5 ms / 60 字节 mSBC frame。

## 9. 简化代码片段：发一条 HCI Command

```cpp
// 传统 Stack（system/stack/hcic/）：
void btsnd_hcic_inquiry(const LAP inq_lap, uint8_t duration,
                        uint8_t response_cnt) {
    BT_HDR* p_buf = (BT_HDR*)osi_malloc(HCI_CMD_BUF_SIZE);
    p_buf->offset = 0;
    p_buf->layer_specific = 0;
    p_buf->len = ...;
    uint8_t* p = (uint8_t*)(p_buf + 1);
    UINT16_TO_STREAM(p, HCI_INQUIRY);   // OpCode 0x0401
    UINT8_TO_STREAM(p, HCIC_PARAM_SIZE_INQUIRY);
    LAP_TO_STREAM(p, inq_lap);
    UINT8_TO_STREAM(p, duration);
    UINT8_TO_STREAM(p, response_cnt);
    btm_acl_send_cmd(p_buf);   // 进入 shim → GD HciLayer
}
```

GD 端用 PDL 生成的 `HciInquiryPacket::Create(lap, duration, response_cnt)` 也能构造同样字节流。

## 12. FAQ

**Q1：H4 / H5 区别？**
A：H4 是基础（多用于 UART），H5 加 sliding window + 重传（高速 UART）。Android 用 H4 + HAL 实现重传。

**Q2：Command 一直没回 Command_Complete？**
A：① 控制器死锁 ② HCI 流控满 ③ 物理通道断（UART idle）。先看 HAL 进程是否还活。

**Q3：可以并发多条 Command 吗？**
A：可以，但受 HCI Command Queue 限制（通常 1）。GD HciLayer 自动排队。

**Q4：SCO 数据用 HCI 还是直接走 PCM？**
A：取决于硬件。Audio HAL Offload 路径：芯片 ↔ Audio HAL 之间走 PCM 物理线；Software 路径：芯片 ↔ Host 走 HCI SCO 包。

**Q5：BLE 5 ISO Data 怎么处理？**
A：新 packet type（0x05）；本仓在 GD 中处理（`system/gd/hci/`）。

## 14. 本节小结（速记卡）

```
HCI = Host ↔ Controller 接口
四类 packet：Command(0x01) / Event(0x04) / ACL(0x02) / SCO(0x03)（+ ISO(0x05) LE Audio）
OpCode = OGF(6bit) + OCF(10bit)
关键命令：Reset(0x0c03) / Inquiry(0x0401) / Create_Connection(0x0405)
        LE_Set_Scan(0x200b/0x200c) / LE_Create_Connection(0x200d)
        Setup_Synchronous_Connection(0x0428)
关键事件：Command_Complete(0x0e) / Number_Of_Completed_Packets(0x13)
        LE Meta Event(0x3e) + 子事件
处理流程：BTA → shim → GD HciLayer (Command Queue) → HAL → 芯片
流控：HCI Number_Of_Completed_Packets 决定 host 何时可发下一包
Vendor：OGF=0x3F 私有命令，BluetoothHciVendorSpecific* 系列
```
