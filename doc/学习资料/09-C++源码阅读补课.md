# 09. C++ 源码阅读补课：从 Android 蓝牙 Native 代码学常见模式

## 1. 学习目标

Android 蓝牙 Native 栈里 C 和 C++ 混用明显：BTIF/BTA/Stack 既有传统 C 风格结构体和回调，也有 `std::unique_ptr`、`std::optional`、`std::variant`、`base::BindOnce`、线程投递等现代 C++ 写法。本章不单独讲语法书，而是把语法绑定到仓库里的真实源码。

读完本章后，你应该能看懂：

- `do_in_main_thread` / `do_in_jni_thread` 为什么会改变执行线程。
- `base::BindOnce`、`base::Bind`、`std::move` 在异步调用里的作用。
- `std::unique_ptr`、`std::shared_ptr`、`std::optional`、`std::variant` 在蓝牙代码中的使用场景。
- 看到接口表、回调表、状态机时如何快速定位调用方向。

## 2. 先认三类代码风格

| 风格 | 常见目录 | 阅读重点 |
| --- | --- | --- |
| C 风格协议栈 | `system/stack`、部分 `system/bta` | 全局控制块、结构体、函数指针、事件码 |
| C++ 适配层 | `system/btif/src` | 接口表、线程投递、回调到 JNI |
| 新模块/LE Audio/GD | `system/gd`、`system/bta/le_audio` | 智能指针、optional、variant、类封装 |

不要一上来追所有模板类型。先判断“这是入口函数、回调函数、接口表成员，还是异步任务”。

## 3. 线程投递：do_in_main_thread

`do_in_main_thread` 是 Native 阅读的核心入口之一。很多 Java/JNI 过来的动作不会在当前线程直接执行，而是投递到 BT main thread。

```cpp
// system/stack/btu/main_thread.cc
39 bt_status_t do_in_main_thread(base::OnceClosure task) {
40   if (!main_thread.DoInThread(std::move(task))) {
47 bt_status_t do_in_main_thread_delayed(base::OnceClosure task, std::chrono::microseconds delay) {
48   if (!main_thread.DoInThreadDelayed(std::move(task), delay)) {
```

例如启动栈和关闭栈：

```cpp
// system/btif/src/stack_manager.cc
139   event_init_stack(std::move(promise), interface);
157   event_clean_up_stack(std::move(promise), stopProfiles);
293   do_in_jni_thread(base::BindOnce(event_signal_stack_up, nullptr));
308   do_in_main_thread(base::BindOnce(&btm_ble_scanner_cleanup));
313   do_in_main_thread(base::BindOnce(bta_dm_disable));
341   do_in_jni_thread(base::BindOnce(event_signal_stack_down, nullptr));
```

阅读技巧：

- 看到 `do_in_main_thread(...)`，下一步要跳到括号里的函数。
- 看到 `do_in_jni_thread(...)`，说明它准备回 JNI/Java 侧发回调。
- `BindOnce` 通常表示任务只能执行一次，常与 `std::move` 搭配。

## 4. std::move：不是复制，是转移所有权或转移可调用对象

蓝牙代码里 `std::move` 经常用于异步回调和 buffer。

```cpp
// system/stack/arbiter/acl_arbiter.cc
69     return arbiter_->InterceptPacket(tcb_idx, std::move(vec));
133   do_in_main_thread(base::BindOnce(&AclArbiter::SendPacketToPeer, base::Unretained(&GetArbiter()),
134                                    tcb_idx, std::move(buffer)));
```

这里的重点不是背诵“左值右值”，而是理解：`buffer` 被交给异步任务后，当前作用域不应再依赖它的内容。

HCI 命令回调也常这样写：

```cpp
// system/stack/hcic/hciblecmds.cc
391   btu_hcif_send_cmd_with_cb(HCI_LE_SET_CIG_PARAMS, param, params_len, std::move(cb));
407   btu_hcif_send_cmd_with_cb(HCI_LE_CREATE_CIS, param, params_len, std::move(cb));
```

## 5. unique_ptr：唯一所有权

`std::unique_ptr` 表示这块对象只能有一个拥有者。Socket/L2CAP 配置里很常见。

```cpp
// system/btif/src/btif_sock_l2cap.cc
883   std::unique_ptr<tL2CAP_CFG_INFO> cfg = std::make_unique<tL2CAP_CFG_INFO>(
893   std::unique_ptr<tL2CAP_ERTM_INFO> ertm_info;
898   BTA_JvL2capStartServer(connection_type, sock->security, std::move(ertm_info), sock->channel,
899                          sock->rx_mtu, std::move(cfg), btsock_l2cap_cbk, sock->id);
996     std::unique_ptr<tL2CAP_CFG_INFO> cfg = std::make_unique<tL2CAP_CFG_INFO>(
1011    BTA_JvL2capConnect(connection_type, sock->security, std::move(ertm_info), channel, sock->rx_mtu,
```

读法：

- `make_unique`：创建对象。
- `std::move(unique_ptr)`：把所有权交出去。
- 交出去之后原指针通常就不能再当作有效对象使用。

## 6. shared_ptr：共享数据

GATT database hash 计算里可以看到 `shared_ptr`。

```cpp
// system/stack/gatt/gatt_sr_hash.cc
33         std::shared_ptr<std::list<tGATT_SRV_LIST_ELEM>> lst_ptr) {
66 static void fill_database_info(std::shared_ptr<std::list<tGATT_SRV_LIST_ELEM>> lst_ptr,
120 Octet16 gatts_calculate_database_hash(std::shared_ptr<std::list<tGATT_SRV_LIST_ELEM>> lst_ptr) {
```

它表达“多个函数/对象可以共享同一份服务列表”。阅读时要注意共享对象是否可能被异步修改。

## 7. optional：值可能不存在

`std::optional` 常用于能力、配置、解析结果。A2DP codec 解析就是一个好例子。

```cpp
// system/stack/a2dp/a2dp_codec_config.cc
67 std::optional<CodecId> ParseCodecId(uint8_t const media_codec_capabilities[]) {
```

GATT API 里也有 feature flag 风格的 optional：

```cpp
// system/stack/gatt/gatt_api.cc
1667 std::optional<bool> OVERRIDE_GATT_LOAD_BONDED = std::nullopt;
```

读法：

- `std::nullopt`：当前没有值。
- 使用前通常要判断 `has_value()` 或直接在条件里判断。
- optional 不是错误码，它表达“不一定存在”。

## 8. variant：一个变量可表示多种类型

Volume Control 里同一个接口既可以按设备地址操作，也可以按 group id 操作。

```cpp
// system/bta/vc/vc.cc
1187  void MuteUnmute(std::variant<RawAddress, int> addr_or_group_id, bool mute) {
1276  void Mute(std::variant<RawAddress, int> addr_or_group_id) override {
1281  void UnMute(std::variant<RawAddress, int> addr_or_group_id) override {
1286  void SetVolume(std::variant<RawAddress, int> addr_or_group_id, uint8_t volume) override {
```

BTIF 对应封装：

```cpp
// system/btif/src/btif_vc.cc
177   void SetVolume(std::variant<RawAddress, int> addr_or_group_id, uint8_t volume) override {
185     do_in_main_thread(Bind(&VolumeControl::SetVolume, Unretained(VolumeControl::Get()),
186                            std::move(addr_or_group_id), volume));
```

读法：看到 `variant<RawAddress, int>`，先问当前调用传的是“单设备”还是“组”。

## 9. 接口表与回调表

Android 蓝牙 JNI 到 BTIF 常通过接口表。GATT Client 是典型例子：

```cpp
// system/btif/src/btif_gatt_client.cc
857 const btgatt_client_interface_t btgattClientInterface = {
860         btif_gattc_open,
```

JNI 注册表也类似：

```cpp
// android/app/jni/com_android_bluetooth_gatt.cpp
2007 static int register_com_android_bluetooth_gatt_(JNIEnv* env) {
2016          {"gattClientConnectNative", "(ILjava/lang/String;IZIZIIZ)V",
2027          {"gattClientReadCharacteristicNative", "(III)V",
2032          {"gattClientWriteCharacteristicNative", "(IIII[B)V",
```

阅读接口表的技巧：

1. 先找表名，例如 `btgattClientInterface`。
2. 再找 Java/JNI 调用的是表中哪个函数。
3. 然后跳到该函数实现。
4. 如果函数里投递线程，再跳到投递的目标函数。

## 10. 建议练习

1. 用 `rg -n "do_in_main_thread" system/btif/src system/stack` 找 10 个投递点，写下它们投递到哪个函数。
2. 用 `rg -n "std::optional" system` 找一个配置类 optional，判断它的“没有值”代表什么。
3. 从 `btgattClientInterface` 开始追 `open/read/write` 三个函数，画出接口表到 BTA 的链路。
