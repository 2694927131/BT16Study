# 09.1 HiCar 中蓝牙的角色与可定位点

> 速通摘要：**HiCar** = 华为推出的"手机 ↔ 车机"互联方案。主数据走 **Wi-Fi P2P / Wi-Fi Direct**；蓝牙在其中扮演**配对触发 + 信令辅助 + Profile 共存**角色。本节理清"HiCar 用蓝牙做了什么"以及在 AOSP 本仓中可定位的钩子点。**注意**：HiCar 完整实现属外部依赖（华为车机 ROM），本仓只能定位通用蓝牙能力。

## 3. HiCar 在蓝牙层做的 3 件事

### 3.1 配对触发 + 设备识别
- 用户手机靠近车机 → 通过 **BLE 广告**或 **NFC tap**触发关联流程。
- 车机扫到含 HiCar 厂商 ID 的 BLE 广告 → 弹窗"是否连接 HiCar"。
- 用户确认 → 双方走标准 BLE 配对（SMP）+ HiCar 业务层认证。

### 3.2 RFCOMM 控制信道
- HiCar 通常在 Classic 蓝牙上注册一个 **RFCOMM 服务**（自有 UUID）。
- 控制信令（如"切到投屏"）通过这个 RFCOMM 通道走。
- 主数据流（视频、音频）走 Wi-Fi P2P。

### 3.3 蓝牙 Profile 共存
- HFP 通话照常用蓝牙。
- 蓝牙音乐（A2DP）可能被 HiCar 强制走车机音频（不再用 A2DP，而是 Wi-Fi 数据流）。
- 这里就是车机/手机两边"路由"决策的关键。

## 4. 在本仓的可定位点

虽然 HiCar 实现不在本仓，但有几个**通用钩子**可被车厂 HiCar 服务复用：

| 钩子点 | 用途 |
|--------|------|
| `BluetoothDevice.createRfcommSocketToServiceRecord(UUID)` | HiCar 自定义 RFCOMM UUID |
| `BluetoothAdapter.listenUsingRfcommWithServiceRecord(name, UUID)` | 车机做 RFCOMM server |
| `BluetoothLeScanner` 配合 `ScanFilter.setManufacturerData(...)` | 按华为厂商 ID 过滤 BLE 广告 |
| `BluetoothLeAdvertiser.startAdvertising` + Manufacturer Data | 车机反向广告 |
| `BluetoothA2dp.setActiveDevice(null)` | 让 A2DP 让位给 Wi-Fi 投屏音频 |
| `BluetoothHeadsetClient.connect/disconnect` | 通话切换 |
| `system/conf/interop_database.conf` | 把 HiCar 设备做特殊处理 |
| Vendor HCI（`OGF=0x3F`） | 华为芯片定制命令 |

## 7. FAQ

**Q1：HiCar 是不是完全不用蓝牙？**
A：不是。蓝牙在配对触发 + 信令辅助 + Profile 共存中仍重要。

**Q2：HiCar 让 A2DP 出问题？**
A：常见现象——HiCar 启动后把音乐路由从 A2DP 切到 Wi-Fi 投屏的音频，A2DP 进 PAUSED。用户感觉"蓝牙音乐坏了"，其实是路由切换。

**Q3：本仓能改 HiCar 行为吗？**
A：不能。HiCar Service 在车厂 ROM 外部仓库。本仓只是提供通用能力。

**Q4：如何 disable HiCar 让车机用普通蓝牙？**
A：车机 HMI 一般有 HiCar 总开关。开关关闭后回退到标准 A2DP/HFP/AVRCP。

**Q5：HiCar 的"无感连接"是怎么做的？**
A：BLE Adv（手机持续广播）+ 车机后台扫 + 自动握手。蓝牙层就是 `BluetoothLeScanner` 的低占空比扫描 + `autoConnect=true` GATT 连接。
