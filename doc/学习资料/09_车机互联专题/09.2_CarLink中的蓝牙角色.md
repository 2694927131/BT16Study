# 09.2 CarLink 中蓝牙的角色与可定位点

> 速通摘要：**CarLink** = 百度推出的"手机 ↔ 车机"互联方案，类似 HiCar / CarPlay 的国产替代。主数据走 **Wi-Fi**；蓝牙做配对触发 + 信令。本仓只能定位通用钩子，完整 CarLink 实现属外部依赖。

---

## 1. 学习目标

读完本节，你应该能：

1. 说出 CarLink 在蓝牙层用到的能力。
2. 与 HiCar 对照看："互联方案"在蓝牙层都长一个样。
3. 知道车机定制 CarLink 时哪些蓝牙 API 是必走的。

---

## 2. 外部依赖声明

CarLink 协议、车机 CarLink Service、百度手机端 SDK 都**不在本仓**。本节仅基于公开资料 + 蓝牙逻辑做推断。

---

## 3. CarLink 在蓝牙层做什么

| 阶段 | 蓝牙的角色 |
|------|----------|
| 发现 | 手机 BLE 广告 + 车机扫描 |
| 配对 | 标准 SMP + 业务层认证（百度 ID） |
| 连接控制 | RFCOMM 控制信道 |
| 音频/电话 | 标准 HFP / A2DP（必要时 CarLink 用 Wi-Fi 替代 A2DP） |
| 数据投屏 | Wi-Fi P2P |
| 解绑 | 标准 removeBond + 业务层清理 |

---

## 4. 与 HiCar 对照

| 维度 | HiCar | CarLink |
|------|-------|--------|
| 厂商 | 华为 | 百度 |
| 主数据 | Wi-Fi P2P | Wi-Fi |
| BLE 触发 | Manufacturer Data (0x0BD9 华为) | Manufacturer Data (百度 ID) |
| RFCOMM | 自定义 UUID | 自定义 UUID |
| 通话 | 标准 HFP | 标准 HFP |
| 音乐 | A2DP 或投屏 | A2DP 或投屏 |

**蓝牙层路径几乎一致**——只差厂商 ID 和 UUID。

---

## 5. 本仓可定位点

参考 09.1 §4 表。CarLink 用同一套 AOSP 蓝牙 API：

- `BluetoothLeScanner` + `ScanFilter`（按 CarLink Manufacturer ID）
- RFCOMM Socket（自定义 UUID）
- BLE GATT（可选，做配对辅助）
- `interop_database.conf`（特殊设备处理）

## 8. FAQ

**Q1：CarLink 与 HiCar 能否同时连？**
A：物理上能（各自 RFCOMM + GATT），但通常车机 HMI 互斥（只一个互联方案 active）。

**Q2：能否在本仓代码里识别 CarLink 设备？**
A：通过 `interop_database.conf` 加白名单/黑名单条目（按 MAC 前缀），或自定义 vendor metadata。

**Q3：CarLink 影响蓝牙性能？**
A：扫描 + RFCOMM 数据流叠加，会让 A2DP 偶尔卡顿。建议把 LE Scan mode 调到 BALANCED 而非 LOW_LATENCY。

**Q4：本仓有 CarLink 显式支持吗？**
A：**没有**。CarLink 完全是车厂外加层，本仓零提及。

**Q5：CarLink BLE 广播能多频繁？**
A：典型 100-500 ms。手机 SDK 自决。
