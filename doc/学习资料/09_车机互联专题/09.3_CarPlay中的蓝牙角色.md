# 09.3 CarPlay 中蓝牙的角色（外部依赖说明）

> 速通摘要：**CarPlay** = Apple 推出的"iPhone ↔ 车机"互联方案。蓝牙在其中扮演**配对触发 + 控制信道 + HFP 通话**；主数据走 **Wi-Fi P2P**（无线 CarPlay）或 **USB**（有线 CarPlay）。本仓**完全没有 CarPlay 实现**——Apple 协议是闭源 + 严格授权，由 Apple MFi 认证芯片 + 车厂 SDK 处理。本节说清边界。

---

## 1. 学习目标

读完本节，你应该能：

1. 说清 CarPlay 在蓝牙层的功能定位。
2. 区分有线 CarPlay 与无线 CarPlay 对蓝牙的依赖度。
3. 明白本仓代码对 CarPlay 完全"中立"——iPhone 通过标准 BT Profile 与车机交互即可。

---

## 2. 外部依赖声明

CarPlay 是 Apple **闭源协议**，车机要做 CarPlay 必须：
1. 获得 Apple MFi 授权。
2. 集成 MFi 认证芯片（用于双向认证）。
3. 集成 Apple 提供的 CarPlay SDK（车厂 ROM 内）。

AOSP 本仓**完全没有** CarPlay 相关代码。

---

## 3. 无线 CarPlay 的握手序列

```
[iPhone] 蓝牙搜到车机
   ↓
用户点配对 → 标准 SSP 双向认证
   ↓
配对完成 → iPhone 通过蓝牙发现车机的 "_carplay" SDP record
   ↓
车机回 SDP record + IP-address-via-Bonjour-instructions
   ↓
iPhone 弹"是否启动无线 CarPlay" → 用户同意
   ↓
双方切到 Wi-Fi P2P → 5GHz CarPlay 数据流
   ↓
通话仍走标准 HFP（蓝牙 SCO）
```

---

## 4. 蓝牙在 CarPlay 中的具体能力

| 能力 | 蓝牙 Profile / 协议 | 本仓代码是否实现 |
|------|------------------|----------------|
| 配对 | Classic SSP | ✅（通用） |
| 设备发现（标识为 CarPlay） | SDP record（自定义 UUID `_carplay`） | ⚠️ SDP 框架可注册；具体 UUID 由车厂加 |
| 通话 | HFP HF | ✅（通用） |
| 通讯录 | PBAP Client | ✅（通用） |
| 短信 | MAP Client | ✅（通用） |
| 媒体控制 | AVRCP Controller | ✅（通用） |
| 投屏触发信令 | RFCOMM 私有 channel | ⚠️ 框架支持；UUID 闭源 |
| 主数据流（音视频） | **不走蓝牙**（Wi-Fi） | 与本仓无关 |

---

## 5. iPhone HFP 特殊点

iPhone 用 HFP 1.7+ 时会发一组 Apple-Specific AT 命令（`AT+XAPL`、`AT+IPHONEACCEV` 等）：
- `AT+XAPL=<vendorid-prodid-versions>` —— Apple 设备识别
- `AT+IPHONEACCEV=<battery_level>` —— iPhone 电量上报

车机要做"AVRCP/HFP for iPhone" 一致体验，必须正确响应这些命令。本仓 `VendorCommandResponseProcessor.java` 提供 hook 点。

## 7. FAQ

**Q1：本仓能改 CarPlay 行为吗？**
A：不能。Apple 协议闭源。

**Q2：车机不支持 CarPlay，iPhone 还能用普通蓝牙吗？**
A：完全可以。iPhone 走标准 HFP / A2DP / AVRCP / PBAP。CarPlay 只是"附加增值"。

**Q3：MFi 认证芯片是什么？**
A：Apple Authentication Coprocessor (MFi)。车机集成它后才能"被 Apple 识别"。本仓不涉及。

**Q4：CarPlay 无线时 A2DP 还能用吗？**
A：通常 iPhone 在无线 CarPlay 期间会把 A2DP "暂停"——音乐通过 Wi-Fi 路径走。

**Q5：本仓 `interop_database.conf` 对 iPhone 有特殊处理？**
A：有几条针对 iPhone 的兼容性条目（如绝对音量 quirk）。看具体文件。
