# 10.2 RAII、锁与并发（含 Java 对照）

> 速通摘要：C++ 用 RAII 把"锁、文件、内存"这类资源生命周期绑到对象上。`std::lock_guard<std::mutex> lock(m)` = "进入作用域上锁，出作用域解锁"——比 Java `synchronized` 更直接。蓝牙 Native 代码大量用 `std::shared_timed_mutex` 保护回调时的全局引用（如 04.4 节 `jniObjMutex`）。

## 3. 4 种常用锁 + Java 类比

| C++ | 含义 | Java 类比 |
|-----|------|---------|
| `std::mutex` | 互斥锁（独占） | `synchronized` / `ReentrantLock` |
| `std::recursive_mutex` | 可重入 | `ReentrantLock`（同线程多次进入） |
| `std::shared_mutex` / `shared_timed_mutex` | 读写锁 | `ReentrantReadWriteLock` |
| `std::atomic<T>` | 原子变量 | `java.util.concurrent.atomic.AtomicXxx` |

## 4. RAII 加锁三件套

```cpp
std::mutex m;
{
    std::lock_guard<std::mutex> lk(m);  // ① 出作用域自动解锁
    shared_data++;
}

std::unique_lock<std::mutex> lk(m);     // ② 可手动 unlock/lock；可配合 condition_variable
condition_var.wait(lk, predicate);
lk.unlock();

std::shared_mutex rw;
std::shared_lock<std::shared_mutex> read(rw);    // ③ 多个读并发
std::unique_lock<std::shared_mutex> write(rw);   // 独占写
```

## 5. 蓝牙真实例子：读写锁保护全局引用

```cpp
// system/.../com_android_bluetooth_btservice_AdapterService.cpp:125
static std::shared_timed_mutex jniObjMutex;
static jobject sJniCallbacksObj;

static void some_callback(...) {
    std::shared_lock<std::shared_timed_mutex> lock(jniObjMutex);   // ① 读锁
    if (!sJniCallbacksObj) return;
    // 使用 sJniCallbacksObj
}

static void cleanup() {
    std::unique_lock<std::shared_timed_mutex> lock(jniObjMutex);   // ② 写锁
    sJniCallbacksObj = nullptr;
}
```

理由：回调发生频繁（多线程读），cleanup 很少（独占写）。读写锁比 `mutex` 性能好。

**Java 类比**：
```java
private final ReadWriteLock lock = new ReentrantReadWriteLock();
private volatile JniCallbacks sJniCallbacks;

void someCallback() {
    lock.readLock().lock();
    try {
        if (sJniCallbacks == null) return;
        // 使用
    } finally { lock.readLock().unlock(); }
}

void cleanup() {
    lock.writeLock().lock();
    try { sJniCallbacks = null; }
    finally { lock.writeLock().unlock(); }
}
```

## 6. condition_variable

C++ 等待 / 通知：
```cpp
std::mutex m;
std::condition_variable cv;
bool ready = false;

// 等待
std::unique_lock<std::mutex> lk(m);
cv.wait(lk, []{ return ready; });

// 通知
{
    std::lock_guard<std::mutex> lk(m);
    ready = true;
}
cv.notify_one();
```

Java 类比：`Object.wait()` / `Object.notify()` 或 `Lock.newCondition()` 的 `await()` / `signal()`。

## 7. 原子操作

```cpp
std::atomic<int> counter{0};
counter++;                       // 原子加
int v = counter.load();           // 读
counter.store(42);                // 写

// CAS
int expected = 0;
counter.compare_exchange_strong(expected, 1);
```

Java：`AtomicInteger` / `compareAndSet`。

## 8. 蓝牙线程模型

回顾：
- **main_thread**：BTA/BTIF/Stack 业务全在这里。`do_in_main_thread` 投递。
- **HCI 线程**：GD HciLayer 自有线程。
- **Profile 线程**：A2DP 编解码线程等。
- **Binder/JNI 线程**：从 Java 入口进来。

**Native 规约**：业务数据**只在 main_thread 修改**——所以蓝牙绝大多数 BTA/Stack 函数**无锁**。锁主要出现在：
- JNI 全局引用保护（`jniObjMutex`）。
- 共享于多线程的统计计数。
- profile 线程与 main_thread 共享的数据队列。

## 9. 并发陷阱

| 陷阱 | 后果 | 修法 |
|------|------|------|
| 持锁阻塞（在锁内做 IO） | 阻塞所有等待者 | 锁内只做最小操作 |
| 嵌套加锁顺序不一致 | 死锁 | 全局锁层级表 |
| 忘记 unique_lock 默认 RAII 会解锁 | 假设手动控制结果错 | 看清 lock_guard vs unique_lock 行为 |
| 在 callback 中再调本对象的"对外接口" | 重入死锁 | 用 weak_ptr + post 出去再处理 |

## 12. 本节小结（速记卡）

```
锁 4 种：
  mutex / recursive_mutex / shared_(timed_)mutex / atomic
RAII 包装：
  lock_guard       简单 RAII 加锁
  unique_lock      可手动 unlock，可与 condition_variable 配
  shared_lock      读锁（共享）
通知：condition_variable.wait / notify
原子：std::atomic CAS
蓝牙线程模型：业务在 main_thread；锁主要保护 JNI 全局引用与跨线程队列
Java 对照：synchronized / ReentrantLock / ReadWriteLock / AtomicXxx / Object.wait
陷阱：持锁 IO / 嵌套不一致 / 重入死锁
```
