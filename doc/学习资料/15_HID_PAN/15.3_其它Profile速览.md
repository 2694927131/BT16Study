# 15.3 其它 Profile 速览

> **速通摘要**：除了主线讲过的 A2DP/AVRCP/HFP/GATT/HID/PAN/LE Audio/OBEX，Android 蓝牙栈还有若干"补位"Profile：① **A2dpSink**——车机当 Sink 接手机音乐（不同于 A2DP Source）；② **HeadsetClient**——车机当 HF 接听手机来电（最常用，事实上是 IVI 主路径）；③ **AvrcpController**——车机当 CT 控制手机播放；④ **BatteryService (BAS)**——读对端电量；⑤ **HearingAid (ASHA)**——12.5 已介绍过的助听器；⑥ **VAPS**——车载 Vendor 扩展。本节按"用途 + Service 入口"快速点名，方便后续深挖时定位起点。

---

## 学习目标

读完本节后，你能：
1. 列出 IVI 车机最常用的 6-8 个 Profile 角色（Source vs Sink / AG vs Client）。
2. 找到每个 Profile 的 Service 类入口。
3. 区分 "本机角色" 与 "对端角色"（同 Profile 不同 Service）。
4. 知道哪些 Profile 是 LE Audio 引入的，哪些是 Classic 老牌。

## 一、Source/Sink、AG/Client 角色对照

蓝牙 Profile 多数是"角色对称双角色"，本机当哪一边决定加载哪个 Service：

| Profile 家族 | 角色 A | 角色 B | 车机典型选择 |
|--------------|--------|--------|--------------|
| A2DP | **Source**（出声方，手机） | **Sink**（收声方，耳机/车机） | Sink |
| AVRCP | Target（被控方，手机） | **Controller**（控制方，车机） | Controller |
| HFP | **AG** (Audio Gateway，手机) | HF/Client（车机） | HF/Client |
| HID | Host（主机，车机） | Device（外设） | Host |
| PAN | NAP（热点） | PANU（客户端） | PANU + NAP 都可 |
| OBEX (PBAP) | PSE（电话簿服务器，手机） | **PCE**（客户端，车机） | PCE |
| OBEX (MAP) | MSE（消息服务器，手机） | **MCE**（客户端，车机） | MCE |
| LE Audio (Unicast) | Sink/Source 双向 | Sink/Source 双向 | 双向 |

**车机最常用组合**：A2DP Sink + HFP Client + AVRCP Controller + PBAP Client + MAP Client + GATT Client + HID Host + LE Audio。

## 三、A2DP Sink + AVRCP Controller（车机音频接收端）

车机播手机音乐的路径：

```
手机 (A2DP Source)        车机 (A2DP Sink)
   └─ AVDTP START ──────→ A2dpSinkService.java:48
                            └─ 收 SBC/AAC/LDAC 流 → AudioTrack → 车机喇叭

手机 (AVRCP Target)       车机 (AVRCP Controller)
   ↑                       AvrcpControllerService.java:52
   └─ "下一首" 命令 ←──────  按方向盘 Next 键
   └─ Track 信息 ────────→ 车机仪表盘显示歌名
```

**与 A2DP Source / AVRCP Target 的差异**：
- Sink 不需要做 SBC 编码（手机已经编好），只需解码
- Controller 主要发送命令、被动接收 NowPlaying / 元数据
- 同一台车机不会同时启用 Source 和 Sink（角色冲突）

## 四、HFP Client（车机接听电话）

```
手机 (HFP AG)             车机 (HFP HF/Client)
   └─ RING ──────────→ HeadsetClientService.java:63
                          └─ 通知车机来电 UI
                          └─ 用户接听 → ATA 回送 AG
                          └─ SCO 建立 → 通话音频路由
```

详见 07 章。车载场景下 `HeadsetClient` 是**绝对主线**，没有这个手机来电就完全无法用车机接。

## 五、Battery Service (BAS)

```java
// android/app/src/com/android/bluetooth/bas/BatteryService.java:47
public class BatteryService extends ConnectableProfile {
    // 通过 GATT 读对端 Battery Service (UUID 0x180F) 的电量特征
}
```

车机用途：仪表盘显示手机电量、显示蓝牙耳机电量。

GATT 路径：
- Battery Service UUID: `0x180F`
- Battery Level Characteristic: `0x2A19`（0-100 整数）
- 通过 Notify 机制实时更新

## 六、HearingAid (ASHA)

```java
// android/app/src/com/android/bluetooth/hearingaid/HearingAidService.java:62
public class HearingAidService extends ConnectableProfile {
    // ASHA = Audio Streaming for Hearing Aids（Google 主推）
    // 区别于 BT SIG 标准的 HAP（LE Audio 体系下）
}
```

ASHA 与 LE Audio HAP 的关系：
- ASHA = 老方案，专用 LE Audio Stream，仅 Google 阵营支持
- HAP = SIG 标准，基于 LE Audio Unicast，全行业支持
- 详见 12.5

## 八、Profile 加载机制

所有 `ConnectableProfile` 子类由 `AdapterService` 在启动时根据 sysprop / aconfig flag 决定是否实例化：

```java
// 车机定制：通过 sysprop 关闭不需要的 Profile（节省内存）
// android/app/sysprop/BluetoothProperties.sysprop
isProfileA2dpSinkEnabled()      → true   // 车机要听音乐
isProfileA2dpSourceEnabled()    → false  // 车机不出声给别人
isProfileHfpClientEnabled()     → true   // 车机要接电话
isProfileHfpAgEnabled()         → false  // 车机不是 AG
isProfilePbapClientEnabled()    → true   // 车机同步电话簿
isProfilePanPanuEnabled()       → false  // 大多关掉
```

## 九、Profile 角色冲突表

部分 Profile 同一台设备不能同时启用对立角色：

| 不可共存组合 | 原因 |
|--------------|------|
| A2DP Source + A2DP Sink | SDP 记录冲突，同一 SBC 端点角色不能两面 |
| HFP AG + HFP Client | 一个号一个声音通道，无法双向 |
| AVRCP Target + AVRCP Controller | 同上 |
| PBAP Server + PBAP Client | 同一 OBEX 通道角色冲突 |

**可以共存**：
- A2DP Sink + AVRCP Controller（车机主线）
- HFP Client + PBAP Client（车机主线）
- 多个 LE Audio 角色（Sink + Source + BASS Client + VCP）

## FAQ

**Q1：为什么 Battery Service 这么简单还要单独 Service？**
为了在 ProfileProxy 统一暴露给应用层（`BluetoothProfile.BATTERY` 常量），并参与 ConnectionPolicy / 自动重连。同时方便统一管理 GATT 订阅生命周期。

**Q2：HAP 和 ASHA 车机要不要都支持？**
现阶段两者并存：① ASHA 已大量出货（2019+ 的助听器），不能砍；② HAP 是未来标准。Android 16 同时维护两个 Service。

**Q3：VAPS 是什么时候用的？**
车机厂商谈下来的私有 Profile（如某汽车品牌专用低延迟音频）。AOSP 主线提供框架，具体 vendor 实现在 vendor 仓里。一般工程师无需关心。

**Q4：每个 Profile 是不是都有 StateMachine？**
不全是。简单的（如 BatteryService）用 Handler；复杂的（A2DP/HFP/LE Audio）用 `com.android.bluetooth.statemachine.StateMachine`（Android 状态机框架）；中等的（如 PAN/HID Host）用 Handler + 状态字段。
