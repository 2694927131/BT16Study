# 17.3 多 Profile 共存（HFP + A2DP + BLE 扫描 + 多手机的资源仲裁）

> **速通摘要**：多 Profile 同时工作时，蓝牙芯片的资源（HCI 带宽、L2CAP 通道、SCO slot、ACL 数量、LE 扫描时间片）会发生争抢。典型问题：① 来电时 BLE 扫描中断；② 两台手机同时连 A2DP 时第二台拒绝；③ Auracast 广播开启后 HFP SCO 失败。Android 通过多层资源管理处理：**aconfig flag 控制 Profile 启用**、**ConnectionPolicy 限制并发**、**HCI 调度由 Controller 仲裁**。本节梳理常见冲突场景与排查思路。

## 场景故事

某车主反馈：开车时手机 A 在播音乐（A2DP），手机 B 来电话，车机一接听就听到 B 的 HFP 切到了，但 A 的音乐没暂停（应该自动 Duck 或停）；通话挂掉后，A 的音乐也没自动恢复。

实际原因牵涉到三个 Profile（A 的 A2DP / B 的 HFP / Audio 焦点管理）和一个外部依赖（AudioPolicyManager）。多 Profile 场景的故障，往往要从"资源分配 + 焦点流转"两个角度分析。

## 蓝牙芯片的有限资源

| 资源类型 | 典型上限 | 受谁限制 | 用途 |
|---------|---------|---------|------|
| **ACL 连接数** | 7（理论）/ 5-7（实际） | Controller 固件 | 同时连的 Classic BT 链路 |
| **LE 连接数** | 8-20 | Controller | BLE GATT 连接 |
| **SCO Slot** | 1-3 | Controller + Profile | 通话音频 |
| **L2CAP 通道** | 0xFFFF 个 CID | 协议层 | 上层应用复用 |
| **LE Scan 时间片** | 60% 占空比典型 | Controller 调度 | BLE 扫描，与 LE 连接互斥 |
| **HCI 带宽** | UART 3-4Mbps | HW | 命令/数据传输 |

读取本机限制的方法：

```bash
adb shell dumpsys bluetooth_manager | grep -i "max_\|num_\|supported"
# 关键值：max_acl_connections / max_le_connections / sco_link_count
```

## 典型冲突 1：HFP SCO vs A2DP

**现象**：A2DP 在播音乐，HFP 进入通话（建立 SCO）后音乐音量明显下降或被压制。

**原因**：
- 同一台设备的 A2DP 和 HFP 共享 ACL 链路上的带宽
- SCO 是同步链路，优先级高，必然抢占
- AudioPolicyManager 会根据 STREAM_VOICE_CALL 出现，自动给 STREAM_MUSIC 让位（Audio Focus 切换）

**Android 处理**：

```java
// android/app/src/com/android/bluetooth/hfp/HeadsetService.java（路径示例，见 16.3）
// 当 HFP 进入 RINGING / IN_CALL：
// 1. HeadsetService.requestAudioStateChange() 触发 SCO 建立
// 2. AudioManager.requestAudioFocus(STREAM_VOICE_CALL)
// 3. 触发 A2DP 的 Audio Focus loss → 应用层（Spotify）收到 onAudioFocusChange
// 4. Spotify 自动暂停或降音
```

排查：
```bash
adb logcat -s AudioFocus:V Headset:V A2dpService:V
```

## 典型冲突 2：两台手机同时连 A2DP

**现象**：iPhone 已连 A2DP 听歌，Pixel 来连 A2DP，连接成功但听不到声。

**原因**：A2DP Source 端（手机）和 Sink 端（车机）的关系是 1:N（车机可以接多台手机），但**车机一次只能 active 一台**（见 17.1 ActiveDeviceManager）。

**Android 处理**：
- 两台都允许 Connect（Connected）
- 但 Active 只能一台，看哪个先 Start Streaming 或哪个被用户在 UI 上选中

**车机厂商有时需要更严格策略**：只允许一台手机连 A2DP。修改方式：
- 在 `PhonePolicy.processProfileStateChanged()` 中：第二台 A2DP CONNECTING 时直接拒绝
- 或在 `A2dpService` 的 `okToConnect()` 中加额外判断

## 典型冲突 3：BLE 扫描 vs BLE 连接

**现象**：车机一边扫描 BLE 蓝牙钥匙广播，一边维持已连的 BLE 设备，发现钥匙广播经常丢。

**原因**：BLE 扫描和 LE 连接共享同一射频时间片。控制器固件用时间分片调度：
- 连接事件（Connection Interval）必须按时发生
- 扫描在连接事件的空隙进行
- 如果连接数多、Connection Interval 短，扫描占空比被压缩

**Android 优化**：

```java
// 通过 ScanMode 控制扫描占空比：
SCAN_MODE_LOW_POWER     // ~10% duty cycle（默认）
SCAN_MODE_BALANCED      // ~25%
SCAN_MODE_LOW_LATENCY   // ~100%（持续扫描，耗电）
SCAN_MODE_OPPORTUNISTIC // 不发起扫描，搭车其他 app 的扫描
```

车机需要快速发现 BLE 钥匙时用 LOW_LATENCY，但要注意：
- LE 连接的 Connection Interval 会被自动调大以让位扫描
- 已连的 BLE 设备会感觉到延迟变高

## 典型冲突 4：Auracast 广播 vs HFP SCO

**现象**：开启 Auracast LE Audio 广播后，HFP 通话偶尔建链失败。

**原因**：LE Audio 的 BIS（Broadcast Isochronous Stream）和 Classic 的 SCO 都需要预留固定的 ISO/SCO 时间片。低端控制器的 ISO 调度算法可能没考虑同时存在的 Classic SCO。

**排查**：
```bash
adb logcat -s LeAudioBroadcaster:V hci:V | grep -i "sco\|iso\|reject"
# 关注 HCI Error Code 0x0D (Connection Rejected due to Limited Resources)
```

**缓解**：
- aconfig flag `leaudio_broadcast_inhibit_sco` 可在广播开启时禁用 SCO
- 或反过来：通话时强制停止广播

## 资源监控

```bash
# 当前所有 ACL 连接
adb shell dumpsys bluetooth_manager | grep -i "ACL_\|le_conn"

# 当前 SCO 状态
adb shell dumpsys bluetooth_manager | grep -i "sco_\|audio_state"

# 当前 L2CAP CID（活动连接）
adb logcat -s L2cap:V | tail -100

# HCI 错误码（常见资源耗尽：0x07/0x0D/0x0E）
adb logcat -s hci:V | grep -i "Connection Rejected\|Limited Resources"
```

**常见 HCI Error Code（资源相关）**：

| Code | 含义 |
|------|------|
| 0x07 | Memory Capacity Exceeded |
| 0x0C | Command Disallowed |
| 0x0D | Connection Rejected: Limited Resources |
| 0x0E | Connection Rejected: Security Reasons |
| 0x1B | SCO Offset Rejected |
| 0x1C | SCO Interval Rejected |
| 0x1D | SCO Air Mode Rejected |

## 多手机场景仲裁矩阵

| 设备 1 | 设备 2 | 冲突点 | Android 默认行为 |
|--------|--------|--------|------------------|
| 手机A A2DP | 手机B A2DP | Active 只能一个 | 后启动播放者成为 Active |
| 手机A HFP | 手机B HFP | SCO 只能一个 | 来电方成为 Active |
| 手机A A2DP | 手机A HFP | 同设备共存 OK | 同时 Connected, Active 互不冲突 |
| 手机A A2DP | 手机B HFP | 跨设备共存 | A2DP/HFP active 分属两台，OK |
| 多台 BLE 设备 | LE 扫描 | RF 时间片 | 扫描间隔被自动拉长 |
| LE Audio Broadcast | HFP SCO | ISO/SCO 调度 | 取决于 controller 固件 |

## FAQ

**Q1：为什么车机厂商常常限制只能连 2 台手机？**
理论上 Android 蓝牙栈不限制 N 台，但实际：① 控制器 ACL slot 有限；② Audio HAL 路径只支持单 active；③ 用户体验混乱（5 台都连着切不过来）。所以 IVI 一般用 PhonePolicy 限制 2-3 台。

**Q2：HFP SCO 建立失败错误码 0x1B/0x1C/0x1D 是什么？**
SCO 参数协商失败：
- 0x1B：SCO Offset 不可接受（时间槽冲突）
- 0x1C：SCO Interval 不可接受
- 0x1D：SCO Air Mode 不可接受（CVSD vs mSBC 不匹配）
解决：检查双方 HFP/eSCO 支持能力，必要时降级 mSBC 到 CVSD。

**Q3：LE 扫描时车机用 LOW_LATENCY 会有什么副作用？**
- 耗电激增（持续 RX）
- 已连的 BLE 设备 Connection Interval 被拉大，响应变慢
- 不能长时间使用（建议带超时，找到目标后切回 BALANCED）

**Q4：如何知道当前用了多少 ACL slot？**
看 `dumpsys bluetooth_manager` 的 ACL 连接列表，或 logcat `hci:V` 中 `CONNECTION_COMPLETE` 事件数量。蓝牙规范支持最多 7 个 ACL，但实际很少有控制器能跑满。
