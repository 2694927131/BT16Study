# 17.4 SilenceDeviceManager / CompanionManager

> **速通摘要**：除了 `ActiveDeviceManager` 和 `PhonePolicy`，Android 还有两个面向高级场景的管理器：① **SilenceDeviceManager**——"静默"某设备（不路由音频但保持连接，类似"挂起"），常用于多设备场景下用户想暂时静音某台手机但不断开蓝牙；② **CompanionManager**——通过 Android `CompanionDeviceManager` 把某蓝牙设备标记为"主/副配对伴侣"（Primary/Secondary），用于 GATT 连接参数优化（智能手表场景）。源码位置：`SilenceDeviceManager.java:50`、`CompanionManager.java:46`。

## 一、SilenceDeviceManager

### 1.1 场景

用户场景：副驾的手机连了车机，但副驾不想让自己的歌占了音频通道，又不想断开蓝牙（因为还要让车机能转发副驾手机的来电通知到副驾这边）。

**Silence 模式 = "连接保持，但音频路由跳过"**：
- A2DP 还是 Connected，但不会成为 Active
- HFP 也是 Connected，但 SCO 不路由到该设备
- 通知 / 短信 / 联系人同步等非音频功能依然工作

### 1.2 源码结构

```java
// android/app/src/com/android/bluetooth/btservice/SilenceDeviceManager.java:50
public class SilenceDeviceManager {
    // :60
    private static final int MSG_SILENCE_DEVICE_STATE_CHANGED = 1;
    private static final int MSG_A2DP_CONNECTION_STATE_CHANGED = 10;
    private static final int MSG_HFP_CONNECTION_STATE_CHANGED = 11;
    private static final int MSG_A2DP_ACTIVE_DEVICE_CHANGED = 20;
    private static final int MSG_HFP_ACTIVE_DEVICE_CHANGED = 21;

    // :74 来自 ActiveDeviceManager 的回调
    public void profileActiveDeviceChanged(int profile, BluetoothDevice device) {
        switch (profile) {
            case BluetoothProfile.A2DP:
                mHandler.obtainMessage(MSG_A2DP_ACTIVE_DEVICE_CHANGED, device).sendToTarget();
                break;
            case BluetoothProfile.HEADSET:
                mHandler.obtainMessage(MSG_HFP_ACTIVE_DEVICE_CHANGED, device).sendToTarget();
                break;
        }
    }

    // :91 A2DP 连接状态变化
    public void a2dpConnectionStateChanged(BluetoothDevice device, int fromState, int toState) {
        mHandler.obtainMessage(MSG_A2DP_CONNECTION_STATE_CHANGED, fromState, toState, device)
                .sendToTarget();
    }

    // :103 HFP 连接状态变化
    public void hfpConnectionStateChanged(BluetoothDevice device, int fromState, int toState) {
        mHandler.obtainMessage(MSG_HFP_CONNECTION_STATE_CHANGED, fromState, toState, device)
                .sendToTarget();
    }
}
```

### 1.3 上层 API

```java
// android.bluetooth.BluetoothDevice （Framework API，外部依赖）
public boolean setSilenceMode(boolean silence);
public boolean isInSilenceMode();
```

应用层（如设置 UI、车机管家 App）调用 `setSilenceMode(true)` 把设备静音：
1. SilenceDeviceManager 把内部状态置 silenced
2. 如果该设备当前是 active，触发 ActiveDeviceManager 切到下一个候选
3. 该设备依然 Connected，但所有"成为 active"的判定都跳过它

### 1.4 状态联动

```mermaid
graph TD
    A[User: setSilenceMode(true)] --> B[SilenceDeviceManager 标记]
    B --> C{当前是否 Active?}
    C -->|是| D[触发 ActiveDeviceManager 切换]
    C -->|否| E[只更新状态]
    D --> F[新设备成为 A2DP/HFP Active]
    E --> G[等待下次 Profile 事件]

    H[Profile Connection 变化] --> I{设备是 silenced?}
    I -->|是| J[跳过成为 Active 的判定]
    I -->|否| K[正常仲裁]
```

### 1.5 Silence vs Disconnect 对比

| 维度 | Silence | Disconnect |
|------|---------|------------|
| ACL | 保持 | 断开 |
| Profile 连接 | 保持 | 断开 |
| Audio Active | 否 | 否（无连接） |
| 通知/同步 | 工作 | 不工作 |
| 重连成本 | 0（无需重连） | 需要 ACL+Profile 全重建（~3-5s） |
| 用户体验 | 即时切换 | 有可见的"断开-重连"延迟 |

## 二、CompanionManager

### 2.1 场景

智能手表场景：用户的手机长时间连接智能手表（BLE GATT 通信，心率/通知同步）。手表是"伴侣设备"，需要更激进的 GATT 连接参数（更短的 Connection Interval）来保证消息及时性，但同时不能太激进以免耗电。

Android 通过 `CompanionDeviceManager`（外部依赖，framework 提供）允许 App 把某设备标记为 **Companion**（主/副伴侣），蓝牙栈根据这个标记调整参数。

### 2.2 源码结构

```java
// android/app/src/com/android/bluetooth/btservice/CompanionManager.java:46
public class CompanionManager {

    // :60 Companion 类型
    static final int COMPANION_TYPE_NONE       = 0;  // 不是伴侣
    static final int COMPANION_TYPE_PRIMARY    = 1;  // 主伴侣（如主用手表）
    static final int COMPANION_TYPE_SECONDARY  = 2;  // 副伴侣（如备用手环）

    // :68 持久化存储
    static final String COMPANION_INFO        = "bluetooth_companion_info";
    static final String COMPANION_DEVICE_KEY  = "companion_device";
    static final String COMPANION_TYPE_KEY    = "companion_type";

    // :378 GATT 连接参数定制入口（核心）
    public int getGattConnParameters(BluetoothDevice device, int type, int priority) {
        int companionType = isCompanionDevice(device) ? mCompanionType : COMPANION_TYPE_NONE;
        return switch (companionType) {
            case COMPANION_TYPE_PRIMARY   -> getGattConnParameterPrimary(type, priority);   // :381
            case COMPANION_TYPE_SECONDARY -> getGattConnParameterSecondary(type, priority); // :382
            default                       -> getGattConnParameterDefault(type, priority);
        };
    }
}
```

### 2.3 三档参数差异

| 设备类型 | Connection Interval Min | Min Latency | Supervision Timeout | 用途 |
|---------|------------------------|-------------|---------------------|------|
| **PRIMARY** | 较短（7.5-15 ms） | 较低 | 短 | 主要伴侣，响应灵敏 |
| **SECONDARY** | 中等（15-30 ms） | 中 | 中 | 次要伴侣，平衡 |
| **NONE**（默认） | 30-50 ms | 较高 | 较长 | 普通 BLE 外设，省电优先 |

参数越激进（间隔越短）：响应越快，但耗电越多、与其他 BLE 设备的射频争抢越激烈。所以只有 Primary 才用最激进档。

### 2.4 持久化

```java
// CompanionManager.java:217
String address = getCompanionPreferences().getString(COMPANION_DEVICE_KEY, "");
mCompanionType = getCompanionPreferences().getInt(COMPANION_TYPE_KEY, COMPANION_TYPE_NONE);
```

存储位置：`bluetooth_companion_info` SharedPreferences。开机时自动加载，不需要重新由 App 标记。

### 2.5 应用层标记 API

```java
// android.bluetooth.BluetoothDevice
public static final String COMPANION_TYPE_PRIMARY   = "primary";
public static final String COMPANION_TYPE_SECONDARY = "secondary";

// 设置（需要 BLUETOOTH_PRIVILEGED 权限，通常只有系统 App 能调）
device.setMetadata(BluetoothDevice.METADATA_COMPANION_APP, "primary".getBytes());
```

车机场景一般不需要 Companion——手机不是车机的"伴侣"，而是临时连接的源设备。Companion 主要用于 Wear OS / 手表 / 健身手环这类长时绑定。

## FAQ

**Q1：Silence 模式下应用还能用 RFCOMM Socket 发送数据吗？**
能。Silence 只影响 ActiveDeviceManager 的音频仲裁，不影响应用层的 Socket / GATT / OBEX 数据通道。一台 silenced 的手机依然可以用 PBAP 同步联系人、用 RFCOMM 收发 SPP 数据。

**Q2：CompanionDevice 在车机场景有用吗？**
极少。车机最常的"长期伴侣"可能是车主主用手机（设为 Primary 可以让 BLE 钥匙数字钥匙更灵敏），但需要 App 主动标记。多数车机不利用这个机制，而是直接调 GATT API 的 `requestConnectionPriority()`。

**Q3：Silence 和 ConnectionPolicy_FORBIDDEN 有什么区别？**
- FORBIDDEN：禁止自动连接，但用户手动可以连
- Silence：已连接，只是不参与音频仲裁
两者完全独立，可以组合：一台 FORBIDDEN + Silence 的设备 = 不会自动连，连上后也不能成为 active。

**Q4：把所有手机都 Silence 了，音频会怎么样？**
没有任何手机能成为 A2DP/HFP active，车机喇叭无蓝牙音乐输出（fallback 到本地音频源，如 FM/AUX/USB）。来电时也无法用蓝牙接听。
