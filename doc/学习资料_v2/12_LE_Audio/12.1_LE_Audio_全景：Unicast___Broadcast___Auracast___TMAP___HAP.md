<!--
已知陷阱（生成时必须注意）：
  - 不要把 LE Audio 当成 A2DP 的 LE 版
      LE Audio 重新设计了协议栈：用 LC3 取代 SBC、用 CIS/BIS 取代 L2CAP+AVDTP、用 BAP/ASCS 取代 A2DP/AVDTP；它是 BLE 5.2 引入的全新音频架构
  - 不要把 Auracast 和 BLE Mesh 混为一谈
      Auracast 是 LE Audio Broadcast 的市场品牌名（由 Bluetooth SIG 推广），走 BIS/PA；BLE Mesh 是另一个完全独立的网络层协议（走 GAP Advertising + GATT），两者无关
  - 不要假设所有 BLE 5.2+ 设备都支持 LE Audio
      LE Audio 需要 Controller 支持 Isochronous Channels（CIS/BIS）；早期 BLE 5.2 芯片可能只支持 LE 2M PHY 但不含 ISO，要用 LE Read Local Supported Commands 验证
  - Unicast 和 Broadcast 是两套独立 Service
      LeAudioService 只管 Unicast；Broadcast 是 LeAudioBroadcastService（Native 端为 LeAudioBroadcasterImpl）；两者的 GATT 服务、状态机、HAL 路径完全独立，调试时不要混查日志
  - 不要用 'Master/Slave' 描述 LE Audio 角色
      LE Audio 中应使用 Central（车机/手机）/ Peripheral（耳机/助听器）；Broadcast 中应使用 Source（发射端）/ Sink（接收端）
-->

### 片段：snippet_le_audio_initialize

**来源**：`system/bta/le_audio/client.cc:7749-7758`

```cpp
// L7749
void LeAudioClient::Initialize(
        bluetooth::le_audio::LeAudioClientCallbacks* callbacks_, base::Closure initCb,
        base::Callback<bool()> hal_2_1_verifier,
        const std::vector<bluetooth::le_audio::btle_audio_codec_config_t>& offloading_preference) {
  std::scoped_lock<std::mutex> lock(instance_mutex);
  if (instance) {
    log::error("Already initialized");
    return;
  }
  // ... 创建 LeAudioClientImpl 单例，注册回调、初始化 codec、加载持久化的 group ...
}
```

LE Audio Unicast 的 Native 入口。LeAudioService.java 通过 JNI 调用进入此处。
`offloading_preference` 参数告诉 Stack 哪些 codec 配置允许 offload 到 Controller（节省功耗），
其他配置回退到 Software 路径（CPU 跑 LC3 编解码）。
这里用 `std::scoped_lock` 加锁是 RAII —— 等价于 Java 的 `synchronized` 块。
