<!--
已知陷阱（生成时必须注意）：
  - 不要把 LC3 的帧时长和 CIS 的 ISO Interval 混为一谈
      LC3 帧时长（7.5ms 或 10ms）是编解码的时间粒度，决定编码延迟；
CIS 的 ISO Interval 是蓝牙等时流的调度间隔，通常是帧时长的整数倍。
帧时长 10ms + ISO Interval 10ms 是最常见的低延迟配置，详见 12.3。

  - 不要假设所有 LE Audio 设备都支持 Offload
      Offload 需要 Controller 和 Audio HAL 同时支持（LeAudioHalVerifier::SupportsLeAudioHardwareOffload）。
车机 OEM 如果芯片的 Audio HAL 尚未实现 LE Audio Offload 接口，GetCodecLocation 会返回 HOST，
LC3 就在 CPU 上跑，功耗上升约 3%（单通道）。

  - 不要直接 new CodecInterface，要用 CreateInstance 工厂方法
      `CodecInterface::CreateInstance(LeAudioCodecIdLc3)` 返回 unique_ptr，
确保生命周期安全（RAII）。直接构造 `CodecInterface obj(...)` 没有问题但不符合项目惯例，
且与 PIMPL 的 impl 析构顺序会有微妙差异。

  - LeAudioCodecIdOpus 是 Vendor Specific，不是 LC3 的变种
      OPUS 在 LE Audio 中走 Vendor Specific Codec（coding_format = 0xFF，vendor_company_id = Google）。
`leaudio_add_opus_hi_res_codec_type` flag 开启后才有效，且需要对端耳机也支持。
不要把 OPUS 和 LC3 的 codec_id 混用。

  - JSON 配置文件在 APEX 下，模拟器上路径不同
      `kLeAudioSetConfigs` 定义的路径是 `/apex/com.android.bt/...`，在模拟器或 AOSP 开发构建中
该路径可能不存在，LoadConfigurationsFromFiles 会失败并回退内置默认配置。
真机调试时先用 `adb shell ls /apex/com.android.bt/etc/bluetooth/le_audio/` 确认文件存在。

-->

### 片段：snippet_codec_interface_encode

**来源**：`system/bta/le_audio/codec_interface.h:41-72`

```cpp
// L41
class CodecInterface {
public:
  enum class Status {
    STATUS_ERR_CODEC_NOT_READY = -128,
    STATUS_ERR_INVALID_CODEC_ID = -127,
    STATUS_ERR_CODING_ERROR = -1,
    STATUS_OK = 0,
  };

  CodecInterface(const types::LeAudioCodecId& codec_id);
  virtual ~CodecInterface();
  static std::unique_ptr<CodecInterface> CreateInstance(
          const types::LeAudioCodecId& codec_id) {
    return std::make_unique<CodecInterface>(codec_id);
  }
  // L55
  virtual CodecInterface::Status InitEncoder(
          const LeAudioCodecConfiguration& pcm_config,
          const LeAudioCodecConfiguration& codec_config);
  virtual CodecInterface::Status InitDecoder(
          const LeAudioCodecConfiguration& codec_config,
          const LeAudioCodecConfiguration& pcm_config);
  // L59
  virtual CodecInterface::Status Encode(
          const uint8_t* data, int stride, uint16_t out_size,
          std::vector<int16_t>* out_buffer = nullptr, uint16_t out_offset = 0);
  virtual CodecInterface::Status Decode(uint8_t* data, uint16_t size);
  // ...
};
```

CodecInterface 是 AOSP LE Audio Software（CPU）编解码路径的核心：
- 用 `CreateInstance(LeAudioCodecIdLc3)` 创建 LC3 编解码器实例（工厂方法，返回 unique_ptr）；
- InitEncoder / InitDecoder 传入 PCM 参数（采样率、比特宽度、帧间隔）与 codec 参数；
- Encode 把 PCM 字节流编成 LC3 帧，Decode 反向；
- Status 枚举是 C++ 的错误码机制，等价于 Java 的枚举返回值或 exception。
Offload 模式（Controller 自行编解码）不走此路径，但 Software 回退时必经此处。

### 片段：snippet_codec_manager_start

**来源**：`system/bta/le_audio/codec_manager.cc:1455-1475`

```cpp
// L1455
CodecManager::CodecManager() : pimpl_(std::make_unique<impl>(*this)) {}

// L1457
void CodecManager::Start(
        const std::vector<btle_audio_codec_config_t>& offloading_preference) {
  if (!pimpl_->IsRunning()) {
    pimpl_->Start(offloading_preference);
  }
}

// L1463
void CodecManager::Stop() {
  if (pimpl_->IsRunning()) {
    pimpl_->Stop();
  }
}

// L1469
types::CodecLocation CodecManager::GetCodecLocation(void) const {
  if (!pimpl_->IsRunning()) {
    return CodecLocation::HOST;
  }
  // ... 返回 ADSP / HOST / UNKNOWN
}
```

CodecManager 通过 PIMPL 模式（Pointer to IMPLementation）隐藏内部实现——
等价于 Java 的接口 + 实现类分离。pimpl_ 是一个指向 impl 的 unique_ptr，
公开方法全部转发给 pimpl_->xxx()。
GetCodecLocation 返回的 CodecLocation 枚举决定了 LC3 跑在哪里：
- HOST：CPU Software 路径，走 CodecInterface::Encode/Decode；
- ADSP：DSP Offload 路径，由 Controller/DSP 完成编解码；
Start() 的 offloading_preference 参数来自 LeAudioClient::Initialize 时透传的
`offloading_preference`（见 12.1 物料包 snippet_le_audio_initialize）。
