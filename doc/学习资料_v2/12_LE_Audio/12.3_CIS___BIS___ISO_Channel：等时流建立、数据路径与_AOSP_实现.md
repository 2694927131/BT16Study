<!--
已知陷阱（生成时必须注意）：
  - 不要把 CIG 和 ACL Connection Handle 混淆
      CIG 有自己的 conn_handle（由 HCI_LE_CREATE_CIS 返回），
与 ACL 的 conn_handle 是不同的命名空间。
调试时 `ProcessHciNotifCisEstablished` 中的 cis_conn_hdl 是 CIS 专属句柄，
不能用来发 ACL 数据。混用会导致 HCI 命令失败。

  - max_transport_latency 不等于端到端音频延迟
      max_trans_lat 是 BLE 物理层的传输延迟上限（Controller 级别），
端到端延迟还需加上：编解码延迟（LC3 帧时长）+ Presentation Delay（接收端缓冲等待）。
典型端到端延迟 = 帧时长(10ms) + max_trans_lat(10ms) + Presentation Delay(10-40ms)
≈ 30-60ms，远高于 max_trans_lat 本身。详见 16.4。

  - CIS 建立是异步多步的，不要期望 StartStream 同步返回音频可用
      StartStream() 只是触发 CigCreate，整个流程经历
CigCreate → CisEstablish → SetupIsoDataPath 三个异步步骤，
每步都需要等 HCI Event。从 StartStream 到音频真正可播，
通常需要 200-500ms。LeAudioClient 通过 StatusReportCb 通知上层流已就绪。

  - Broadcast BIS 的安全性依赖 Broadcast Code，不要以为无配对就意味着无加密
      Auracast 广播可设置 Broadcast Code（128-bit 密钥）对 BIG 加密；
接收端需要通过带外方式（如 QR 码、NFC）获取 Broadcast Code 才能解密。
如果没有 Broadcast Code，BIG 是明文传输——公共场所广播（如车站音频）通常不加密，
私密场景（如会议室）应设置 Broadcast Code。

  - 不要用 LeAudioGroupStateMachine 直接处理 Broadcast 事件
      LeAudioGroupStateMachine 只管理 Unicast（CIG/CIS）；
Broadcast（BIG/BIS）由 BroadcastStateMachine 独立管理。
两套状态机的 HCI 回调注册路径完全不同（RegisterCigCallbacks vs RegisterBigCallbacks），
调试时不要混查日志。

-->

### 片段：snippet_cig_create_params

**来源**：`system/stack/include/btm_iso_api_types.h:74-83`

```cpp
// L74
struct cig_create_params {
  uint32_t sdu_itv_mtos;   // SDU 间隔：Central→Peripheral，单位 µs（如 10000 = 10ms）
  uint32_t sdu_itv_stom;   // SDU 间隔：Peripheral→Central，单位 µs
  uint8_t  sca;            // Slave Clock Accuracy，影响时钟漂移容忍度
  uint8_t  packing;        // 0x00 顺序打包 / 0x01 交错打包
  uint8_t  framing;        // 0x00 Unframed（固定大小 SDU）/ 0x01 Framed
  uint16_t max_trans_lat_stom;  // 最大传输延迟 Peripheral→Central，单位 ms
  uint16_t max_trans_lat_mtos;  // 最大传输延迟 Central→Peripheral，单位 ms
  std::vector<EXT_CIS_CFG> cis_cfgs;  // 该 CIG 下所有 CIS 的配置列表
};
```

cig_create_params 对应 HCI LE Set CIG Parameters 命令（opcode 0x0062）的参数。
- sdu_itv 是 LC3 帧时长的 µs 表达：帧时长 10ms → sdu_itv = 10000。
- packing = 0x00（Sequential）是车机 LE Audio Unicast 最常用配置；
  0x01（Interleaved）用于多设备同步（如左右耳独立 CIS 但精确同步）。
- max_trans_lat 不等于端到端音频延迟——它只是无线链路的传输时延上限，
  不含编解码（Presentation Delay）。端到端延迟详见 16.4。
等价 Java 理解：这个 struct 就是一个 Builder 模式的配置对象，
AOSP 把它填好后通过 IsoManager::CreateCig() 下发给 Controller。

### 片段：snippet_state_machine_start_stream

**来源**：`system/bta/le_audio/state_machine.cc:218-232`

```cpp
// L218
bool StartStream(LeAudioDeviceGroup* group, LeAudioContextType context_type,
                 const BidirectionalPair<AudioContexts>& metadata_context_types,
                 BidirectionalPair<std::vector<uint8_t>> ccid_lists) override {
  log::info("current state: {}", ToString(group->GetState()));

  switch (group->GetState()) {
    case AseState::BTA_LE_AUDIO_ASE_STATE_CODEC_CONFIGURED:
      if (group->IsConfiguredForContext(context_type)) {
        if (group->Activate(context_type, metadata_context_types, ccid_lists)) {
          SetTargetState(group, AseState::BTA_LE_AUDIO_ASE_STATE_STREAMING);
          if (CigCreate(group)) {   // ← 调用 IsoManager::CreateCig()
            return true;
          }
        }
      }
      // ...
  }
}
```

StartStream 是 Unicast CIS 建立流程的驱动入口：
1. 前提：ASE 已处于 CODEC_CONFIGURED 状态（GATT ASE 协商完成）
2. 调用 CigCreate → IsoManager::CreateCig → HCI_LE_SET_CIG_PARAMS
3. Controller 回调 OnCigEvent → ProcessHciNotifOnCigCreate（L653）
4. 再调用 IsoManager::EstablishCis → HCI_LE_CREATE_CIS
5. Controller 回调 OnCisEvent → ProcessHciNotifCisEstablished（L1150）
6. 最后 SetupIsoDataPath（L796）打通数据通路

这是"先配置 GATT ASE → 再建立 HCI CIG/CIS → 最后 Setup ISO DataPath"的三段式流程。
每一段都是异步的（等 HCI Event），所以用状态机串联。
