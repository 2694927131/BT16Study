<!--
已知陷阱（生成时必须注意）：
  - 不要把 VCP 的 VCS 和 AVRCP 的绝对音量混淆
      AVRCP Absolute Volume（A2DP 场景用）与 VCP VCS（LE Audio 场景用）是两套独立的音量协议。
如果设备同时连着 A2DP 和 LE Audio，需要分别处理。
车机切换到 LE Audio 后应停止用 AVRCP 音量控制，改用 VCP，否则两套控制会互相干扰。

  - CSIP lockGroup 不是分布式锁，只针对同一 Android 进程内的竞争
      lockGroup 防止的是同一 Bluetooth App 进程内多个客户端同时操作同一协调集，
不能防止跨 App 的并发（如车机 App + 三方音乐 App 同时调音量）。
实际生产中 OEM 通常通过 AudioPolicyManager 的音量路由确保只有一个路径在控制音量。

  - TBS 的 callAdded 只通知耳机，来电铃声路由还需 AudioPolicyManager 配合
      callAdded 只是把来电信息通知给 TBS Client（耳机），
真正让铃声从耳机扬声器出来，还需要 AudioPolicyManager 把 STREAM_RING
路由到当前活跃的 LE Audio 输出设备。两个步骤都要就绪铃声才能响。

  - MCP 控制的是 GATT 层的媒体状态，不直接控制 Android MediaPlayer
      McpService 通过 MediaControlProfile 连接到 Android MediaSession，
耳机发来的 MCP 媒体控制命令（play/pause）经由 MediaSession API 传到 App。
如果 App 没有注册 MediaSession（如某些直播 App），MCP 控制命令会被静默忽略。

-->

### 片段：snippet_csip_lock_group

**来源**：`framework/java/android/bluetooth/BluetoothCsipSetCoordinator.java:285-320`

```java
// L285
public @Nullable UUID lockGroup(
        int groupId,
        @NonNull @CallbackExecutor Executor executor,
        @NonNull ClientLockCallback callback) {
    // ...
    final IBluetoothCsipSetCoordinator service = getService();
    if (service == null) {
        Log.w(TAG, "Proxy not attached to service");
        return null;
    }
    // 向服务端申请对 groupId 的独占锁
    final ParcelUuid ret = service.lockGroup(groupId, delegate, mAttributionSource);
    return ret != null ? ret.getUuid() : null;
}

// L320
public boolean unlockGroup(@NonNull UUID lockUuid) {
    // 释放之前申请的锁，传入 lockGroup 返回的 lockUuid
    final IBluetoothCsipSetCoordinator service = getService();
    if (service == null) {
        return false;
    }
    service.unlockGroup(new ParcelUuid(lockUuid), mAttributionSource);
    return true;
}
```

lockGroup / unlockGroup 是 CSIP 的"原子操作"机制：
在给双耳同时设置音量或换曲时，先 lockGroup 确保两台设备不会被其他操作打断，
然后批量操作，最后 unlockGroup。
这等价于 Java 的 synchronized 块——锁住一个 groupId 代表的协调集，
期间其他客户端的操作会被排队。锁由 UUID 标识，不是 int，避免跨进程锁 ID 冲突。
未能获取锁时（另一个客户端持有锁）返回 null。

### 片段：snippet_vcp_set_device_volume

**来源**：`android/app/src/com/android/bluetooth/vc/VolumeControlService.java:583-595`

```java
// L583
synchronized void setDeviceVolume(BluetoothDevice device, int volume, boolean isGroupOp) {
    Log.d(TAG,
            "setDeviceVolume: " + device
            + ", volume: " + volume
            + ", isGroupOp: " + isGroupOp);
    if (isGroupOp) {
        // 找到设备所在的协调集 groupId，对整组下发音量
        int groupId = mCsipSetCoordinatorService.getGroupId(
                device, BluetoothUuid.CAP);
        if (groupId != BluetoothCsipSetCoordinator.GROUP_ID_INVALID) {
            mNativeInterface.setGroupVolume(groupId, volume);
            return;
        }
    }
    // 单设备音量设置（非组操作）
    mNativeInterface.setVolume(device, volume);
}
```

VCP 的音量控制分两路：
- isGroupOp=true：通过 CSIP 找到协调集 groupId，调用 Native setGroupVolume，
  一次命令同步双耳音量（如左右耳机）；
- isGroupOp=false：只对单个设备设置音量。
车机场景通常用 isGroupOp=true，确保双耳一致。
VOCS（Volume Offset Control Service）通过 setVolumeOffset 实现
左右声道独立偏移（如左耳 -3dB），与 VCS 绝对音量是叠加关系。
