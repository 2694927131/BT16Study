已知陷阱（生成时必须注意）：
  - 不要把 ASHA 的 OnAudioDataReady 和 LE Audio 的 CodecInterface::Encode 混淆
      ASHA 的 OnAudioDataReady 收到的是已经过 Audio HAL 处理的 G.722/16kHz PCM 数据，
由 hearing_aid_audio_hw.cc 调用，不走 CodecInterface（CodecInterface 只用于 LE Audio LC3）。

  - ASHA 不支持 Auracast（Broadcast），只支持单播
      ASHA 基于 BLE unicast（L2CAP CoC，点对点），没有 Broadcast 能力。
如果车机要向助听器广播公共音频（如导航提示音给所有乘客），
只能用 LE Audio HAP + Auracast，ASHA 助听器无法接收 BIS/BIG。

  - HAP 助听器需要 LE Audio 全套支持，不是独立 Profile
      HapClientService 本身只处理 HARC GATT 服务，音频传输还是走 LeAudioService 的 CIS。
如果 `bluetooth.profile.bap.unicast.client.enabled` 为 false，
HAP 助听器能连接但没有声音——两个 sysprop 必须同时开启。

  - ASHA 的 setVolume 和 VCP 的 setDeviceVolume 是两套独立音量控制
      ASHA 助听器的音量走 HearingAidService.setVolume → Native SetVolume（hearing_aid.cc:1984）；
LE Audio HAP 助听器的音量走 VolumeControlService.setDeviceVolume（见 12.4）。
不要用错接口——对 ASHA 设备调 VCP 无效，对 HAP 设备调 HearingAidService.setVolume 也无效。

### 片段：snippet_asha_on_audio_data_ready

**来源**：`system/bta/hearing_aid/hearing_aid.cc:1476-1510`

```cpp
// L1476
void OnAudioDataReady(const std::vector<uint8_t>& data) {
  /* called periodically by the writable socket thread  */
  std::lock_guard<std::mutex> guard(big_mutex);

  if (data.empty()) return;

  // 遍历当前活跃的助听器设备（可能有 2 台：左右耳）
  for (auto& device : hearingDevices.devices) {
    if (!device.accepting_audio) continue;

    // 音频数据通过 L2CAP CoC 发送到助听器
    // L2CAP CoC（Connection-oriented Channel）是 BLE 上的可靠传输通道
    int result = BT_STATUS_SUCCESS;
    if (!device.gap_handle) {
      log::warn("device {} has no gap handle", device.address);
      continue;
    }
    // 发送 PCM/编码数据到助听器（ASHA 不用 CIS/BIS，用 L2CAP CoC）
    SendPacket(device, data);
  }
}
```

OnAudioDataReady 是 ASHA 音频流的核心路径：每隔 ~20ms 被 Audio HAL 回调一次，
将 PCM 数据通过 L2CAP CoC 发送给助听器。
注意 ASHA 走的是 L2CAP CoC（不是 CIS），这是与 LE Audio HAP 最大的协议层差异：
- ASHA：BLE + L2CAP CoC + 专有音频编码（16kHz / 16-bit）
- HAP：LE Audio + CIS + LC3 编解码
ASHA 是 Google 在 LE Audio 标准化之前推出的过渡方案，HAP 是长期标准。
std::lock_guard<std::mutex> guard(big_mutex) 是 RAII 锁，等价于 Java synchronized 块。

### 片段：snippet_hearing_aid_initialize

**来源**：`system/bta/hearing_aid/hearing_aid.cc:2251-2265`

```cpp
// L2251
void HearingAid::Initialize(HearingAidCallbacks* callbacks, Closure initCb) {
  if (instance) {
    log::error("Already initialized!");
    return;
  }
  // 创建 HearingAidImpl 单例（类似 12.1 的 LeAudioClient::Initialize 模式）
  instance = new HearingAidImpl(callbacks, initCb);
}
```

HearingAid::Initialize 的模式与 LeAudioClient::Initialize（见 12.1）完全一致：
全局单例 + 静态工厂方法 + RAII 管理。
这是 AOSP BTA 层的惯用模式：每个 Profile Native 模块只有一个全局实例，
HearingAidService.java 通过 JNI 调用此处完成 ASHA 模块初始化。
