# 物料包目录（_物料包/）

> 本目录存放 **v2 工程化约束层**中每一节的「物料包 YAML」。
>
> 物料包是 v2 章节生成的**唯一可信信息源**：所有 `file:line` 引用、函数名、代码片段、Mermaid 模板编号、术语约束、FAQ 建议都集中在此处一次性核验，中等模型只能引用而不能改写。
>
> 物料包错则整章全错 —— 因此物料包必须由强模型（Claude Opus / 人工）一次性制作，并通过 `scripts/verify_materials.py` 自检。

**命名规则**：
- 章目录：`<两位章号>_<章标题>/`，与 `doc/学习资料_v2/` 下一级目录一致
- 物料包文件：`<节编号>_<节标题>.yaml`，节编号用点分（如 `13.2`），标题去除空格
- 一节一文件，禁止合并

## 2. 物料包 YAML Schema

完整 schema 见 `doc/v2_物料包示例.md` 和 `doc/v2_编写规范.md §3`。这里给出**字段清单 + 必填/可选标注**：

| 顶层字段 | 必填 | 说明 |
|---------|-----|------|
| `meta` | ✅ | 元数据（section_id / title / priority / last_verified 等） |
| `allowed_refs` | ✅ | 白名单：本节允许引用的 file:line 集合 |
| `code_snippets` | 推荐 | 预喂代码片段（带 source/code/annotation） |
| `flags` | 推荐 | 涉及的 aconfig flag 清单 |
| `terms` | ✅ | 术语白/黑名单（含 canonical/forbidden） |
| `mermaid_templates` | ✅ | 推荐使用的 Mermaid 模板编号（必须在 `doc/v2_Mermaid模板库.md` 中） |
| `section_outline` | ✅ | 十二段填空提示（每段的 min_words / must_contain / must_link 等） |
| `known_pitfalls` | 推荐 | 已知陷阱（注入 HTML 注释让中等模型规避） |
| `cross_links` | 可选 | 建议交叉链接 |

## 3. 制作物料包的工作流（强模型一次性）

```
┌─────────────────────────────────────────────────────────┐
│  STEP 1：拉清单（10 分钟）                                │
│   - 确认 section_id / title                               │
│   - 列出本节所有要讲的主要文件（typically 3-8 个）        │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  STEP 2：实查 file:line（20-40 分钟）                     │
│   - 对每个目标函数 Grep + Read 精确行号                   │
│   - 写入 allowed_refs[*].lines                            │
│   - 顺手截取 2-3 段关键代码到 code_snippets               │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  STEP 3：填 outline / terms / templates（20 分钟）        │
│   - 每段 outline 必须含 min_words 和 must_contain         │
│   - 术语从 doc/术语表.md 抽取本节相关条目                  │
│   - Mermaid 模板从 doc/v2_Mermaid模板库.md 选择 2-3 个    │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  STEP 4：补 known_pitfalls / cross_links（10 分钟）       │
│   - 反例库（doc/v2_反例库.md）筛已知坑点                  │
│   - 关联章节列入 cross_links                              │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  STEP 5：自检（1 分钟）                                   │
│   python scripts/verify_materials.py <yaml>               │
│   必须 PASS 才能交给中等模型                              │
└─────────────────────────────────────────────────────────┘
```

**预算**：单个物料包约 1-1.5 小时（强模型）。

## 4. 中等模型的使用工作流

中等模型**禁止**修改本目录任何文件，只能：

```
1. 读取物料包：例如 doc/学习资料_v2/_物料包/13_安全与加密/13.2_SMP详解.yaml
2. 生成脚手架：
     python scripts/scaffold_section.py <物料包.yaml>
3. 在脚手架的「<!-- ↑ 在此段下方填写中文内容 -->」位置填中文
4. 自检：
     python scripts/verify_section.py <章节.md> --materials <物料包.yaml>
5. 失败则重新填充（≤ 3 轮），仍失败移交人工
```

详见 `doc/v2_编写规范.md §1` 五步工作流。

## 6. 物料包变更管理

| 场景 | 处理方式 |
|-----|---------|
| AOSP 版本升级（如 android-16.0.0_r5 → r6） | 整批重跑 `verify_materials.py`，行号失效的物料包重新对位 |
| 节标题/编号微调 | 物料包文件改名 + 修改 `meta.section_id` + 联动 `doc/开发计划.md` |
| 新增反例库条目 | 在所有相关物料包 `known_pitfalls` 中追加 |
| Mermaid 模板库新增编号 | 旧物料包无需改；新物料包可使用 |

## 8. FAQ

**Q1：为什么要单独建一个物料包目录，不直接放到章节 md 里？**

A：物料包是「输入约束」，章节 md 是「输出产物」。分离的好处：
- 输入可以由强模型/人工严格审核，输出可以由弱模型批量生成；
- 物料包变更（如行号更新）不污染章节内容历史；
- 自检脚本可以单独验证物料包，提前拦截错误。

**Q2：物料包能不能复用？比如 13.2 和 13.3 共用一些 file:line？**

A：可以，但**禁止跨节直接 include**。同样的 file:line 在两个物料包的 `allowed_refs` 里**重复写**，反而能让每节自包含。

**Q3：物料包写完后还能改吗？**

A：可以，但任何修改都要重跑 `verify_materials.py` + 重新 `scaffold_section.py` 生成脚手架（旧脚手架可能与新物料包不一致）。

**Q4：中等模型能不能直接写物料包？**

A：**不行**。物料包是地基，地基错则整楼塌。物料包目前**只能由 Claude Opus（强模型）或人工**制作。后续若中等模型能力跃迁验证可信，再开放权限。
