## 2. 当前重点

首版已完成，后续如继续扩展，优先处理：

- 基于真实设备日志补案例库。
- 使用 `问题排查记录模板.md` 将真实问题按统一结构归档。
- 源码更新后按 `源码行号校准清单.md` 重新校准关键入口行号。
- 新增案例时优先写入 `97-真实案例库.md`，再回填到具体章节。
- 若拿到完整车机工程，补 Settings、system_server 和厂商互联协议边界。
- 对关键源码行号做二次校准。
- 根据团队反馈补充练习答案或排查模板。
- 按新计划优先生成 `11-蓝牙Framework架构地图.md`，然后依次完成 BLE Scan、BLE Connect、Pairing、GATT Client 定向代码阅读报告。

## 3. 风险与约束

- 当前仓库未必包含 Settings App 和 system_server 中完整 BluetoothManagerService 源码，相关章节只能讲 API 边界与调用入口。
- 手机互联方案多为厂商/认证实现，当前仓库只能给出 Android 蓝牙侧可能参与的协议和代码观察点。
- Android 16 代码体量较大，后续章节需要持续补充真实函数调用链，避免一次性过度展开。
