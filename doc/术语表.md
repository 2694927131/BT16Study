# 蓝牙术语表（v2 全量）

> **本术语表是 v2 章节生成的强制约束**：所有 v2 章节中出现的术语**必须**使用本表的「规范译名」，**禁止**使用「禁用别名」。
>
> 自检脚本 `scripts/verify_section.py` 会检查违规用词。
>
> **维护原则**：
> 1. SIG 在 BLE 5.3 后强制使用的术语（如 Central/Peripheral 替代 Master/Slave）一律强制
> 2. 高频缩写（HCI / L2CAP / GATT 等）保留英文原文，**首字母必须大写**
> 3. 协议帧字段名（如 `Pairing Request`、`Connection Complete Event`）保留英文，用反引号包裹
> 4. AOSP 源码中的函数名/类名保留英文原文，用反引号包裹
>
> 最后更新：2026-05-25
> 对齐基线：Bluetooth Core Spec v5.4 + BLE 6.0 + AOSP android-16.0.0_r5

---

## 使用约定

每条术语包含：
- **规范译名**：v2 中必须使用的中文 / 英文形式
- **英文**：英文原文（如有）
- **缩写**：缩写（如有）
- **定义**：一句话定义
- **禁用别名**：禁止使用的其它写法
- **出处**：Spec 章节号 / AOSP 路径 / 相关 v2 章节锚点

## A. 总览与架构

### A.1 Bluetooth Classic（BR/EDR）
- **英文**：Bluetooth Classic / Bluetooth BR/EDR
- **缩写**：BR/EDR（Basic Rate / Enhanced Data Rate）
- **定义**：传统蓝牙，承载 A2DP / HFP / HID / OPP / PBAP / MAP 等 Profile，最大速率 3 Mbps
- **禁用别名**：经典蓝牙（中文场景可用，但 AOSP 文档统一 "Bluetooth Classic"）、传统蓝牙
- **出处**：Core Spec Vol 2

### A.2 Bluetooth Low Energy
- **英文**：Bluetooth Low Energy
- **缩写**：BLE / LE
- **定义**：低功耗蓝牙，承载 GATT / Mesh / LE Audio / Channel Sounding 等，最大数据速率 2 Mbps（PHY 2M）
- **禁用别名**：低能耗蓝牙、低功耗蓝牙（中文段落首次出现可加括号注释）
- **出处**：Core Spec Vol 6

### A.3 Host（蓝牙主机）
- **英文**：Host
- **定义**：蓝牙协议栈的软件部分，运行在 Application Processor（AP/CPU）上，包含 L2CAP/SMP/ATT/GATT/Profile 等
- **禁用别名**：主机栈、主控软件
- **出处**：Core Spec Vol 3

### A.4 Controller（蓝牙控制器）
- **英文**：Controller
- **定义**：蓝牙协议栈的硬件 + 固件部分，运行在蓝牙芯片上，包含 Baseband / Link Manager / Link Layer / Radio
- **禁用别名**：控制器（中文 OK，但首次出现需配英文）、芯片端
- **出处**：Core Spec Vol 2 / Vol 6

### A.5 HCI（Host Controller Interface）
- **英文**：Host Controller Interface
- **缩写**：HCI
- **定义**：Host 与 Controller 之间的命令/事件/数据接口，UART/USB/SDIO 物理承载
- **禁用别名**：主控接口
- **出处**：Core Spec Vol 4

### A.6 Adapter（蓝牙适配器）
- **英文**：Adapter
- **定义**：Android Framework 层蓝牙总控对象（BluetoothAdapter），管理开关/扫描/可发现/已绑定设备
- **禁用别名**：蓝牙总管、适配器实例
- **出处**：`framework/java/android/bluetooth/BluetoothAdapter.java`

### A.7 Profile（蓝牙应用协议族）
- **英文**：Profile
- **定义**：基于 L2CAP/RFCOMM/GATT 的应用层协议族，如 A2DP / HFP / HID / GATT
- **禁用别名**：协议、协议簇
- **出处**：各 Profile Spec

### C.2 Peripheral
- **英文**：Peripheral
- **定义**：BLE 连接接受方，等同于 Classic 中的 Slave
- **禁用别名**：⚠️ **`Slave`、`从设备`、`从端`、`外设`、`从`** —— BLE 5.3+ 强制使用 Peripheral

### C.3 Advertiser / Scanner / Initiator / Observer

### C.4 Public Address

### C.6 RPA（Resolvable Private Address）
- **英文**：Resolvable Private Address
- **缩写**：RPA
- **定义**：可解析私有地址，由 IRK 周期性生成，用于 LE Privacy
- **禁用别名**：可解析私有地址（首次必须配英文）

### C.7 Identity Address

- **定义**：设备的真实身份地址（Public 或 Static Random），仅在配对时交换

### C.8 BD_ADDR

## E. GATT / ATT

### E.1 ATT（Attribute Protocol）
- **英文**：Attribute Protocol
- **缩写**：ATT
- **定义**：BLE 属性协议，定义客户端/服务端读写属性的方法
- **禁用别名**：属性协议（首次必须配英文）
- **出处**：Core Spec Vol 3 Part F

### E.2 GATT（Generic Attribute Profile）
- **英文**：Generic Attribute Profile
- **缩写**：GATT
- **定义**：通用属性 Profile，在 ATT 之上组织 Service / Characteristic / Descriptor
- **禁用别名**：通用属性 Profile（首次必须配英文）
- **出处**：Core Spec Vol 3 Part G

### E.3 Service / Characteristic / Descriptor
- **英文**：Service / Characteristic / Descriptor
- **定义**：
  - Service：服务，含若干 Characteristic
  - Characteristic：特征，含值 + 属性 + 若干 Descriptor
  - Descriptor：描述符，提供 Characteristic 的元数据
- **禁用别名**：⚠️ **服务/特征值/特征/属性/描述** 这种混乱译法
- **首次出现规则**：中文译名可用「服务 / 特征 / 描述符」，但代码引用必须英文

### E.4 Notify / Indicate
- **英文**：Notification / Indication
- **定义**：
  - Notify（通知）：服务端主动发送，无确认
  - Indicate（指示）：服务端主动发送，需客户端确认
- **禁用别名**：⚠️ **推送/回执、通知/指示** —— 必须用 Notify/Indicate 原文 + 中文括注
- **出处**：Core Spec Vol 3 Part F §3.4.7

### E.5 CCC（Client Characteristic Configuration）
- **英文**：Client Characteristic Configuration
- **缩写**：CCC / CCCD
- **定义**：客户端特征配置描述符，UUID = 0x2902，用于启用 Notify/Indicate
- **禁用别名**：客户端配置（首次必须配英文）
- **出处**：Core Spec Vol 3 Part G §3.3.3.3

### E.6 UUID（Universally Unique Identifier）
- **英文**：Universally Unique Identifier
- **缩写**：UUID
- **定义**：128-bit / 32-bit / 16-bit 标识符，标识 Service / Characteristic / Descriptor
- **基础 UUID**：`0000xxxx-0000-1000-8000-00805F9B34FB`
- **禁用别名**：通用唯一标识（罕用）

### E.7 MTU（GATT 上下文）
- **英文**：ATT_MTU
- **定义**：ATT 层协商的最大传输单元，默认 23，可协商至 247（LE）/ 517（EATT）
- **禁用别名**：见 D.4

### I.3 Unicast / Broadcast
- **英文**：Unicast / Broadcast

  - Broadcast：广播，1-to-many 单向音频流（用 BIS）
- **禁用别名**：单播/广播（中文 OK，但需配英文）

### I.4 Auracast
- **英文**：Auracast™

### I.5 CSIP / VCP / MCP / TBS
- **英文**：保留英文 + 缩写
- **定义**：

  - MCP：Media Control Profile，媒体控制

### I.6 TMAP / HAP / GMAP
- **英文**：保留英文 + 缩写
- **定义**：
  - TMAP：Telephony and Media Audio Profile，电话与媒体上层 Profile
  - HAP：Hearing Access Profile，助听器接入
  - GMAP：Gaming Audio Profile，游戏音频
- **禁用别名**：无

### I.7 ASHA
- **英文**：Audio Streaming for Hearing Aids
- **缩写**：ASHA
- **定义**：Google 助听器音频流协议（早于 LE Audio HAP）

### I.8 BAP（Basic Audio Profile）

- **路径**：`system/bta/`
- **禁用别名**：蓝牙适配（首次必须配英文）

### N.3 Stack
- **英文**：Stack
- **定义**：AOSP 蓝牙核心协议栈（L2CAP / GATT / SMP / SDP / RFCOMM 等）

### N.4 GD（Gabeldorsche）
- **英文**：Gabeldorsche
- **缩写**：GD
- **定义**：AOSP 新一代模块化蓝牙栈，与旧 Stack 并存（shim 层桥接）
- **路径**：`system/gd/`
- **禁用别名**：无

### N.5 Profile Service
- **英文**：Profile Service
- **定义**：Android Profile 的系统服务，继承 `ProfileService`
- **路径**：`android/app/src/com/android/bluetooth/<profile>/`
- **禁用别名**：Profile 服务（中文 OK）

### N.6 aconfig flag
- **英文**：aconfig flag
- **定义**：Android Mainline 的特性开关，编译时 + 运行时双重控制
- **路径**：`flags/*.aconfig`

### N.7 Mainline / APEX
- **英文**：Mainline / APEX
- **定义**：
  - Mainline：可独立升级的模块化系统组件
  - APEX：Android Pony EXpress，Mainline 的容器格式
- **路径**：蓝牙 APEX = `com.android.btservices`
- **禁用别名**：主线（错译，禁用）

### N.8 ActiveDevice
- **英文**：Active Device
- **定义**：当前路由音频/通话的设备（多设备共存时）
- **代码**：`ActiveDeviceManager` in `android/app/src/com/android/bluetooth/btservice/`
- **禁用别名**：活动设备（中文 OK）
