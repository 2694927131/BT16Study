## 1. 目标与边界

### 1.1 总目标
生成一套面向**车载 Android 开发工程师**的源码学习资料，让一个具备「会 Android 应用开发、C++ 仅入门、蓝牙协议零基础」起点的读者，能在跟随本资料学习后，**独立完成 Android 蓝牙 Framework 与 Native 协议栈的阅读、修改、调试与车载场景定制**。

### 1.2 读者画像（必须始终对齐）
- 会写 Java/Kotlin 业务代码，熟悉 Activity/Service/Binder/Handler。
- 看得懂 C++ 语法基础（类、引用、指针），但**不熟悉**智能指针、模板、Lambda、状态机、RAII。
- 没读过过 Bluetooth 协议规范，不了解 HCI/L2CAP/SDP/GATT 这些术语的物理含义。
- 工作场景为车载 IVI（信息娱乐）：A2DP 蓝牙音乐、HFP 蓝牙电话、BLE 钥匙/胎压/OBD 等 AIoT 外设、手机互联（HiCar/CarLink/CarPlay）相关蓝牙辅助链路。

### 1.3 事实纪律（最重要）
本资料以**当前仓库源码为唯一事实基础**。文档中涉及类名、函数名、路径、调用链时：
- **必须**优先引用真实源码，并使用 `file_path:line_number` 形式给出可点击定位。
- 无法在当前仓库确认的外部组件（如 Settings App、`system_server` 中的 `BluetoothManagerService` 完整实现、厂商车机互联具体实现、HAL Vendor 实现等）**必须明确标注**为 "外部依赖 / 推断场景 / AOSP 框架其他仓库"，并尽量给出 AOSP 官方路径以供读者旁站查阅，**不得伪造源码路径或行号**。
- 当源码与协议规范不一致时，以源码为准并在注释中标注差异。

## 2. 源码范围

当前仓库是 Android Bluetooth 模块源码（packages/modules/Bluetooth 的本地切片），核心目录如下（已在本仓库验证存在）：

| 目录 | 角色 | 主要语言 |
|------|------|----------|
| `framework/java/android/bluetooth` | 公开/系统蓝牙 API（`BluetoothAdapter`、`BluetoothDevice`、`BluetoothProfile` 等） | Java |
| `android/app/src/com/android/bluetooth` | 蓝牙 App 与各 Profile Service（`AdapterService`、`A2dpService`、`HeadsetClientService`、`GattService` 等） | Java/Kotlin |
| `android/app/jni` | Java/Kotlin 到 Native 栈的 JNI 桥接 | C++ |
| `service/src` | 系统服务相关 Kotlin 代码（`BluetoothManagerService` 现代实现） | Kotlin |
| `system/btif` | BTIF 适配层，承接 JNI 调用并下发到 BTA/Stack | C++ |
| `system/bta` | Profile 与设备管理的中间层状态机 | C++ |
| `system/stack` | Classic/BLE 协议栈核心（HCI、L2CAP、SDP、RFCOMM、GATT、A2DP、AVRC、SMP 等） | C++ |
| `system/gd` | "Gabeldorsche" 模块化蓝牙栈实现（HAL、HCI、metrics、storage、L2CAP 新栈） | C++/Rust |
| `system/main` | 启动入口与 shim 层（`bte_main`、`shim`） | C++ |
| `system/hci` | HCI 命令/事件下层调度 | C++ |
| `system/audio_hal_interface` | 与 Audio HAL 的对接（A2DP/HFP Offload 路径） | C++ |
| `flags` / `sysprop` | aconfig flag 与系统属性定义 | flags/sysprop |

## 4. 内容质量要求

### 4.1 章节统一模板
每个主题章节必须按下列结构组织（顺序不可调整）：
1. **学习目标**：读完后能解决什么问题（务必可验证）。
2. **前置知识**：需要先读哪些前置章节，需要什么基础（Binder/JNI/Handler/C++ 锁等）。
3. **场景故事**：用车载场景说明这个模块的价值（具体到 IVI 上的现象）。
4. **分层调用链**：从 API 到 Service / JNI / BTIF / BTA / Stack（缺哪层补哪层）。
5. **源码导读**：真实路径 + 类 + 方法 + 建议阅读顺序，所有路径形如 `system/stack/btm/btm_sec.cc:1234`。
6. **简化代码片段**：截取关键逻辑，保留行号，附通俗注释；超过 60 行的片段必须省略并标注省略原因。
7. **流程图/时序图**：Mermaid 源码（Markdown 直接渲染优先）。
8. **调试方法**：日志 tag、adb 命令、dumpsys 节点、btsnoop 观察点。
9. **常见问题（FAQ）**：本节最容易踩的坑，每条带"原因 + 验证 + 修复方向"。

### 4.2 C++/Java 双语对照（重点）
凡是 C++ 讲解涉及以下概念，**必须**给出 Java/Kotlin 类比示例：
- 智能指针（`std::shared_ptr` / `std::unique_ptr`）↔ Java 强引用、`AutoCloseable`。
- RAII / 析构 ↔ `try-with-resources` / `finally`。
- Lambda + `std::function` ↔ Java Lambda + `Runnable`/`Consumer`。
- `std::mutex` / `std::lock_guard` ↔ `synchronized` / `ReentrantLock`。
- 模板（template）↔ Java 泛型（同异点必须说明）。
- 状态机（如 BTA SM、BondStateMachine）↔ Android 框架的 `StateMachine`。

### 4.3 车载视角
所有 Profile 章节必须包含至少一节"在车机上会怎么用 / 出问题时表现是什么 / 厂商常做哪些定制"。

### 4.4 学习坡度
- 每章开头给一句"如果你只看一段，看这段"的速通摘要。
- 复杂术语第一次出现必须用一句白话解释。
- 章末给"上路任务"：1-2 个可在源码里实际完成的小练习（例如：找出某 log tag，定位某次回调路径）。

## 5. 车载重点场景（必须覆盖）

- **基础蓝牙**：开关、扫描、配对、连接、取消配对、设备列表持久化。
- **蓝牙音乐**：A2DP Source/Sink、AVRCP Target/Controller、绝对音量、卡顿/无声定位。
- **蓝牙电话**：HFP AG/Client、SCO 音频建立/释放、通话状态同步、车机麦克风和扬声器通路。
- **系统设置**：Settings 到 `BluetoothAdapter` / `BluetoothDevice` API 的交互，权限与 AppOps、隐私权限演进。
- **手机互联**：配对触发、RFCOMM/L2CAP/BLE/GATT 可能的辅助角色、认证辅助链路。
- **AIoT 外设**：BLE 扫描、GATT 连接、服务发现、Characteristic 读写、Notify/Indicate、OTA 思路。
- **多点连接 / 双手机**：车载典型的两台手机同时连接（A2DP/HFP）场景与受限点。

## 6. 验收标准

### 6.1 内容验收
1. 文档中的源码路径和函数名**可在当前仓库 grep 检索到**（外部依赖除外，且已明确标注）。
2. 每个主要章节至少 **1 条完整调用链** 和 **1 张 Mermaid 图**。
3. 每个 Profile 专题至少包含 **Java Service、JNI、Native 入口三层映射**。
4. C++ 讲解必须绑定真实蓝牙源码例子，避免孤立语法课。
5. C++ 讲解凡有 Java 类比的，**必须**给出 Java 类似语法使用对比。
6. 每章末尾必须有可执行的"上路任务"。

### 6.2 过程验收
1. `doc/开发跟踪记录.md` 能清楚显示当前完成度、未完成章节、风险与下一步。
2. **每完成一个完整章节（一级章节，如 03、04、05…）必须 `git commit` 一次**，提交信息形如 `docs(学习资料): 完成第 04 章 JNI 桥接机制`。
3. 章节内部小节可以边写边落盘，**不必每节单独提交**；待整章所有小节完成再统一一次提交。
4. 提交前必须更新 `开发跟踪记录.md` 反映该章所有小节状态。
5. Claude 自动执行 `git commit`，不需询问用户。

### 6.3 长期可维护性
1. 仓库根 `CLAUDE.md` 必须包含：项目背景、目录约定、工作流约定（含每节提交规则）、术语表入口、待办指引。
2. 所有路径使用仓库相对路径，不写绝对 Windows 路径。
